**What shipped.** `account_authority.media_mode_previews text[]` (migration
`drizzle/0083_media_mode_previews.sql`) holds a per-account grant.
`browsableMediaModeTargets` is now the single answer to which Media Modes a viewer may
browse: enabled targets plus that account's previews. The grant rides the existing
`select` in `readAccountAccess` that every authenticated bearer request already pays for,
so there is no extra round trip; the mobile API wrapper exposes it as
`ctx.browsableTargets` and the Media Mode Scope gate reads that instead of the launch
constant. `/v1/users/me` reports and accepts the viewer's own answer. The web gate is
deliberately untouched — this is app-first per the spec. Plus the `CONTEXT.md` glossary
entry for Media Mode Preview and `docs/media-mode-previews.md`.

**Key decisions.**
- The grant is read on the authority row rather than a join table: the read path that
  needs it already selects that row, so a column costs nothing per request.
- The two Subdomain Target maps were pinned as exact inverses in a test (review fix), so a
  future mode added to one map cannot silently fall out of the other.
- No rebase before the queue. main was 6 behind / 7 ahead, `mergeable` MERGEABLE, and
  Mergify builds base+PR itself; a rebase would have re-run CI for nothing.
