## The ticket itself

The chain tested `p.includes("he")` first, and `"she/her"` and `"they/them"`
both contain `"he"`. Word-boundary matches replace it. `/\bhe\b/` cannot match
inside `"she"` or `"they"` — the `"he"` is preceded by a word character in both
— so the chain's order stops mattering for correctness, which is the point:
ordering `they`/`she` before `he` would also work and would break the next time
someone reordered it.

**The ticket asked whether any other path had the same substring test. One did**,
and the standards review is what found it: `scripts/import-letterboxd.ts`,
which `package.json` exposes as `import:letterboxd`. My own `grep` had truncated
it away. Both call sites now share `pronounsFromLetterboxdProfile` in
`src/lib/letterboxd-import.ts` — the pure parsing module both already import. It
stays free of the Drizzle schema, so the `watchxd_pronouns` union is written out
literally; that is a real trade-off and it is stated in the PR body.

Files: `src/lib/letterboxd-import.ts`, `src/lib/letterboxd-import.test.ts`,
`src/server/imports/letterboxd.ts`, `src/server/imports/letterboxd.test.ts`,
`scripts/import-letterboxd.ts`.

No glossary term was settled — `CONTEXT.md` carries no pronoun or Letterboxd
concept, and this ticket did not earn one. `CONTEXT.md` untouched.
