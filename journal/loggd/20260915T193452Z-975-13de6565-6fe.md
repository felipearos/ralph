## What shipped

- **`src/lib/api-utils.ts`:**
  - `withAuth` takes a new third argument, `options: ThrottleAuditOption = {}`.
  - `withOptionalAuth`'s existing options gained `auditThrottle?: AuthAbuseFlow`.
  - When `auditThrottle` is set and the limiter refuses, `runMiddleware` calls `auditAuthThrottled({ flow, source: "application", retryAfter })` once, before the 429.
  - The option is opt-in, so read and mutation routes stay silent.
- **Routes:** `/api/v1/auth/forgot-password` passes `recovery_email` and `/api/v1/auth/password-screen` passes `sign_in`. Each matches its cookie twin.
- **`docs/security/auth-abuse-controls.md` (Monitoring) now states three things:**
  - v1 routes audit through the wrapper.
  - v1 sign-up and resend-confirmation don't use the wrapper. They already audit inside `account-creation.ts`, so nothing is emitted twice.
  - The two password-screen routes throttle different callers. The wrapper rate-limits a tokenless caller by IP before its 401. The cookie route refuses that caller before its limiter runs. So counts for one storm won't match.
- **Tests:**
  - `api-utils.test.ts` has 5 cases.
  - Each route test asserts the audit on a 429 and no audit on a 200.
  - I mutation-checked removing the audit call and removing each opt-in.

## For the next iteration

- **Pre-PR hook trap:** it runs before the Bash command. If one call chains `git commit … && touch marker && gh pr create`, the hook sees the old HEAD and denies the whole command, so the commit never happens. Commit, record the marker and push in one call, then run `gh pr create` in a separate call.
- **Wait loops:** Bash tool calls cap at 600 s. A wait loop whose deadline is near 600 s gets moved to the background. Keep each wait's deadline around 480–540 s and chain several calls.
