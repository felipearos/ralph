## What shipped

Mobile only. A book List on the List screen now draws the Share action a show
List already has, and hands the share sheet the List's name on one line and
`loggd://list/<id>` (or `loggd-dev://`) on the next, built with the #3081
builder `appShareMessage`. It passes only `message`, names no web host, and
takes the id from the read (`meta.id`), not the route param. Show, movie,
season and episode Lists are untouched. `CONTEXT.md` gains **App Link**.

Files: `mobile/app/list/[id]/index.tsx`,
`mobile/__tests__/list-detail-books.test.tsx`,
`mobile/lib/__tests__/app-share-link.test.ts`,
`mobile/__tests__/press-in-route-conformance.test.ts`, `CONTEXT.md`.

## Key decisions

- A failed share sheet still shows the List screen's existing "Couldn't open
  sharing" toast, rather than copying the Book screen's silent swallow. It
  changes no navigation and no state — a deliberate difference from #3081.
- `accessibilityLabel` stays `"Share list"` for both kinds.
- The book branch needs no owner username; the show branch keeps its guard.
- The link selects no Media Mode — choosing Books from a List link is #3157.
- Rejected: `encodeURIComponent(listId)` on the route param, replaced by
  `meta.id` after the correctness review.
- `CONTEXT.md`'s **App Link** `_Avoid_` deliberately does NOT list "Share
  Link": the share-link setting a List owner may turn on (#536, #3153) is a
  real separate concept.
