## The decision worth arguing with: I added a server field for a client filter

The ticket wanted a "Logged" Show/Hide control. `ViewerMediaStateEntry` had `rating` and `hasReview` and no way to answer it. The tempting move is `rating != null || hasReview` in the client.

That is wrong, and the case that proves it is in the glossary already: the Import Merge writes a log carrying "a watched date and nothing else". A row with no score and no words **is** a log, and the derivation calls it not-logged. The web has answered this server-side all along (`watchStatus.ts`: `logged: reviewData !== undefined`).

So `logged` went on the read. It cost no query — the review scan already selects the row, so it is one field folded out of something already found. **Generalisable: before deriving a domain concept from two adjacent fields, go and look at whether the other surface already names it. If it does, the derivation is a second definition of a term that already has one.**

The spec axis then caught that my `logged` and the web's are still not the same: mine applies `publishedReviewPredicate`, the web's does not, so a draft-only log reads Logged on web and Not logged on mobile. I did **not** fix that — relaxing the predicate for one field needs a second scan or a split fold plus a rule for which row wins, which is a decision about what a log is. Documented at the query, filed as **#1157**. Same shape as #1079's #1150.

## Absent is not false, again — and this time it was three bugs, not one

#1079's journal says: "when two surfaces compute the same field from different evidence, the one that cannot compute it must be able to say so in the type." This iteration is the same lesson one level up, and I shipped the bug it warns about straight past my own brief.

The lookup spells "the member has not watched this" and "the read has not answered yet" identically, as a missing key. A surface that *draws* that is fine — no indicator. A surface that **filters** on it is not. All three defects the spec review found were that one fault:

- **Filtering an unanswered read.** In flight, after an error, or signed out, every reference looks unwatched — so "Show watched" emptied the grid, and the empty state I had just added announced a match failure that never happened, then items popped in. Also across chunks: `combine` returns a populated map as soon as *any* chunk resolves.
- **Signed out kept applying.** The controls hid, the filters did not, so a stale `watched: "show"` emptied the grid with no visible control to undo it, and the badge counted a filter nothing on screen explained.
- **Fade dimmed the indicators.** The dim sat on the poster frame, which contains the `ViewerMediaStateIndicators` cluster — so fading a watched poster faded the very mark that says it is watched. #1076's work undone exactly where it mattered.

The fix is one concept: the provider now hands down `answered` (`!isLoading && states.size > 0`), and the grid filters only then. That third term is exact because the read returns one entry per reference for a signed-in member, so an empty lookup always means unanswered.

**Next iteration: any surface that FILTERS on viewer media state needs `useViewerMediaStateAnswer`, not the bare lookup.** Drawing can tolerate an absent entry; filtering cannot. #1064 has more filtering surfaces coming.
