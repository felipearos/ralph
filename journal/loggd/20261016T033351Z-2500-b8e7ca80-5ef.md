## The real find: the seventh criterion could not be satisfied

It demanded the landing be "asserted on the host and path explicitly". **Host and path cannot tell
the modes apart in the environment this spec runs in.** `onboardingDestination` returns `movies`
for the "walks all three steps" test (`src/lib/onboarding.ts:184-191`), `exitOnboarding` goes to
`getSubdomainHomeUrl("movies")` (`src/lib/media-subdomain.ts:162-164`), and
`BROWSE_NAV.movie.homeHref` is `"/"` — identical to `tv`'s (`src/lib/media-types.ts:61-62`).
Against the spec's `http://localhost:3000` base URL (`e2e/target.ts:56,108` →
`playwright.config.ts:42-43,490`) `getSubdomainUrl` takes its **localhost branch** and carries the
mode as `?mode=movie` on an unchanged host instead of as a subdomain (`:128-145`); the `shows`
destination deletes that parameter (`:142-143`) and lands on the same host and path. The describe
is skipped without a local database (`e2e/onboarding.spec.ts:116`), so it never meets a real
subdomain host. A literal exact-string `toHaveURL` of host+path therefore both fails (the query is
there) and proves nothing (shows passes it).

Appended an eighth criterion: assert the whole URL with its query, keep the 20s timeout the `:236`
check was also serving as the cross-document navigation wait, and mutation-check **on the product**
— make `onboardingDestination` return `ENABLED_SUBDOMAIN_TARGETS[0]` (`"shows"`,
`media-types.ts:218`) and confirm failure. The old `not.toHaveURL(/\/onboarding/)` survives that
mutation; the new assertion does not.

Appended, not replaced: #2500 is `ready-for-agent` and the human-edits rule bars replacing an
existing `Acceptance criteria` there. Same call as #2499 two iterations ago. The append's first
line neutralises the seventh's wording explicitly, which the reviewer required.

so any claim about an installed library's behaviour has to be checked at `/home/faros/loggd`.
