## What I decided

**Not a split.** The oversize bucket fired lexically: `isOversize`
(`frontier/next-tasks.ts:1188`) flags a body matching three of its four surface
regexes, and #2672's prose says `web`, `mobile` and `server`. Only 5 acceptance
checkboxes, well under the 8 threshold. Four reasons it stays whole:

1. **The deliverable is atomic.** Its criterion 1 is "the *only* definition" and
   criterion 2 is "`rg` finds no local copy". Both are false in every
   intermediate state, so a per-surface child would add a sixth definition and
   remove none — the exact defect the ticket exists to remove.
2. **No parallelism to buy.** Consumers cannot import a module that does not
   exist; the module has no reason to exist before a consumer uses it. A split is
   a strictly serial chain.
3. **The children would not stand alone** — "migrate the web grid to the shared
   module" is unreadable without the parent naming the rules. §2's own test.
4. **It would nest a container.** A split demotes #2672 to a spec, and #2673
   declares `## Blocked by #2672`. `next-tasks.ts:381` counts a blocker while it
   is *open*, and a spec stays open until its children close — #2673 gains
   nothing and the tree gains a second container.

Mapper size: **9 files** to change or create, each a mechanical 3–10 line
replacement, plus ~7 regression tests that keep passing. One agent's work.

## What I amended, and why a comment rather than the body

#2672 is `ready-for-agent`, and the Guardrails let me replace `Acceptance
criteria` only on an untriaged or unlabelled ticket (the rescue bucket is the
other exception, and this is not it). So the amendment is prose in the triage
comment. **It widens the body**, which the comment says in so many words.

The substantive find: **criteria 1 and 2 cannot both be satisfied as written.**
Criterion 2 sweeps three sites ("the web grid, the mobile hook or the server
write" — itself ambiguous, since two of the sites are server write files), but
the mark set and candidate key have **five** definition sites. The two the body
never names:

- `src/server/queries/watchStatus-write.ts:136` — `SeenMarkState`, a fourth
  hand-written mark union (it also admits `null`)
- `src/server/queries/onboarding-candidates.ts:69` — the inline
  `` `${mediaType}:${tmdbId}` `` dedupe key

Both pulled **in** scope. Deliberately left **out**: the storage encoder
(`watchStatus-write.ts:172-173`), the decoder `seenMarkOf`
(`onboarding-candidates.ts:184-192`), `src/lib/watch-status.ts:1-7`, and the ~20
unrelated files that build the same Media Reference key — a repo-wide sweep would
have made the ticket either impossible or a different ticket.

**The trap, now written into the ticket:** the mark vocabulary and the DB enum
collide on the word `watching`. `schema.ts:754-759` is
`pgEnum("watchxd_watch_status", [...])`; the **Watching mark** is stored as
`caught_up`, while the stored status `watching` decodes to **no mark at all**
(`onboarding-candidates.ts:189-190`). A shared module that derives the mark union
from the enum silently changes which titles show a Watching chip.

## Review stages — two rounds, both acted on

`ralph-review-spec` on the amendment text (there is no diff; the brief carried
the change verbatim, as §3 requires). Round 1: three blocking findings. Round 2
on the rewrite: two more blocking. All accepted and fixed; no finding was argued
away.

- **R1-1** the `rg` check could never pass — it matched call sites, and
  "repo-wide" caught ~20 unrelated `${mediaType}:${tmdbId}` keys. → bounded to
  the five files, definition-anchored pattern, out-of-scope sites named.
- **R1-2** amendment 3 asked for a test that **already exists**
  (`onboarding-candidates.test.ts:267-283` pins both halves of the collision). →
  now "must keep passing unmodified; do not duplicate".
- **R1-3** amendment 4's "both clients" cases cannot live in
  `onboarding-equivalence.test.ts`: it compares two *server* surfaces, and root
  Vitest cannot import `mobile/hooks/useSeenStep.ts` at all. → split, one case in
  the equivalence file, the rest as `packages/**/*.test.ts` unit tests.
- **R2-A** my new pattern matched the very re-export I recommended
  (`type SeenMark\b` hits `export { …, type SeenMark }`). → anchored to
  `type SeenMark\s*=`, and the allowed `from` re-export forms spelled out.
- **R2-C** the equivalence case has no harness behind it: that file imports
  neither `markSeenTitleAction` nor the v1 seen route, and its `~/server/db` mock
  (101-123) has only `select`/`update`, so the accept half throws. → the
  amendment now names the imports to add and the mock to copy from
  (`route.test.ts:41-45`).
- **R2-D** the `SEEN_MARKS` vs `watchStatusEnum.enumValues` test would have
  dragged `~/server/db/schema` into the shared package, whose tsconfig has no
  `~/*` path and whose package.json depends only on `zod` — it would have broken
  the ticket's own "typecheck (shared)". → replaced with a literal
  `toEqual([...])` plus `not.toContain("caught_up")`.
- **R2-E** `mediaKey` reuse settled: `CsvRowMediaType` is `"tv" | "movie"`, the
  same as the seen candidate's, so the shared `candidateKey` wraps `mediaKey`.

**I mutation-tested the final `rg` guard** rather than trusting it: it returns
all 10 definitions across the five files on today's `main`, and matches none of
the six allowed forms (the two `from` re-exports, an inline type import, two call
sites, a type annotation). A guard asserted only against empty output would have
passed while meaning nothing.

No third round. R2's remaining findings were all narrow and mechanical, applied
exactly as the reviewer worded them, and the one correctness-critical item (the
pattern) was verified by execution instead.
