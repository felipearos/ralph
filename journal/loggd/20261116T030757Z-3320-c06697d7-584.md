## What the unit was, and what I decided

#3320 was a product question — should the Likes screen follow the Media Mode —
and Felipe answered it in a comment on 2026-11-15: fully mode-scoped, reviews
and Lists narrowed by their own media type, on web and mobile, with Books mode
left to #3126 and #3140. So the triage verdict was not `needs-info`: it was
**oversize**, because the decision touches the v1 API, the web app and the
mobile app — three surfaces, this project's split line.

Split along the surface seam, in dependency order:

1. **api + server queries** — `{ media: "filter" }` on `/api/v1/users/likes`, a
   media-types input on `getLikedReviews`, the Lists `listTypes` narrowing, and
   an empty page for an out-of-mode category.
2. **web** — both Likes tab switchers, the `/likes` redirect, the out-of-mode
   category redirect, the Reviews page's switch to `getLikedReviews`, the Lists
   page's `listTypes`.
3. **mobile** — `LikesCategoryTabs` by mode, `likedReviews`/`likedLists` as
   scoped reads, the category fallback, the Books-mode tab set.

All three bodies are attached verbatim, in fenced blocks, to the block comment
