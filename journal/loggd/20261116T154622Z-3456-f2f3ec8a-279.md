## Two facts from the mapper that reshaped the brief

1. **The API leg also runs under Doppler.** `:87-95` starts `next dev` through `doppler run`,
   so "start Metro without Doppler" does not by itself make the script runnable, and that
   server needs exactly the values the decision withholds. Preset mode therefore starts Metro
   only. The decision for that is cited, not invented: `docs/development-workflow.md` — "The
   client's `EXPO_PUBLIC_SUPABASE_URL` and anon key must target the authentication project
   used by its `EXPO_PUBLIC_API_URL` backend." Running the local API on the loop's own
   environment would check production tokens against the local stack, which that rule forbids.
   Same rule gives `EXPO_PUBLIC_API_URL` its default, `https://loggd.dev/api/v1` (the value
   `mobile/.env.production` already carries, which Expo does not load for a `--dev-client`
   start).
2. **`scripts/check-loop-env.ts` never reads `EXPO_PUBLIC_*`** — only `NEXT_PUBLIC_SUPABASE_URL`
   and the three database URLs (`:16-24`). The "matching exemption" Felipe asked for has
   nothing to exempt. The ticket locks that in with a test case that must start failing if
   either name is ever added, instead of editing the script. The triage comment says so
   explicitly, because it is a narrower reading of his words than he wrote.

## review.spec: three rounds, each of the first two with a real blocker

- **Round 1 (4×P2).** It rejected my judgement that `EXPO_PUBLIC_API_URL` should be a third
  *required* trigger: nothing injects it into loops, so every loop run would have been a
  "partial preset" that dies. It also caught that `doppler` lives in `/usr/bin` beside `env`
  and `curl`, so "a PATH without doppler" is not achievable by dropping PATH entries — the
  test needs a bin directory of symlinks; that no criterion checked what preset mode *keeps*
  (an implementation that deletes `:25` and dies at the next line passed my AC1); and that
  the API-URL assertion could pass on unchanged code if the preset value happened to equal
  `http://localhost:3500/api/v1`. Plus: my "harness change outside this repository" was
  wrong — `.ralph/config.json` is in the repo; the harness half is operator work.
- **Round 2 (1×P2, the good one).** `mobile/package.json:7` runs `dev:prod` under `bun run`,
  which merges `mobile/.env` into the environment, and `mobile/README.md:14-20` tells every
  developer to put those exact two variables in that file. Triggering on the values alone
  would have taken **every README-configured machine**, and `open-orca-emulator.sh:100` with
  it, off the Doppler path silently. That is where `LOGGD_MOBILE_SKIP_DOPPLER=1` came from.
- **Round 3 (1×P2).** My own fix for round 2 added a `bun --no-env-file` "belt and braces"
  clause for `dev:prod` and a criterion asserting the script never receives the file values.
  It cannot work: the outer `bun run` has already merged the file before the script starts,
  and nothing inside the script can tell an inherited file value from a real one. Dropped,
  along with the `mobile/package.json` scope entry it existed for; the criterion became an
  outcome assertion in a temporary `mobile/` tree (the reviewer also caught that a test could
  otherwise clobber a developer's real `mobile/.env`).
- **Fifth time this role has learned the same thing** (#3320, #2716, #3321, #3484): rounds 2
  and 3 pay for themselves, because round 1's fixes are themselves wrong. New this time:
  **round 3 was needed because round 2's fix was mine, not the reviewer's.** The round that
  reviews my response to a blocker is the one that caught the unimplementable clause.
