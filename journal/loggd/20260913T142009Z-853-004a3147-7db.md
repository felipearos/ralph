## What shipped

**Server: `getActivity` takes `scope?: MediaScope`, not a bare `tmdbId`.**
- **The bug.** Every branch filtered by `tmdb_id` alone. That caused three leaks, live on web too:
  - a movie and a show with the same id mixed, including on the web movie activity page
  - a movie scope returned the show's `episode_watch_status` rows
  - likes-by-user and incoming likes/comments ignored season/episode
- **The fix.**
  - `reviewScopeConditions` (media type + id + season/episode) is shared by the four review-joined branches.
  - The episode-watch branch is skipped for movies.
  - The four web activity pages pass a full scope.
- **Semantics kept on purpose.** A title scope includes its season and episode rows, and a season scope includes its episodes; web already relied on this. Siblings, other titles and the other media type never match.

**`GET /api/v1/activity`** accepts `mediaType`, `tmdbId`, `seasonNumber`, `episodeNumber`, validated by `mediaScopeSchema`.
- If any param is present, the set must parse, or the route answers 400.
- An empty numeric param is rejected (Codex P2): `Number("")` is 0, a valid season.
- The `?username=` branch also takes a scope. Blocks still apply.

**Mobile.**
- `lib/media-activity.ts`: key `["activity","scope",type,id,s|null,e|null]`, plus path, href and empty copy.
- `useMediaActivity`, and `MediaActivityScreen`, which mirrors `ActivityTabPage` rather than extracting it.
- Four routes: show/movie `(subpages)/activity.tsx`, season, and episode.
- The sheet shows "Show your activity" only with a session.
- `LogSheet` now invalidates `["activity"]`. Quick actions and `useBlockUser` already did, by prefix.
- **Codex P2:** `FullActivityCard` defaulted contentless logs and watchlist rows to `/show/{id}`, so a movie feed opened a colliding show. `ReviewActivityData` and `WatchlistActivityData` now carry `mediaType`, and `titleHref` routes by it.

## Read this before touching activity

- **Pre-existing, not fixed (possible ticket).** `getActivity` is a `"use server"` export that takes `userId` from its caller. `MediaActivityFeed` (a client component) calls it directly, so any client can ask for any user's `incoming`/`you` tab with no `blockedUserIds`. The data is mostly public, but it bypasses the viewer's blocks.
- `src/app/api/v1/media-actions/route.ts` still coerces an empty numeric param to 0. I left it alone as out of scope.
- **Glossary conflict (pre-existing).** `CONTEXT.md` defines **Media Scope** twice: under Lists as the stats TV/movie choice, and under Server Writes as a Media Reference plus season/episode. The standards reviewer read the first one and flagged this diff. This ticket uses the Server Writes meaning, as #850–#863 did. The stats term wants a rename; that is a glossary ticket, not this one.
- The mobile `ActivityCardShell` still defaults to `/show/{id}` when no href is passed. Only the episode cards rely on that now, and they are TV. A new card type must pass `titleHref`.
