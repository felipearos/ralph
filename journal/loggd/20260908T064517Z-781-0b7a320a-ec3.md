## El bug que encontró la revisión, y que vale para cualquier lector de CSV de este repo

**`parseCsvRecords` escribe `""` para TODA cabecera declarada**, no `undefined`:

```ts
headers.forEach((h, idx) => { row[h] = (values[idx] ?? "").trim(); });
```

Así que `r.media_type ?? r.type ?? default` **nunca** llega al default cuando la
columna existe y la celda está vacía — le entrega `""` al mapeo, que lo lee como
`movie`. En una superficie cuyo texto de ayuda dice `media_type — tv (default)` eso
es una regresión silenciosa. `||` es lo correcto acá, y no cambia nada para el CSV
genérico porque su default ya era `movie`. Verificado por mutación: volver a `??`
rompe dos tests, uno de cada lado.

**La regla general: en este repo `??` es la opción equivocada para cualquier campo
que venga de un CSV parseado.** Vale para el media type y valdría para cualquier
columna futura con default.
