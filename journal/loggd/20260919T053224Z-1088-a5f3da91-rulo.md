## READ THIS FIRST: `git restore` during mutation testing ate an uncommitted fix — again

Three journals in a row now carry this lesson (rafa #1072, rulo #1087, and now
this one) and I still walked into it. My mutation helper restored each mutated
file with `git restore <file>`. I ran it on a file whose **review fix was still
uncommitted**, so the restore reverted the mutation *and* the fix, and
`git diff --stat` quietly stopped listing that file. I only caught it because I
printed the diffstat after the run and noticed `movies/[id]/route.ts` had
vanished from it.

The rule that keeps being restated and keeps not being enough: **commit before
you mutate.** What is new here is the failure's *shape* — the earlier two were
caught by a failing test, mine produced a **green** run, because the mutation I
was testing and the fix I was testing lived in the same file, so reverting both
put the file back in a passing state. A green mutation run over a
silently-reverted fix is indistinguishable from success. The only tell was the
diffstat.

So: **print `git diff --stat` after any mutation loop and check the file list
is what you expect**, even when every mutation reports "killed".

Second, smaller trap in the same helper: I ran the test command with
`eval "$MT"` where `$MT` began `cd mobile && …`. That `cd` persisted into the
*next* iteration's relative-path `cp`, so every subsequent mutation failed
setup with `No such file or directory` and the first mutation was left applied.
Run the test command in a subshell — `( eval "$MT" )` — and pass absolute paths.

## The decision worth arguing with: no cross-region fallback

The web pages do `results.US ?? Object.values(results)[0]`. I made the versioned
read answer `results[region]` and nothing else, because provider licensing is
per country and showing a UK member Hulu is a false claim about what they can
stream — and web's second arm is worse still, handing out an arbitrary
first-key country.

The standards axis then turned that argument on me: **the US *default* is the
same false claim in miniature.** A UK member on a device whose locale is a bare
`en` — the common Android case — asks for US and is shown US providers. I kept
the default (an always-empty section for every region-less locale is worse) but
the honest move was to stop the comment claiming a purity the code does not
have. It now names the tension and points at `x-vercel-ip-country`. Filed as
#1164 together with the web/mobile rule split.

**Generalisable: when you write a comment arguing a rule, check the code's
default obeys it.** Mine did not, and the comment was the most confident thing
in the file.

## Both axes found the same P2 independently, again

The providers fetch had no `.catch`. `fetchTMDB` throws on any non-2xx, the
rejection escapes the extras `Promise.all`, and the wrapper 500s — so a TMDB
`/watch/providers` outage returned **no title, no seasons, no cast**, because a
six-logo strip could not load. `override` right above it has carried
`.catch(() => { extras.override = null; })` since forever.

What makes this worth recording is that it was **pre-existing route policy** —
`similar`, `recommendations`, `stats`, `score` and `bestBackdrop` are all
equally exposed — and both reviewers still called it, because *this diff made it
reachable on a path it was not on before*: the mobile detail include set now
always asks for providers, so every detail screen open pays the risk. An
unchanged policy becomes a new defect when you widen who runs through it.

## The cache bug the executor volunteered

`MediaPoster`'s poster-tap prefetch hand-rolled its own show URL under the
**same** `["show", id, include]` key the detail screen reads. Adding the region
param to the hook and not to the prefetch would have written a region-less,
provider-less answer into the cache the section renders from — the section
would have vanished on any title reached by tapping a poster, and on no other.
`showDetailQueryOptions` now owns key and path together, mirroring
`movieDetailQueryOptions`, so they cannot drift.

**A hand-rolled query that reuses another query's key is a latent version of
every future change to that query.** The fix is not to remember; it is to make
one factory the only way to build the pair.
