# 2026-11-04 — #2896 The mobile settings screen has no Adult content switch

**Outcome: merged.** PR #2902, merged through the Mergify queue at 2026-11-04T22:55:08Z as `17b2984a6`; issue #2896 closed.

**What shipped.** The Adult content switch is gone from the Expo app's Settings → Edit profile on
every platform, and the mobile client can no longer send `showAdultContent` in a `PATCH /users/me`
body. Six files, all under `mobile/`; nothing under `src/` or `packages/`, and
`ProfileParticipationWire` is deliberately unchanged. Hiding the row is not the whole fix: a
web-set preference stays stored and still gates data — that is #2894/#2895's job.

**Key decisions.**

- `ProfileParticipation` is the mobile-local *update* shape, so dropping the field from it is what
  stops the send. But `UpdatedParticipationResponse` typed the server's *reply* with the same
  interface, and `onSuccess` writes that reply into a cache whose `participation` is the wire type —
  so dropping the field from the update shape alone does not compile. Retyping the reply as
  `ProfileParticipationWire` is the fix. **Do not re-derive this.**
- The ticket names four files; there are five. `mobile/.maestro/profile-participation.yml` tapped
  the removed row, and was retargeted at the members switch.
- The review's best finding: the "never sent" rule was type-only, and TypeScript's excess-property
  check fires only on an inline literal, so a later `{ ...participation }` spread would have
  compiled and echoed a web-set `true` straight back. `mutationFn` now builds the body field by
  field (commit `52ed76f31`). Mutation-proven by the hook case only; the screen case pins the call
  shape instead, since the screen already passes a literal. Both kept, asymmetry stated in the PR.
- Two redundant `not.toHaveBeenCalledWith(expect.objectContaining(…))` assertions dropped: jest's
  plain-object `toHaveBeenCalledWith` is a recursive-equality match that already rejects an extra
  key, and `expect.anything()` is typed `any`, so each only added a fresh lint warning.
- `card-snapshot.ts`'s doc comment now names **Identity Exit** (`CONTEXT.md:208`) and says what is
  true rather than what stopped being true.
- No glossary entry: the adult gate's mobile control is not a domain concept, and `CONTEXT.md`
  already owns Card Snapshot and Identity Exit.
