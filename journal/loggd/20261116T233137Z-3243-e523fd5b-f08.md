## What landed

`GET /api/v1/users/reviews` with `media=books` **and** `sort=name` now orders a
member's Book Logs by the book's title. The SQL `name` order reads
`media_metadata.title`, which carries no book titles, so books previously sorted
last in an undefined order. The read now takes the member's matching Book Logs
newest-reviewed-first, bounded by `PROFILE_REVIEW_TITLE_SORT_MAX_ROWS` (1 000),
resolves them through the one `hydrateBookBasics` call it already made, sorts in
memory (titled A–Z lowercased in the `en` locale, untitled last, ties newest
first then by id), slices the page and hands it to `pageOf`. Shows, movies and
`media=all` are untouched.

## Key decisions

- **One `db.select()` declaration**, branching only on order/limit/offset, so
  `publishedReviewPredicate()` stays lexically inside it — the visibility
  conformance check is lexical. Both branches end in `.offset(...)` because
  `route.test.ts`'s fake db chain is not thenable.
- **The 1 000-row bound is a deliberate deviation from the issue's wording**
  ("the whole matching set … like the diary's title filters"). The book path
  sends every id to Hardcover in one `_in` query and this read's `maxOffset` is
  10 000, so literally unbounded means a ten-thousand-id GraphQL query per page.
  Followed the merged book shelf (#3204), which caps the same scan at 1 000. The
  PR body gave this its own section plus the one-line revert; no reviewer asked
  for the change.
- **`isServableBookId` now filters both hydration call sites.** One id past the
  provider's `Int` makes Hardcover refuse the whole batch; on a title-sorted read
  reusing one map across pages that would blank every row's title, cover and
  authors and change the order. A small deliberate widening beyond the ticket.

## Dead ends — skip these next time

- `getBookBrowsePage({ sort: "az", ids })`, the provider's own A–Z paging: it
  answers books not review rows, drops summaries, and cannot express two Book

- #3245's diary book filters are **not on main** (PR #3543 still open), so the
  precedent the issue names could not be imported.
