## What landed

- `GET /api/v1/users/me` reports `mediaPreference: { availableTargets,
  selectedTargets }` — the same two lists, under the same names, that the
  Onboarding Snapshot answers with, so a client reads one shape from either
  endpoint. `selectedTargets` is **unfiltered** on purpose (matching
  `snapshotFromRow`): intersecting is the client's move, and filtering server-side
  would silently forget a stored choice of a gated-off mode on the next profile write.
- `PATCH /api/v1/users/me` accepts `mediaPreference`, narrows to
  `ENABLED_SUBDOMAIN_TARGETS`, refuses an empty survivor set, and writes through
  the existing single `writeProfileSettings` call.
- Mobile: `modesForTargets`, `useMediaPreference`/`useMediaModeSync`,
  `<MediaModeSync />` mounted beside `<NotificationRouting />`, a Settings → Media
  screen, and `useMediaModeStore.reset()` in the two places `clearPendingIntent`
  already fires.

## Decisions the next mobile ticket inherits

- **`canChoose` waits for the read to settle; `modes` does not.** Offering a
  picker before the answer is in flashed a control at a single-mode account on
  every cold start. A signed-out visitor's read settles as an *error*, so they
  still get the picker — a beat late. If you gate any other affordance on the
  profile query, copy that asymmetry rather than `isLoading`.
- **Falling back to *everything* beats falling back to nothing.** An unknown or
  all-gated-off preference keeps the member's picker and current mode instead of
  stranding them, which is the same reasoning `modeForTarget` documents.

## Delegation — two timeouts, and what to do about it

`delegate.sh` was called three times. The server slice landed clean in one round.
The mobile slice **timed out at 900s twice**: round 1 got ~60% through (hooks,
store, sheet) and round 2 produced **zero edits** after 900s of exploration, even

The pattern in both timeouts is exploration, not generation — the round-2 log is
20+ `read`/`grep` calls before the first edit that never came. **A brief that
names files is not enough; the executor still re-reads the world.** If a mobile
slice touches more than ~4 files, either split it further or plan to finish it
yourself. Worth noting that a timed-out round still bills and still leaves a
half-diff you must review.
