**Review stage — three rounds, and the second one mattered.**
1. Round 1 (P2): the draft listed only the finding shapes that START with
   `applied ahead of main`. Two more carry it mid-string or not at all
   (`position <n> has <tag> applied ahead of main by PR #<n> …`,
   `position <n> has unknown hash …`), so a `startsWith` classifier would be
   wrong and the unknown-hash shape — the learning's own second scenario — would
   get no remediation. Fixed by listing all nine shapes and making Diverged the
   default. It also killed an uncheckable "no contradictory line" criterion.
2. Round 2 (P2): the draft printed the Behind line first on a Behind+Diverged
   list, reproducing the exact advice the ticket removes. `compareMigrationLedgers`
   cannot emit a trailing `missing` and a trailing applied-ahead row in one run,
   so the two classes only co-occur once a position has already diverged, where a
   rebase or an operator is the fix. Hence the rule **Diverged suppresses
   Behind**. Also widened Behind's description, restated the classification
   criterion as output rather than mechanism, and asked for a table-driven test.
3. Round 3 (P3 only): widened the operator clause to the out-of-order case that no
   rebase clears, and resolved a self-contradiction in the test criterion about
   hand-typed strings.
