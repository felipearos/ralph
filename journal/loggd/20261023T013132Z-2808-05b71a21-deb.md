## What I decided and why

The ticket's own acceptance criteria were placeholders ("specify a reproducible
verification criterion before marking this ready"), so the whole unit was: is
there a bounded change in THIS repo, and where?

There is. The mapper showed `.claude/hooks/pre-merge-green.py` is already the
enforcement point for merge discipline — it gates `gh pr merge` and a
`gh pr comment` carrying `@mergifyio queue` on CI colour (`:63`), and it
deliberately lets `@mergifyio requeue` and `@Mergifyio refresh` through
(docstring `:32`, `.ralph/prompt.md:200`). The learning's workaround ("check
status.mergify.com before requeuing; if degraded, the blocker is external") is
exactly a denial on those two commands. Nothing in the repo records the failure
mode: no tracked file mentions `status.mergify.com`, and `docs/merge-gates.md`
covers only the pre-install refresh case (`:381-386`) and the failed-batch
dequeue (`:184-191`).

Three design constraints went into `## What to build` because the hook runs on
every Bash call: fail open on any status-read failure, read only for those two
comment forms, and make the status source a **command** named by an environment
variable. The last one is forced by the test harness, not taste:
`scripts/pre-merge-green.test.ts` stubs with a fake binary on `PATH` and runs
the hook under `execFileSync` (`:99`), which blocks the Node event loop — an
in-process fake HTTP server could never answer, and a `file://` URL leaves
nothing to count.

## Spec review (one round, `ralph-review-spec`)

Six findings, all acted on, none rejected:

- the timeout must be env-overridable too, or a 5s timeout test blows vitest's
  default per-test budget;
- `runHook` must default **every** existing call to an operational fake,
  otherwise an untouched `requeue`/`refresh` test reaches the real status page;
- `LOGGD_MERGE_RED=1` had to be pinned — it now skips this gate as it skips the
  others;
- the match is spelled out as `@mergifyio\s+(requeue|refresh)\b`,
  case-insensitive, rather than "the same token forms";
- `bun run typecheck` folded into the gates criterion (the change edits TS);
- **a wrong reference of mine:** `docs/agents/codex-claude-compatibility.md:44`
  does not claim `requeue` is ungated, it merely lists what the hook gates.
  Criterion 7 now asks for an addition there, not a correction.

The reviewer also asked why `@mergifyio queue` is left out of the new gate.
Kept out on purpose — it is already gated on CI colour, and the incident's
loop-level damage was the requeue path — and that reasoning is now a sentence
in the body so the next reader does not read it as a gap.
