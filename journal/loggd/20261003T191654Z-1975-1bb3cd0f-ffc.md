# 2026-10-03 — #1975 Poster Quick Actions: start the media-actions read at press-in

**Outcome: merged.** PR #1982, squash-merged through the Mergify queue as `c1edafff0`; issue #1975 auto-closed.

**What shipped.** Two pieces, both mobile-only:

1. `MediaActionSheet` gains `watchTargetStatus?: "pending" | "unavailable"`. A disabled, muted,
   neutrally-labelled placeholder ("Watch status", `MoreHorizontal` glyph) holds the watch button's
   slot so the round-button row never changes shape mid-read. `undefined` keeps today's meaning —
   no watch button at all, which is what `MediaActionRow`'s detail sheet wants.
   `PosterMediaActionSheet` derives the value from the query's `status` **and** `fetchStatus`.
2. `mobile/hooks/usePressInActionState.ts`: a 150 ms ref-held timer started on press-in that
   prefetches `mediaActionStateQueryOptions(scope)` for the poster's full Media Scope. A tap, a
   press-out or unmount cancels it. `MediaPoster` wires it.

**Key decisions.**

- **Three-valued prop, not a boolean.** A boolean left the slot announcing `busy` for ever after a
  failed read, and again for a session that never hydrates — a disabled query is `pending` with an
  idle `fetchStatus`, which only the two-field read can tell apart from a real in-flight fetch.
- **Signed-in check via a store selector, never `getState()`.** `getState()` breaks roughly sixty
  thin-mock suites that only provide the selector form. Worth knowing before touching the auth
  store from any new hook.
- **#1955 overlap, not reverted.** `prefetchTitleSections` already fires the title-scope
  `mediaActions` prefetch on press-in, uncancellably. So AC2 ("a plain tap fires no mediaActions
  read") holds for season, episode and back-tap posters only. Out of scope here; stated plainly in
  the PR body rather than quietly widened into a revert of #1955.
- **Ruled out:** the >150 ms tap case, a redundant `cancel` in `handlePress`, a title-scope skip
  inside the hook, `Ellipsis` instead of `MoreHorizontal`.
- **Dropped a React-fiber walk** that a reviewer finding prompted. The `watchTarget == null` guard
  already means no handler there can write, so the walk was brittleness with no discriminating
  power. Don't re-add it.
- No `CONTEXT.md` entry needed: the diff stopped misusing **Quick Action** rather than coining a term.
