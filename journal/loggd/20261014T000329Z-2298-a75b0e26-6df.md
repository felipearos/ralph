## The decision that shaped the iteration

The ticket's hard acceptance criterion is a measurement, and **the loop cannot run it**:
`bun run dev:prod` → `mobile/scripts/start-prod-dev.sh` requires
`doppler run -p loggd-web -c prd`, and a plain `bun start` cannot boot because
`mobile/lib/supabase.ts` throws without `EXPO_PUBLIC_SUPABASE_*`, which a loop worktree
does not have. It is a **credentials** fence, not a host fence, so a host lease would have
been the wrong instrument and I did not request one. Published as the learning
`mobile-dev-screening-needs-doppler-prd` (project scope) — #2299–#2302 carry the identical
protocol, so it is five tickets, not one.

**I established that before building the deferral**, off the back of the select note's own
plan to probe feasibility between slices B and C. That ordering is the thing worth copying:
it cost one read of the start script, and it meant nothing was spent on a dead end while
still leaving the branch able to finish either ending.

The host itself was never the problem and is worth recording for whoever measures: `Pixel_9`
and `Pixel_9_Power` AVDs exist, `Pixel_9_Power` was already booted as `emulator-5554` with
`dev.loggd.app` installed, idle, no Metro, owned by nobody (I left it alone and started
nothing); a physical Pixel 6 (`19271FDF600BKF`) is attached over adb-tls for the release
confirmation; `adb` is at `~/Android/Sdk/platform-tools/adb`, not on PATH; and
`mobile/scripts/screen-review.ts` already force-stops, relaunches via the dev-client URL,
deep links `loggd://<route>` and reads `logcat -d -v brief ReactNativeJS:V *:S` — which is
exactly where `dev-timeline.ts`'s `[timeline] screen … header +Xms · content +Yms` line
lands. The rig is complete minus credentials.

## Key decisions

- **Built the deferral variant anyway, and parked it in a draft.** Without it there is
  nothing to measure against, so it is the single most useful thing to leave behind. It must
  not merge unmeasured, hence the draft and the `Refs #2298` rather than `Closes`.
- **Split the extraction from the deferral** (`5832fe1ec` vs `4a9fc4790`). `useAfterFirstFrame`
  keys off the holding component's first commit, and `EpisodeDetailScreen` renders its own
  skeleton, so a gate there would never engage — the same reason `LoadedTitleDetail` exists.
  Separating them put the risky 342-line move in a commit whose only job was to change nothing.
- **Declined a shared `useBelowFoldDeferral` hook** with `TitleDetailFrame`: the ticket says to
  use "the existing first-frame hook, exactly as the Title Frame uses it", it is three lines,
  and it disappears if the measurement rejects the deferral. Flagged on the issue for
  #2299–#2302, where it becomes the third-to-fifth copy and worth doing.
- **Did not create the research note.** The ticket says the first candidate to need it creates
  it; with no numbers it would have had no rows.
