only the current mode's tags and links each one at that mode's Titles Category;

## Key decisions

- **`getServerMediaMode()` alone**, not the ticket's literal
  `getSubdomainMediaMode()`-then-`getServerMediaMode()` pair: the former already
  answers the host before the cookie (`media-mode-server.ts:26-30`) and Tags has
  no `?media=` widening, so criterion 8 holds by construction. The spec axis agreed.
- **`ShowPoster mediaType="movie"`** for the Movies grid, not `MoviePoster`, which
  carries none of the four `display*` overlay props the Shows grid passes. Both
  the standards and spec axes agreed.
- **The Tags total calls `getProfileTags` and counts rows** rather than
  reimplementing its `having` clause — criterion 7's own wording.
- **`CONTEXT.md`'s `Titles Category` was qualified**: it said an out-of-mode titles
  category "is answered an empty page", which is the API's behaviour; the web
  renders in place per point 3. §6 allows CONTEXT.md in the ticket PR.
- **Shipped a consequence rather than deviating:** the prescribed List-type
  intersection makes `album`/`artist`/`track` Lists unreachable from tag pages.
  Verified real (a track List's tag chip links at the narrowed page,
  `list/track/[slug]/layout.tsx:159`). Flagged in the PR body AND as a comment on
  #3518 offering a one-line option 2 (union the unmoded types back in). If Felipe
  answers on the issue, that answer governs — it is a re-spec of criterion 5, not
  a new ticket. **Next iteration to touch Tags should read that comment first.**
