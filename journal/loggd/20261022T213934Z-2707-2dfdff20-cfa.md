## What shipped on the branch

The #2694 adult-movie guard extended across the whole member-movie family, in
two layers rather than one:

1. **Pages.** `movie-user-page-request.ts` calls `requireVisibleMovie` above the
   profile read (layout header, poster, four tab bodies); all six
   `generateMetadata` exports call `movieVisibleToViewer`; `(review)` and
   `r/[reviewNumber]` call the guard in their bodies because they already join
   `accountAuthority`.
2. **Hydrators, which were the real holes.** `getShowDiaryPaginated` and
   `getShowUserListsPaginated` are also the `loadShowDiaryPage` /
   `loadShowListsPage` server actions, and `readMemberActivityPage` backs
   `loadActivityPage` and `/api/v1/activity` — each takes `profileUserId`,
   `tmdbId` and scope straight from the client, so the page gate was never the
   only way in. All three now return an empty page before any read.

## Key decisions

- **The gate went at the chokepoint, not the page.** `readMemberActivityPage`
  covers the action, the page leaf, the profile feed and the v1 route at once.
- **Two gates, one pipeline, because of credentials.** `movieVisibleToViewer`
  resolves the viewer from the **cookie** only; `/api/v1/activity` resolves a
  member from a **Bearer token**. Using the cookie gate there would have
  refused an opted-in mobile member their own activity — fail-closed, so no
  leak, but a wrong answer. Hence `movieVisibleToMember(id, viewerId)` sharing
  the credential-independent half. `movieVisibleToViewer` is byte-identical for
  its nine existing callers.
- **Series are never gated:** TMDB carries no adult flag for them.
- **A rebase, not a freshness rebase.** Session 6 hit a real textual conflict
  with #2783 (ticket #2708), which had refactored the same function into
  `movieVisibility(id) -> {visible, adult}`. Both refactors are kept, layered:
  main's export reimplemented on this branch's shared pipeline. #2787's seven
  overlapping member-movie files merged clean.

## Things the next iteration should know

- **An unmocked adult gate withholds, it does not pass through.** Main's new
  `r/[reviewNumber]/page.block.test.tsx` failed 7 of 8 assertions on the
  rebased tree because it has no database for the stored-flag read. Fixed by
  stubbing `require-visible-movie` as the sibling suites do. Any future
  member-movie page test arriving on main needs the same stub.
- **Main's `{visible, adult}` pair had no test on any branch** before this PR
  (its two proxy suites mock the module; the gate's own suite only read
  `.visible`). The new `describe("movieVisibility")` covers it.
- **Out of scope, deliberately:** the *unscoped* profile activity feed still
  shows a flagged movie's activity. The spec axis confirmed #2707 enumerates
  only `/<member>/movie/<slug>` and its tabs, and #2685 has a
  `member-activity-gate` child for that surface. Do not widen PR #2781.

## Why it did not merge

Six CI wait rounds, **four of them timeouts** (builds 4061, 4068, 4083, 4089),
every one with "no failed jobs" — the host's three Buildkite agent slots were
busy with other loops' builds (load average 36.59 on 16 cores at the end,
builds 4085/4086/4087/4090 churning while ours queued). One genuine red, in
round 2: build 4061's E2E job died in `test:security` bootstrap on a missing
`supabase-go` binary, before any test ran, on a branch touching no
`supabase/`, `drizzle/` or `security/` file — not the diff, and §5.4's single
re-run allowance went on it (empty commit `59366f1bd`). Round 4 came back
green on that head.

Published the learning `ci-wait-times-out-behind-host-build-queue` for the
timeout pattern: a pending build with no failed jobs is neither a red nor a
flake, and the only correct move is to hand off with the claim intact.
