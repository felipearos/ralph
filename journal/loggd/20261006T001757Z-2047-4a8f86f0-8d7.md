# 2026-10-06 — #2047 List Write: create, delete, content save, Cover Pin and List settings

**Outcome: merged.** PR #2099, squash-merged at `eaa60995` through the Mergify queue; issue #2047 auto-closed. Parent spec #2034.

**What landed.** Five more kinds of the mobile List Write consequence module
(`mobile/hooks/list-write.ts`) are implemented — `list-create`, `list-delete`,
`list-content-save`, `list-cover-pin`, `list-settings` — and the seven mutations of
`mobile/hooks/useCreateList.ts` and `mobile/hooks/useManageList.ts` become thin adapters that
name a kind. `list-membership`'s input gained an optional picker page so the Manage List screen's
membership write uses that kind. `CONTEXT.md` gained a **List Write** glossary entry.

**Key decisions.**
- `list-delete` sweeps the List out of cached List Surfaces in **confirm**, not begin, and calls
  no `removeQueries`: the screen navigates away on success, a refused delete would have blanked
  real surfaces, and the unedited `useManageList.test.tsx` delete case asserts the detail read is
  *invalidated*, which a removal would make `undefined`.
- The sweep drops an array entry only when it has a matching numeric `id` **and** a string `slug`.
  Every List Summary shape on these surfaces carries one; `ListDetailItem` does not. That is what
  keeps a List detail item sharing the List's id out of the sweep, and there is a test for it.
- One shared `writeCanonicalListMeta` confirm for the three save-answer kinds. Items are
  deliberately not patched (`SavedListItem` has no `name`/`posterPath`). AC2's Cover Pin clause
  lands there: the server's answer already omits a pin whose item left the List.
- `list-cover-pin` **is** the content save's three steps (assigned, not copied) after both review
  axes called it a second name for the same writer. The kind stays because #2047 names it and the
  kind is the vocabulary of the write.
- Kind assignments: ranked toggle → `list-content-save` (CONTEXT.md's List Edit Session puts it
  behind Save); share link → `list-settings`; Manage List membership → `list-membership` with no
  picker page; a save whose only content change is `coverPins` → `list-cover-pin`.
- `supporterRefused` rides the content-save input on the error path — recognising the refusal code
  is transport knowledge, the consequence is the module's.
- Behaviour changes: the five migrated manage mutations settle on either outcome (before: success
  only); `list-create` settles on success only; `list-settings` cancels in-flight detail reads.
