## Three traps worth remembering

- **`export const dynamic` is illegal under Cache Components.** The association
  routes had it and `bun run build` refused by name. Removing it made them
  `○ Static` — prerendered, so the env would be baked at build time and
  configuring the credentials later would need a redeploy to take effect.
  `await connection()` is the Cache-Components-era way to say request-time.
- **A dot-directory is invisible to `tsc` and ESLint.** `src/app/.well-known`
  compiles in the Next build and is skipped by a wildcard `include`, so it
  passed `bun run typecheck` while being unchecked. `tsconfig.json` names it
  explicitly now. ESLint is what surfaced it, with a "not found by the project
  service" error.
- **`**/*.ts` inside a block comment ends the comment.** The `*/` in the path
  did exactly that and produced a parse error 10 lines below where I was
  looking.

## The review earned its keep — twice

Both axes ran (`ralph/inspect.sh`), and the fix commit's follow-up review found
a real hole the first pass had missed:

- Dropping `"recovery"` from `AUTH_CALLBACK_OTP_TYPES` did **not** close the
  recovery path. Supabase's implicit recovery redirect is
  `#access_token=…&refresh_token=…&type=recovery`, which the credential branch
  accepted as an ordinary session — signing a member in while the
  `password_reset_pending` gate never fired. The refusal is now checked against
  the URL above every credential form.
- `error_description` is attacker-controlled (it is part of an emailed URL), so
  quoting it let a crafted link print anything it liked on a Loggd page.
  Failure copy now comes from `error_code`, a short enum, mapped to our own
  sentences.
- The two surfaces each carried the same verdict→action switch and their
  failure copy had **already drifted apart inside one change**. `runAuthCallback`
  is the answer: sharing the parser was not enough, because the decision and the
  action are one thing.

## Costs and infrastructure notes for the next iteration

- **`ralph/inspect.sh` timed out repeatedly.** The first standards run died at
  900s with no salvageable output; a rerun at `RALPH_INSPECT_TIMEOUT=1700`
  succeeded for both axes, and the follow-up review timed out again at 1700s.
  The fallback for that stage is only specified for exit 2, not for a timeout,
  so I ran the follow-up as an in-session `Agent` on opus and said so here.
  It is the call that found the recovery hole, so skipping it would have cost
  more than it saved. Consider raising the stage's default timeout.
- **`delegate.sh` has the same shape of problem**: the first web brief timed out
  at 900s having written nothing. Splitting it into two briefs half the size
  worked first time both times. Write smaller briefs.
- **`ralph/ralph.test.ts` fails 19 tests locally inside a live loop** and passes
  in CI. It spawns `ralph.sh`, and the `RALPH_*` variables exported into the
  iteration's own shell perturb it. Do not chase it.
- **`git stash -u` on a clean tree saves nothing, so a later `pop` unpacks
  somebody else's stash.** I did this and pulled `web/quick-fixes` work into the
  worktree. Nothing was lost — a conflicted pop keeps the entry, and
  `git reset --hard` plus removing the untracked residue restored both sides —
  but check `git stash list` before popping, or do not use stash at all.
- **The worktree was moved out from under me mid-iteration**: something switched
