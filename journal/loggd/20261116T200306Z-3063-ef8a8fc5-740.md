## One readiness correction

**#3098 moved `ready-for-agent` → `ready-for-human`.** It adds the Started Date column
to `src/server/db/schema.ts` with a generated migration; loops cannot apply migrations.
Third time this call has been made in the Books specs (#3190 in #3028, #3227 in #3053) —
these spec trees consistently ship their schema ticket as `ready-for-agent` on the
strength of being additive and classifier-safe, which is not the rule here. **A triager
taking a Books tree should expect exactly one such ticket per spec and look for it.**
#3098 is unblocked and is the root of #3070, #3071 and #3240, so it wants a person early.

The other six `ready-for-agent` children (#3106 #3237 #3243 #3245 #3256 #3259) were
re-checked against the readiness rules and all hold. The 13 `needs-info` children keep
that label; this pass changed no acceptance criteria.

## Tooling notes

- `set-section`'s field is **`heading`**, not `section`. The first dry run was refused
  25 times over for it (exit 0 on a dry run, so read the body not the code). Worth
  knowing before writing a 25-op staffing plan.
- A staffing-group **name may repeat across trees**: the frontier keys groups
  `tree:<parent>:group:<name>` (`frontier/next-tasks.ts:901-905`), so this tree's
  `books-profile-mobile` does not merge with #3053's identically-named group. The board
  prints both; they are distinct.
- The `gh issue comment --body-file` guard refuses a body file it cannot read; pass
  `--body "$(cat …)"` instead.
