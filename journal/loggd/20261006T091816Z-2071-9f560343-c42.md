## What the change does

`settleProfileLists` in `mobile/hooks/list-write.ts` — the settle shared by the
`profile-list-pin`, `profile-list-reorder` and `list-directory-save` List Write
kinds — kept a narrower contract than every other List Write. It now refreshes
`listSurfaceKeys.ownerProfileLists()` and `profileKeys.me()`, then delegates to
the shared `staleListSurfaces(queryClient, { listDetails: false })` instead of
its own `isProfileListsKey` predicate.

Most of #2071 had already landed: #2093 moved these writes onto the List Write
contract, and #2051 landed the static raw-key conformance test that is AC3 and
AC4. What was left was a behaviour regression #2093 introduced — the viewer's
profile summary stopped refreshing and the browse Lists surfaces stopped going
stale.

## Key decisions

- `{ listDetails: false }`: verified against `ListDetailMeta` and
  `ListSummaryWire` — neither carries a pin, pin-order or List Directory field.
  Flagged in the PR body as a narrowing the owner may widen.
- The settle now also stales every title's Lists directory
  (`mediaListsPredicate`), wider than the pre-#2093 code. Comes with the shared
  helper by design; the spec axis judged it defensible.
- **AC3 was deliberately not duplicated.** A second raw-key scanner in
  `list-surfaces.test.ts` would be a weaker copy of
  `hooks/__tests__/list-write-key-owner.test.ts`; a pointer comment went in
  instead.
- Declined: unifying `profileKeys.me()` vs `listSurfaceKeys.profileRoot()` in
  one module (pre-existing, other kinds' blast radius); dropping the `stale`
  loop as duplicated (`PINNED_KEY` and `DIRECTORY_KEY` are not in
  `EVERY_SURFACE`, so it is their only coverage).

## Traps worth remembering

- **A vacuous first test draft.** Asserting staleness via `fetchStatus` on
  seeded keys still passed with `refetchType: "all"` — a seeded key with no
  observer never refetches whatever invalidates it. Replaced with live
  observers counting each read's `queryFn`. This is the general trap for any
  React Query invalidation test.
- **A pre-existing suite encoded the defect**: `list-write.test.ts` asserted
  "the owner read and the profile Lists reads, and nothing else", with
  `BROWSE_KEY` among the untouched. Three tests failed on the fix and were
  rewritten.
- **An ordering trap:** referencing a `const` declared below a `describe` from
  inside that describe's *body* yields `undefined` under the jest/babel
  transform — not a TDZ `ReferenceError`. It seeded a query with an undefined
  key and crashed `isProfileListSurfaceKey` inside `invalidateQueries`. Fixed by
  moving the describe below the shared apparatus.
