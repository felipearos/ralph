## What shipped on the branch

A Pending Intent record now carries `runId` (a nonce minted once per app process)
and `capturedAt`. `consumePendingIntent` refuses an **unbound** record
(`userId === null`) unless it came from this run and is at most 30 minutes old
(`isFreshFromThisRun`); bound records are exempt from both checks. A record
written by an older build carries neither field, so it is refused when unbound
and still consumed when bound. Four commits: the library change, the gate-seam
regression test plus `CONTEXT.md`, whole-record assertions relaxed to
`toMatchObject` in two sibling suites, and the review fixes.

Both local review axes passed (`ralph-review-standards`, `ralph-review-spec`),
and the marker in `.claude/reviewed/` covers `1d45212d1`.

## Decisions and dead ends from the implement phase, for the record

- Ruled out a **sign-up-attempt marker** written by the auth screens: the
  legitimate interruption capture happens *before* the member reaches the sign-up
  screen, so "captured at or after the attempt started" would discard it too.
- Ruled out distinguishing **ambient `usePathname()` capture from interruption
  capture**: `mobile/components/media-actions/MediaActionRow.tsx:62-64` records
  that the ambient capture IS the "tapped something, was sent to sign up"
  mechanism, so discarding it would break the ticket's second acceptance
  criterion.
- Accepted limit: an email-confirmation link that **cold-starts** the app loses
  the capture (new run). The module's own stated trade, "one missed resume, never
  a wrong one". Both limits are in the PR body.
- Web needed no code change; the evidence is in the PR body and was checked
  independently by the spec reviewer.
- `delegate.sh` **was** used for slice A (library + unit tests) and slice B (gate
  test + glossary), one round each, exit 0 both times. The review fixes and the
  assertion relaxations were written in-session — small and findings-driven.
