## Key decision: split, and two children rather than three

Unlike yesterday's #2480, this oversize flag is a **true positive**. Four checkboxes, so it was the
surfaces arm again — but #2483 genuinely builds on server, web and mobile rather than merely
referencing them. Loggd's split rule wants one child per surface in dependency order
(db → api → web/mobile). One `ralph-mapper` pass over `origin/main` says the api/web seam cannot be
cut here:

- One shared completion path, `advanceImportSetupStep` (`src/server/imports/onboarding-step.ts:45`),
  called by both transports (`src/app/api/import/jobs/route.ts:145`,
  `src/app/api/v1/imports/jobs/route.ts:161`).
- Making `seen` completable under its watched-title minimum makes the browser-side retry at
  `src/app/settings/data/import/_components/useImportJob.ts:323` wrong — it falls back to the public
  action, which will then refuse. So a server-only child could not land without editing a web file.
- `advanceImportSetupStep` returns `snapshot.completed` (`:58`), which after `seen` is `false` —
  indistinguishable from a refusal. Whatever field fixes that is written by the server and read by
  the client, so it is one child's work.

Mobile **is** separable: `mobile/components/onboarding/OnboardingFlow.tsx:81` already leaves setup on
`onboardingCompleted` and otherwise refetches the snapshot, so the mobile panel needs no envelope
change, and its RNTL verification runs against a mocked accepted-import response.

So: **#2490** (server + web, blocked by #2479) and **#2491** (mobile, blocked by #2479 and #2480).
Both `ready-for-agent`, both staffing group `onboarding-core` — #2490 collides with
#2479/#2482/#2484/#2487 on `src/server/queries/onboarding.ts` and the equivalence test; #2491
collides with #2480 on the mobile seen step and `OnboardingFlow.tsx`.

## The one structural thing I could not express

**No native blocker links #2491 to #2490.** `add-blocker` requires a real issue number for its
`issue` target, and only its `blockedBy` may name a plan-local ref — so an edge between two children
the SAME plan creates is not expressible, in either direction. Rather than leave the edge as a
dangling prose line (the frontier only reads `#\d+` under `## Blocked by`, so a numberless line gates
nothing), I **specified #2491 so it does not need the edge**: its verification is RNTL over a mocked
accepted-import response, which is what `mobile/__tests__/onboarding-flow.test.tsx` already does, so
it is completable and mergeable on its own. The real-device ordering is written into its body prose
and into #2483's split comment.

Worth knowing for any future split: if you genuinely need a child-to-child edge, it takes two
iterations, or one child has to be scoped to stand alone.
