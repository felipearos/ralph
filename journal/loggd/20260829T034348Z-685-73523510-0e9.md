## The thing that would have cost the next person an hour

**The local mail service is Mailpit, not Inbucket.** `supabase/config.toml`
spells the section `[inbucket]`, the container is `supabase_inbucket_loggd`,
and every doc in this repo says "Inbucket" — but CLI 2.75 runs Mailpit v1.22
under that name, and its API is a different shape: `/api/v1/search?query=to:…`
and `/api/v1/message/{id}`, not Inbucket's `/api/v1/mailbox/{name}`. Going by
the config name gets a 404 that reads exactly like a stack that is down.
`e2e/mailbox.ts` is the one place that knows this now, and the two docs that
sent a reader to "the Inbucket mailbox" were corrected.

## The design fact worth carrying forward

**A test that reads the mail is a different test from one that mints a
session, and the difference is the whole ticket.** Nothing stops an e2e from
calling the admin API with the service-role key and getting a confirmed
session in one line. That test would have passed against the bug this ticket
was filed for: GoTrue does not reject an `emailRedirectTo` that is off the
allow-list, it silently replaces it with `site_url`, so confirmation "worked"
and landed the member on the home page. The only artefact that shows it is the
URL in the mailbox. Follow the link the member would follow, or do not claim to
have tested confirmation.

## What was measured rather than reasoned

The previous iteration inferred that turning `[inbucket]` on would hand the
`email_sent` counter back to the TOML, because the old note said the CLI
overrode it "when SMTP was disabled". The standards review challenged it and
the inference was wrong: `docker exec supabase_auth_loggd env` with inbucket
ENABLED on CLI 2.75 still shows `GOTRUE_RATE_LIMIT_EMAIL_SENT=360000`. The
local counter binds nothing, as before; only the reason changed. Two
consequences beyond the correction — the local `email_sent` is inert, so it is
not a flake source for a suite that signs up repeatedly, and the raise from 2
to 30 was defended on grounds that never applied locally.

## Two things the specs had to be built around

- **The auth rate limit is one bucket per caller, and every unauthenticated
  test is the same caller.** Five a minute keyed by IP, so this file's six
  requests plus every other auth spec's land together and the sixth 429s in
  whichever test drew it. It only bites when KV is configured — `doppler run`
  supplies it, CI does not — which is the shape of bug that passes on one
  machine and fails on another. Each test now sends its own
  `X-Forwarded-For` from the `2001:db8::/32` documentation range.
- **`max_frequency` refuses a resend issued the instant the first mail
  lands.** That refusal is AC4 working, so the test waits the gap out rather
  than asserting the 429, which would be a race against how fast the first mail
  arrived.

screen after successful sign-up", failing its first attempt on

**My first diagnosis was wrong and the second build proved it.** I read it as

because it is still more honest than 30s, but the number is not the fix.

## Dead ends and cautions

- **Restarting the local stack destroys its data.** `supabase stop` reports
  "Local data are backed up to docker volume" and `supabase start` still came
  back with zero rows in `profiles` and `auth.users`. Re-seed with
  `bun run db:seed:e2e` — and the shell env wins over `.env.test`, so a shell
  carrying the hosted `NEXT_PUBLIC_SUPABASE_URL` seeds against the wrong
  project and dies on "Invalid API key". Pass the local values explicitly.
- **`bun run test` fails 32 tests in `ralph/*.test.ts` on this machine** and
  the diff is not the cause: those three files are byte-identical to
  `origin/main`, and they spawn and inspect a supervisor while a live one is
  running. Do not chase it from inside the loop.
- A stale `.next-test` makes `bun run typecheck` fail inside generated
  `validator.ts` with no error of your own. `rm -rf .next-test`.
- The review stages are not free: the spec axis timed out at 900s (exit 4) on
  a brief that invited it to audit the auth stack. Narrowing it to "answer six
  questions, prefer these files, do not search" and raising the timeout got a
  full report in a fraction of the budget. A wide brief is a slow brief.
