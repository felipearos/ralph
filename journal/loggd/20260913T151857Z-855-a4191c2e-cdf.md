## What shipped

- **Transport** `GET /api/v1/users/stats` gained `highestRated`, `mostWatched`, `monthlyActivity` and `dailyActivity`.
  - They sit behind the same validation → subject lookup → single `canViewFullStatistics` flow. `parseScopeAndYear` is shared by the five scoped sections.
  - The limit is 10, as on the web. Items carry `mediaType` + `tmdbId`. Daily returns sparse days plus the `year` it counted and `allTime`.
- **`gateAdultStatsTitles`** (`src/lib/api/adult-gate.ts`) gates both ranked sections: `media_metadata` has no adult flag.
  - It resolves the viewer preference first, so there are no fetches for opted-in viewers or TV-only lists.
  - It uses `getMovieBasicOr404`: a 404 is dropped, and a transient TMDB error throws, so the section shows its retry.
- **Two shared-query fixes**, both of which also change the web chart:
  - `getUserMonthlyActivity` no longer adds a 13th month to a `rangeForStatsYear` range.
  - It also no longer counts a logged episode twice (Codex P1). `logShowCore` → `toggleEpisodeWatchedCore` writes a status row stamped `now()`. A status row now counts only when there is no dated, published review for that episode.
  - PGlite regressions for both, mutation-checked.
- **Mobile:**
  - `lib/stats-patterns.ts`: types plus pure UTC helpers.
  - Four hooks keyed `[..., section, scope, year ?? "all"]` with no placeholder data.
  - `components/profile/stats/*`: each section has its own skeleton, empty state and local retry.
  - Daily is a month chip row over a one-month calendar with ~44pt cells, keyed on `${scope}-${year}`. Its unit is "diary entries", and a TV caption explains why quick marks appear only in Monthly.
