## Things that will bite the next mobile ticket

- **`@testing-library/react-native` renders asynchronously here.** `render` and
  `renderHook` both return promises, and `screen.findByText` answers
  "`render` function has not been called" if you forget to await them. So does a
  bare `act(() => …)` around a state change: the assertion reads the previous
  render. Every interaction in `onboarding-flow.test.tsx` is awaited for exactly
  this reason, and its file comment says so — read it before writing a new
  screen test.
- **Hermes has no `crypto.randomUUID`, and `useIdempotencyKey`'s fallback is
  deliberately not a UUID.** The Import Job endpoint validates the v4 shape, so
  `mobile/lib/uuid.ts` formats one itself (`getRandomValues`, then `Math.random`)
  rather than reusing that key minter. Do not wire the two together.
- **The React Compiler lint rule forbids `setState` in an effect**, and the
  executor hit it head-on: two effects copying the watched job's terminal state
  into local state. The fix was to stop storing it — `watchedView()` derives
  phase, outcome and messages from the query at render, and local state now
  holds only what this device is *doing*. That is the better design anyway, and
  it is what the rule is for.
- **Root `tsconfig.json` excludes `mobile/`.** `bun run typecheck` says nothing
  about mobile code; the type-aware root `bun lint` is what covers it.
  `bunx tsc -p mobile --noEmit` reports 4 pre-existing errors (two test files, a
  `global.css` side-effect import, `push-store.ts`) — do not chase them.

## The two review axes, and what they were worth

Both ran on `ralph/inspect.sh` (opencode). **Standards timed out at 900s on the
first attempt** with a brief that invited exploration; re-run with an explicit
"read only these files, do not grep the repo" and `RALPH_INSPECT_TIMEOUT=1500`,
it finished in minutes. Narrow the brief before raising the timeout.

Spec found the two real ones:

- **The panel's copy promised list imports.** `runGenericCsvImport` writes watch
  statuses and reviews, and no list table appears anywhere in the run. Copy
  fixed. Generalise: check member-facing copy against what the *run* writes, not
  against what the source format contains.
- **The retry button could duplicate a live Import Job.** The id is minted before
  the POST precisely so a lost response reconnects — and the only recovery
  offered was "Try again", which called `reset()` (clearing the id) and re-picked.
  Now a create that never got an answer exposes `pendingJobId` and offers
  "Check that import" (`reconnect()`) ahead of "Choose another file". A job
  watched to a terminal failure is deliberately *not* pending: its answer is
  known.

Standards found three `as` assertions and a stray blank line; all fixed. It also
confirmed the web route is byte-equivalent in behaviour after the extraction —
same check order, same status codes, same message strings.
