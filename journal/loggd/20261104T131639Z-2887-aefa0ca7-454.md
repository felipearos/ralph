## What changed

Adding a `drizzle/NNNN_*.sql` used to pass every targeted local run and then fail in CI on `scripts/migration-classifier.test.ts`, whose pin map asserts set equality over the whole `drizzle/` tree. The map moved out to `scripts/migration-verdict-pins.ts`, and the check now fires where a migration is actually written: `bun run db:classify-migrations`, `bun run db:generate` and `.husky/pre-push` each report a missing row with the test's name and the exact row to paste, and the test's own failure now names the unpinned migration instead of printing a set diff.

## Key decisions

- **`db:generate` needed a wrapper script, not a chained `&&`.** bun appends a run's extra arguments to the end of the script string, so `db:generate` as a chain sent `--custom --name x` to the classifier rather than to drizzle-kit. Proved in a throwaway package before accepting the review finding. This is a trap for any `package.json` script that chains a check onto a tool that takes flags — worth remembering beyond this ticket.
- **A `--custom` placeholder classifies `safe` with no statements**, so the row printed at generate time is wrong for the migration the file later becomes. The report warns rather than printing a row to paste. The subtlest thing the two correctness passes found.
- **`.husky/pre-push` reads the working tree, not the pushed commits** — a dropped P2, documented in the PR body for sign-off rather than fixed. It passes a push whose row is pasted but uncommitted, and blocks a push from a checkout holding an untracked WIP migration. Reading the pushed revs would mean sharing git's push list on stdin with `lint:shadcn`, which consumes stdin.
- Exit 1 from the CLI now means "unsafe, or a missing/stale pin". No in-repo caller reads that exit code.
- Vocabulary: **migration verdict pin**, since `CONTEXT.md` already owns "pin" for List concepts. No glossary entry added — this is build tooling, not domain.
