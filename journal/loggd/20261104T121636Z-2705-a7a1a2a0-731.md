## Key decisions

- **AC 3's "cover prefix" cannot be met literally, and that is the one thing a
  person has to rule on.** `user_cover_override.cover_url` holds a provider's
  URL — Hardcover edition images, iTunes artwork, and this app's own
  `/api/musicbrainz/image-proxy?url=…` path. There is no cover bucket and no
  cover upload anywhere in `src/` or `mobile/` (`grep '\.upload('` finds only
  avatars, profile-backdrops and import-uploads), so there is no own folder to
  be outside of. I created the Write Core the criterion assumes
  (`src/server/queries/cover-override-write.ts`, modelled on `avatar-write.ts`)
  and gave it a URL **shape** guard: absolute `https:`, or that proxy path,
  ≤ 2048 chars. Provider hosts deliberately not enumerated — Hardcover returns
  whatever CDN its editions live on. Flagged in the PR body with the two
  alternatives the spec reviewer proposed. The spec axis reached the same
  reading of the criterion independently, which is worth something.
- **`storage.objects` policy drift needed no code.** The verifier already
  queried `pg_policies where schemaname in ('public','storage')` and
  `readDeclaredSql()` already concatenated both trees. Declaring the bucket's
  four policies is what brought them into the comparison; only the bucket
  **rows** were unread. Do not re-derive this next time — half of AC 2 was
  already built.
- Bucket drift is **reported, not judged**: it does not touch the verdict or
  exit status, which are a claim about the anonymous read surface. The AC says
  "reports", so this meets it, but a CI run will not fail on bucket drift.
- `src/test/database.ts`'s classifier already files `0082` under
  `supabase-storage` and excludes it from the pglite replay, as it does `0028`.
  No change needed there.

## Review — all three axes earned their cost this iteration

**correctness: 0 P1, 2 P2, 2 P3 — 3 fixed, 1 dropped.**
- P2, a real hole I had created: my guard filtered out `/`, `.` and `..`. An
  `https:` URL's path is parsed by the WHATWG rules, where **a backslash is
  also a separator**, so `<own prefix>..\<other id>\backdrop-1.webp` carries no
  forward slash, is not `..`, and resolves into another member's folder. I
  verified it with `new URL()` rather than trusting the report. Fixed by
  matching `^backdrop-\d+\.[a-z0-9]+$` — an allowlist of the one shape
  `BackdropForm` has ever written (`git log -L` on that line: one commit,
  `9165adc30`, so no legacy name is rejected). Mutation-tested: reverting to the
  filter fails the three new cases. **Generalisable lesson: a separator filter
  is not a path guard; name the shape you accept.**
- P2: the storage suite's overwrite case re-sent the seeded bytes, so its
  folder listing passed whether or not the write landed. Now sends a larger
  payload, reads the size back privileged, and asserts the payloads differ in
  size so the check cannot go vacuous again.
- P3: the guard only ran for `typeof === "string"`, so an action call with `5`
  skipped it and Postgres cast it into the column. Non-strings now refused.
- P3 dropped: the env prefix is unnormalised, but `avatar-write.ts:76` has had
  the identical pattern since #772 — pre-existing and repo-wide, wants its own
  ticket covering both. Named in the PR body.

**spec: 3 ACs met, AC 4 unmet — and it caught a guaranteed CI red.**
`docs/development-workflow.md:210` requires every committed migration's verdict
to be pinned in `scripts/migration-classifier.test.ts`, whose list enumerates
every `drizzle/*.sql`. I had not added `0082`, so that file was FAILING, and
none of my targeted vitest runs touched it. **Next migration PR: add the
classifier row in the same commit as the migration.**

**standards: 1 P2, 4 P3 — 4 fixed, 1 dropped.** Duplicated
`PRO_SUBSCRIPTION_REQUIRED` moved to `~/lib/tier-utils` — the **pure** half, not
`tier.ts`, because the integration suites mock `~/lib/tier` with `{ isPro }`
alone and a sentinel read through that mock is `undefined`. I found that by
breaking it, which is also why both suites now pin the sentinels to their
literal text: the core and the suite read them through one module, so a bad
re-export would make both `undefined` and every refusal assertion would still
pass. Also added the two `server-action-surface.test.ts` rows this move owes.
