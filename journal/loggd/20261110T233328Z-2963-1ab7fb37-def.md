## The findings worth keeping

1. **Criterion 7's mutation checks are vacuous on almost every request shape, and for all five guards rather than only book keys.** Dispatch skips a source outright when the request excludes its type (`:1343-1355`), and each source self-narrows under `media` or a scope (`:526`, `:686`, `:715`, `:746`, plus `reviewScopeConditions` at `:484-496`). So each check needs a request with **no `media`, no scope, and an `exclude` that does not name its own type**. My first draft said "no `exclude`", which the reviewer correctly called overstated — `exclude=follows` still runs book keys, and criterion 1 names that very request. Third tria unit running where the `assert effect, not mechanism` hazard was the headline finding (#2962 was the second); for this tree it is the thing to look for first.
2. **Criterion 7 counts four guards where there are five.** "Incoming keys" is `fetchIncomingLikeKeys` (`:674`) and `fetchIncomingCommentKeys` (`:703`) — one can be dropped with every test green. The reviewer also noted each check should run on a tab where only its source runs, because on `friends` with `includeIncoming` both like sources run and mask each other (the mocked suite's own doc says so at `activity.test.ts:63-65`).
3. **An existing green test asserts the opposite of criterion 1.** `route.exclusions.integration.test.ts:226` asserts `toContain("read_book")` on a non-excluding request, with the book rows seeded at `:155-177`; `:227` and `:230` move with it. A diff that leaves `:226` untouched and green has not gated the server. This is the single most useful thing the mapper produced and neither the ticket nor I had it.
4. **`media=books` cannot be asked for at all today** (`MODE_BY_MEMBER_LIST_MEDIA` is `shows|movies` only, `media-mode-scope.ts:49-52`), so criterion 4 is reachable solely on the no-`media` request.
5. **Fail closed.** The viewer set must default to the launch constant, never to "all", and must **not** enter `loadActivityPageInput` (`actions/activity.ts:22-33`): Zod strips unknown keys today, so the action is safe as it stands, and the day the field is in that schema a client can widen its own result.
6. **Assert absence by the row, not the item type** — a book review and a liked book review surface as `review` and `liked_review`, the same types the seeded TV rows produce.
7. **A pre-existing hazard, left as a PR note rather than a criterion:** hydration sends anything non-`movie` to `getTVShowDetails` (`:245-252`), a book review's `tmdb_id` is a Hardcover ID (`schema.ts:517-518`), and the adult gate only looks at `media_type === "movie"` (`:967-968`), so a like on a book review may already surface mis-titled at `main`.
