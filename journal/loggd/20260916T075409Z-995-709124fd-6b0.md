## The diagnosis (the part worth keeping)

**#995's named failure was already fixed before this ticket was picked.** PR #993 (`a3dc6d4d`, ralph's #876) folded the `isPending` read into the same `waitFor` as the cache read, in passing. AC2 ("make the mocked answer wait on an explicit promise") was *also* already true — `deferred<T>()` has been there since `5cf3bceb`. The issue was written against a stale picture of the file. Check `git log -- <file>` before trusting a flake ticket's premise.

The real cause, from the `act` warning's stack (last frame `Timeout._onTimeout` in `notifyManager.ts:42`): **TanStack Query notifies subscribers through a `setTimeout(cb, 0)` scheduler.** A notification scheduled by a test's last action fires after every `act` window has closed. That is both the warning and the race on `isPending`. It is a *library timer callback*, not a test call site — so AC3's literal "wrap the test's state updates in act" cannot catch it. `notifyManager.setScheduler(cb => cb())` can; the library's own doc comment names this use.

**The failure never reproduced on this host in any configuration.** It is rarer than 1-in-50 here; `await act(async …)` plus onMutate's own awaits usually give the timer enough turns. The warning column tracks the scheduler exactly, which is the useful signal. The mechanism was proved **deterministically** with a throwaway probe (bare onMutate, `isPending` read straight after act, no `waitFor`): `false` without the inline scheduler every time, `true` with it — literally #1591's `Expected: true, Received: false`.
