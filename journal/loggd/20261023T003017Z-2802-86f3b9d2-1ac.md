## What I decided and why

The ticket was already well shaped by the author. What it needed was for its
references to match the code on `main`, which the mapper showed they do not:

- **`API_ROUTE_OWNER` does not exist** anywhere under `src/`, and neither does
  a `search:` entry nor a comment pointing at #2802. The real map is
  `ROUTE_OWNER` (`src/lib/media-types.ts` L94-154), classifying only top-level
  `src/app/` directories as one entry `api: "shared"` (L122). **#2697 is the
  ticket that will classify the `src/app/api` directories** (its own AC says
  so), and its PR #2804 is open right now.
- **I did NOT block #2802 on #2697.** My first draft set `## Blocked by` to
  `#2697`; the round-1 spec review pushed back that this reverses a fact the
  author stated ("None — #2697 is independent of this") for the sake of one
  code comment. Correct. I withdrew it and reworded the last criterion to hold
  either way: replace #2697's comment if it has landed one, otherwise add the
  statement to whichever route-owner entry exists. `Blocked by` stays `None`.

Three substantive findings went into the body:

- **`authors` was missing from the issue's own list.** `type=authors` (~L436)
  calls `searchAuthors`, the same Hardcover client as `books`. Five branches
  leak, not four. Not scope creep: AC1 already said "each search `type`".
- **There is no multi-type path.** `type` absent defaults to `"shows"`, no
  `"all"` (comments ~L519). The original AC3 was conditional on such a path and
  is dropped with the reason recorded.
- **`MEDIA_TYPES_BY_MODE` cannot be the map** the original AC1 asked to derive
  from: it holds DB `media_type` values and has no `tracks`/`authors` entry.
  `SearchType` is also declared in the route file (~L152), not in `src/lib/`,
  so an exhaustive `Record<SearchType, MediaMode | null>` goes beside it in
  `src/app/api/search/route.ts` and `media-types.ts` needs only its comment
  changed. All 13 members' modes are now spelled out.

**Empty vs 404 was settled by the route, not by preference** — no product
decision, so no `decisions` block and no citation. There is no `default:` case:
an unknown `type` returns the full empty payload at ~L526 with status **200**,
and all five callers expect the `SearchResponse` shape. A gated-off type must
answer byte-identically.

**Added in triage and labelled as such in the body:** the gate returns before
the auth lookup (~L212) and the rate limiter (~L224).

**Staffing group `proxy-and-actions`.** Every open sibling under #2686 already
carried one (#2697/#2701/#2702 `proxy-and-actions`, #2698/#2699
`sanitize-and-links`), so readiness rule 3 required #2802 to have one too — it
had none. It edits `src/lib/media-types.ts`, which #2697 also edits, so it
shares that group. When in doubt, share.

**Readiness.** Not a spec, 0 children. No migration, secret, host config,
product decision or Playwright-only verification — provable by
`src/app/api/search/route.test.ts`, `bun run typecheck` and `bun lint`. Jav is
`enabled: false` with an empty `labels` list on this project, so there is no
difficulty label to apply and rule 4 does not bite. Mapper confirmed nothing
under `src/app/api/` calls `isMediaModeEnabled` at `origin/main`, so it is not
already built. ~2 files, 3 with the comment.

## Things the next iteration should know

- **`triage-apply.ts`'s `set-section` field is `heading`, not `section`.** My
  first dry run was refused on all four section ops for that alone. The dry run
  cost one command and caught it before any write — do not skip it.
- **`set-section` with `mode: "replace"` creates a missing section.** `##
  Staffing group` did not exist on #2802 and the replace added it; no separate
  append op was needed.
- **A `gh pr list --search <n>` hit is not an open PR on the ticket.** #2802
  matched PR #2804, which is #2697's branch merely mentioning 2802 in prose.
  Check `headRefName`/title before treating it as a claim.
- **#2697 / PR #2804 is the ticket to watch for this tree.** If it lands
  per-API-route owner entries, #2802's last criterion points at the new entry;
  if it does not, at `api`. Either way #2802 is workable today.
- Jav on loggd is `enabled: false` with `labels: []`, so the **routing bucket
  can never produce work here** and no difficulty reason can be given for any
  ticket. Do not invent one.
