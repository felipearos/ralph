**What the ticket was.** A pure prefactor: `ShowData` in
`mobile/components/log/types.ts` — which *is* the log module's Media Reference
despite its name — had an optional `mediaType`, and both reads in `LogSheet`
defaulted it to `"tv"`. Making it required, deleting both defaults, and stating
the type at every construction site. Ten insertions, seven files, no behaviour
change.

**The AC list undercounts the construction sites and that matters.** It names
six screens; there are seven — `SearchSheet.tsx` builds one in two places, and
without them the app does not compile. Not scope creep, and worth saying in the
PR body rather than letting a reviewer wonder.

**The finding both review axes reached independently, from opposite ends.**
Requiring a field stops a caller *omitting* it. It does nothing about a caller
stating the *wrong literal* — and the search sheet had two literals whose
correctness lived somewhere else entirely:

- `selectFromResult` asserted `"tv"` where `ShowSearchResult["media_type"]` is
  already the literal type `"tv"`. Now `mediaType: result.media_type` — type-
  identical today, a compile error the day the `shows` tab returns anything else.
- The trending fallback has nothing to derive from: `MediaRowItem`
  (`mobile/lib/media.ts`) is deliberately media-type-agnostic — `toMediaRowItem`
  flattens a movie's `title`/`release_date` into `name`/`first_air_date` and
  discards which it was. It is exactly `CONTEXT.md`'s `_Avoid_: TMDB ID without
  media type`. The `"tv"` there was justified only by `useTrending`'s default
  parameter two files away. Fixed by passing the mode explicitly at the call
  site, so the literal below is locally checkable. **#621 makes that hook
  mode-aware**; without this the literal would have stayed valid TypeScript and
  silently logged every trending movie as the show with the same TMDB ID — the
  precise defect #620 exists to prevent, reintroduced as a literal.

Generalisable: after a required-field tightening, audit the *values* the new
call sites supply, not just that they compile.

**Three follow-ups, all found in review, all recorded on PR #623.**

  (`src/components/log/types.ts`, defaulted 4× in `ShowLogDialog.tsx`). Its
  callers all pass it today so those look like dead defaults, not a live bug —
