## The bug the review caught, which is the whole reason to run it

The gate read `useAuthStore(s => s.session)` alone. **The store reads exactly
like a signed-out one until Supabase restores the stored session** —
`{ session: null, isLoading: true }` — so on every cold start of an incomplete
account the gate took the signed-out branch, mounted the entire app (tabs, log
sheets, deep link, and `(tabs)/_layout`'s "no session → push /auth/sign-in"
effect firing on the false negative), then tore it down when the session
landed. Which is precisely the flash AC 1 forbids. `isLoading` is checked
first now, and there is a test for it.

**Generalise it:** any mobile gate that branches on `session` is wrong unless it
branches on `isLoading` first. Nine existing call sites already read `isLoading`
for this reason; this one didn't.

## The render gate, and why it is worth its cost

Gating by RENDERING rather than by `router.replace` is what makes "back
navigation cannot reveal the gated app" true by construction: the app is never
mounted, so there is nothing behind it. The price is that while gated there is
**no mounted navigator**, so anything above the gate that navigates is broken —
which is exactly how the notification-routing finding happened. `signOut`'s
`router.replace("/auth/sign-in")` has the same shape and is the remaining known
gap: the flow offers no way out, so an account that cannot finish (offline, or
a Google account whose username keeps failing) is stuck until relaunch. Not a
blocker — the gate only holds when the API answers — but it is the next thing
to fix in this area.

Budget for finishing every slice yourself and treat what it writes as a head

All five test failures had **one** cause, worth knowing before writing any
mobile test: **this version of `@testing-library/react-native` renders and
dispatches asynchronously.** `render(...)` and `fireEvent.press(...)` must be
awaited. An unawaited press reads back before its state update flushes, which
surfaces as a button that is still disabled rather than as an error — the
executor's tests pressed a toggle without awaiting, so Continue was disabled
when they pressed it and nothing was posted. `screen` also throws "render
function has not been called" if you assert before awaiting `render`.

Second trap: a component calling `useSafeAreaInsets()` needs
`jest.mock("react-native-safe-area-context", ...)` in the test file, or every
test that renders it fails with an unhelpful "unable to find element".

## A worktree hazard that cost real damage, and how it was repaired

**A review subagent checked out a different branch in the shared worktree
mid-review.** Reflog: `checkout: moving from ralph/652-native-onboarding to
web/quick-fixes`. I did not notice, and the `git rebase origin/main` I ran next
therefore rebased **`web/quick-fixes`** — Felipe's quick-fixes branch — dropping
two of its commits as "already upstream".

Repaired with `git reset --hard c89c600a` (the pre-rebase sha, from the reflog);
`git branch -f` refuses on a branch a worktree holds, so the reset is the move.
Nothing was lost, and my own branch was untouched.

**The rule:** subagents told "change no files" still run `git`. Before any
branch-level operation, run `git branch --show-current` in the SAME command and
check it. Never assume the checkout is where you left it while a subagent is
running.
