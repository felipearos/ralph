## Key decisions

- The `"Profile not found"` and throw tests cannot be written with a
  profile-less user id: `watchStatus.user_id` has an FK to `profiles.id`
  (`src/server/db/schema.ts:768-770`), so the write fails first and the core
  returns at the earlier branch — the wrong path. The test file therefore gained
  a pass-through `vi.doMock` of `~/server/queries/onboarding` with a per-test
  `snapshotOverride.answer` thunk, cleaned up in the describe's `afterEach`.
- Both review axes independently flagged `not.toHaveBeenCalledWith(tag, "max")`
  as too weak; the assertions are now `not.toHaveBeenCalled()`, and a
  `rateSeenTitle` refusal case was pinned too.
- Refused on the record: moving the invalidation above the snapshot read
  (contradicts the spec), adding `onboarding-seen-write` to `FENCED_MODULES`
  (optional, out of scope), refreshing `revalidateUserStats.ts`'s stale "the 19
  of them" doc count (optional, out of scope). The standards reviewer raised the
  placement question; it was answered from the issue rather than changed.
