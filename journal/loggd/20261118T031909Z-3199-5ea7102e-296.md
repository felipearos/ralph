## What shipped

The mobile Book screen draws a Credits row from the Book detail read's
`credits` (landed by #3186): round photo, name, role (`null` reads "Author"),
authorship ordered first, first ten only. Each card opens the Author screen
through `usePressInPreparation`'s `author` destination with a
`{ name, photoUrl }` Card Snapshot. No new read — the credits arrive in the
answer the screen already holds. A book with no credits, or an older cached
answer with no `credits` key, draws no row at all.

## Key decisions

- **"See all" ships as a known dead end.** It routes to the Credits screen,
  which is #3225 (listing #3199 under its own *Blocked by*), so pressing it
  shows `+not-found` on any book with ≥2 credits. AC4 requires only that the
  link *be shown*, so hiding it would fail the spec as written. The PR body
  states the dead end, the release implication (land #3225 before any build
  carrying this) and offers Felipe the one-line hide if he prefers. Left as
  shipped — a future session must not "fix" it without his answer.
- **Role `null` reads "Author"** rather than being omitted, matching how the
  glossary now names a Book Credit.
- **Ordering is authorship-first, capped at ten**, with the overflow handled
  by the "See all" link rather than a scroll.
- Routing reuses `usePressInPreparation` and `CategoryTabs`-era conventions
  rather than a hand-rolled press handler, so the existing
  `press-in-route-conformance` guard covers it.
