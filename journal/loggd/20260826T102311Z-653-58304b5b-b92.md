## Read this first: the previous journal's diagnosis was wrong, and it was a repeat of a known dead end

The #653 hand-off journal concluded the repo-wide red was `ralph/ralph.test.ts`,
19 of 49 failing. **It is not.** That is the *same* false signature #651's journal
had already written up and warned about: `runSupervisor` inherits the live loop's
exported `RALPH_*`, and the previous iteration reproduced it in a detached
worktree **from inside a live loop**, so the leak followed it there. Run CI-shaped
it is clean:

```bash

  NODE_OPTIONS=--max-old-space-size=6144 bun run test ralph/ralph.test.ts

```

**A detached worktree does not scrub the environment. Only `env -i` does.** If you
find yourself confirming a repo-wide break by re-running in a fresh worktree, that
is not the control you think it is — the two journals that hit this both did
exactly that. The `RALPH_*`-scrub ticket is still unwritten and still worth having.

**Generalise it: `gh pr checks` red on this repo is not yet evidence of a break.**
Before diagnosing, check whether `main`'s own most recent build is red too, and
whether *any* branch has gone green nearby. Both are one `gh api .../status` call
against a commit sha, and between them they would have saved this ticket a whole
iteration. Three agents share one dind namespace on Felipe's desktop, beside a
Ralph loop and whatever Felipe is running; the box is oversubscribed and that is

## The forensic technique, now with a cheaper first step

The `docker logs buildkite-agent` job-duration read (from #656/#657, extended by
#651) still works and is what produced the varying-death-point table above:

```bash
docker logs buildkite-agent 2>&1 | sed 's/\x1b\[[0-9;]*m//g' \
  | grep -E "builds/<N>#" | grep -E "Starting job|Exit Status"
```

Job **durations** come out of that directly, and a duration is often enough to
name the failing command without ever reading a log. But do the two `status`
calls above *first* — they are seconds, and if `main` is red on a docs commit you
are done.

Two things that cost time and are worth not repeating:

- **`git worktree add --detach <tmp> origin/main` has no `node_modules`.** Running
  the suite there dies on `Cannot find package 'vitest'`, which reads like a
  lockfile break and is not one. Run from the real worktree with `env -i`; on this
  ticket `src/` and `ralph/` were byte-identical to `main` anyway.
- **A polling loop piped to `tail` shows nothing when the tool call times out.**
  Two ten-minute watch loops produced zero output for this reason. Append to a
  file and `nohup` it if you want to watch a live job.
