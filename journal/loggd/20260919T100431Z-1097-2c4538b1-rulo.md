## READ THIS FIRST: a mutant you "killed" may have been killed by the PREVIOUS mutant

My mutation harness applies a patch, runs, then `git checkout -- .`. The
restore only runs **inside** the `run` helper — and `run` is guarded by a
`grep` that proves the patch landed. When a `grep` pattern didn't match (M14's
leading whitespace), `run` never fired, so the edit stayed in the tree. The
next mutant (M15) was then applied *on top of it*, and the 6 failures I read as
"M15 killed" were M14's. M15 — hard-coding the progress bar to `width: "100%"`
— actually **survived**, and the bar's fill was unasserted.

I only caught it because 6 failures for a cosmetic width change didn't smell
right and I re-ran it alone. **Two rules for the next iteration:** make the
restore unconditional (`trap`/`finally`, not inside the guarded branch), and
treat a failure count that doesn't match the mutant's blast radius as a signal
to re-run in isolation, not as a stronger kill.

## READ THIS FIRST: the loop's four-command gate is NOT CI's quality step

CI went red on `bun run --cwd mobile typecheck`, on a one-line mock I added
late: `Image: (props: { style?: unknown })` handed to a `View`, which TS7
refuses. Fixed in `2c4538b1` with `ReactNative.ViewProps["style"]`.

The interesting part is **why every local gate was green while CI was red**.
The prompt's §4 gate is targeted vitest, `bun run typecheck`, `bun lint`,
`bun run build`. Buildkite's `quality` step runs considerably more:

```
bun lint                                  # root — I ran this
scripts/ci-run-if-scope.sh mobile bun run --cwd mobile lint       # I did NOT
scripts/ci-run-if-scope.sh mobile bun run --cwd mobile test       # I did NOT
scripts/ci-run-if-scope.sh mobile bun run --cwd mobile typecheck  # I did NOT
bun run typecheck                         # root — I ran this
bun run test:coverage                     # I did NOT (I ran targeted only)
bun run build                             # I ran this
bun run build-storybook                   # I did NOT
```

**Root `bun run typecheck` does not cover `mobile/`.** Mobile has its own
tsconfig and its own `typecheck` script, and the root one never reads it. For a
mobile-only diff the root typecheck is close to vacuous — it passed on a file
that does not compile. Same for tests: `bun run test` at root is web vitest;
mobile is a separate jest project.

**For any diff touching `mobile/`, run the mobile trio before pushing:**

```bash
bun run --cwd mobile typecheck && bun run --cwd mobile lint && bun run --cwd mobile test
```

The full mobile suite is 209 suites / 2540 tests in ~16s — there is no reason
to run only the targeted files before a PR. I ran targeted ones throughout,
which was right during the edit loop and wrong as the last step before
pushing. All eight CI commands were verified locally before the second push.

## The review axes earned their keep, and found different things

Both ran as `Agent` calls with `model: "opus"` (§5.1), in parallel.

**Spec** found the one I had already flagged to myself and two I had not.
Its top finding was mine: progress denominated over the *loaded* page, so a
200-entry List read "12 of 40" two lines above "200 items" and climbed as you
scrolled. But it also traced a **per-keystroke request storm** I had walked
straight past: `viewerMediaReferences` was derived from `items`, which is
narrowed by the **raw, undebounced** search term. Those references are the
viewer media state read's cache key, so typing fired one `/viewer/media-state`
request per character and blanked every indicator, every dim and the progress
block in between. That is a live defect in #1096 (rulo's own previous ticket),
not something #1097 introduced — I just made it visible by hanging a header
block off the same references. Fix was one word: derive from `loadedItems`.

**Standards** came back "conformant" on every hard rule and still produced the
most durable artefact of the iteration: **Fade Watched had no glossary entry.**
The concept already existed on web (`BrowseContext`, `ViewFiltersDropdown`) and
in mobile's own `BrowseFiltersSheet`, and CONTEXT.md had never named it — a
real gap, not invented language, which `docs/agents/domain.md` says to record
rather than route around. It also caught a comment whose subject was simply
wrong ("the component still funnels it through the sanitiser" — it is the
store's setter) and one that documented my *test strategy* instead of the
code. Both were mine, both written while I was pleased with myself.

It also checked the Storybook rule rather than assuming it: `find mobile -name
'*.stories.*'` returns nothing — all 219 stories are under `src/`. Mobile's
equivalent is a `components/__tests__/*.test.tsx`. Worth knowing before the
next mobile component.

## The decision I want argued with

Progress now renders **only when `!hasNextPage`**. On a List longer than 40 the
block is absent entirely rather than approximate. I chose silence over a wrong
number, and filed #1186 for the real fix (a viewer-scoped count on the List
read — the spec reviewer found `src/server/queries/listProgress.ts` already
computes watched/total per List, so it is one scoped query plus two meta
fields).

The case against: #1067's user story 8 is "so that I see how far I am", and on
a long List a reader now sees nothing. The case for: the parent spec explicitly
decided "progress and fade consume the viewer media state read", so the
server-side count is a departure that belongs in a ticket of its own rather
than smuggled into this one. A nice side effect — with the gate, the block no
longer flickers on page-append chunk churn, because it does not render until
there are no more pages.

## Mutation testing: 23 mutants, 4 real gaps

Beyond the harness bug above, the survivors that mattered:

- **The `answered` guard was dead to the tests.** Signed-out fell through the
  *empty-total* guard instead, and every fixture List was one chunk. The guard
  exists for the half-landed multi-chunk batch, which nothing exercised. Fixed
  with a component test that mocks `useViewerMediaState` directly and asserts
  the **wrong string** ("2 of 2") is absent — not merely that the block is.
- **The store's initial `fadeWatched` was unobservable.** Every test resets
  first, and `reset()` carried its own copy of the literal. I did *not* add a
  test for it — I named the defaults once (`DEFAULT_LAYOUT`,
  `DEFAULT_FADE_WATCHED`) so the two places cannot disagree. Removing the
  duplicate beats testing the duplicate.
- **`ListEntryRow`'s fade forward could be deleted with 26 tests green.** Every
  case rendered the grid layout; the row layout is a second call site with a
  prop of its own.
- **My own rounding test proved nothing.** I used 1 of 3, where `Math.round`
  and `Math.trunc` both give 33 — and the comment I wrote *said so* while I
  filed it as coverage. 2 of 3 separates them, 67 against 66. Writing the
  admission down did not stop me shipping it; the mutant did.

Two more gaps the spec reviewer named and I closed: the fade toggle's **icon**
was unassertable (lucide is mocked to a null proxy, so only `accessibilityState`
was pinned — the icon is the *sighted* affordance), and `GridPoster`'s
`<Image>` branch dim was untested because every fixture uses `posterPath: null`
and only the fallback branch ever ran. A poster *with* artwork is the common
case. Both mocks now render a `View` carrying the prop under test.

## Declined, with reasons

- **Moving the toggle into `ListFiltersSheet`**, where web and mobile's own
  Browse both put it. `ListFilters` flows into `ListControls` → query params
  and `getListActiveFilterCount`; Fade Watched is a display preference and
  would either pollute that type or need a parallel prop channel. It sits with
  its sibling the layout toggle instead — same row, same store, one tap. This
  is a judgement call the reviewer rated minor and I could be talked out of.
- **Renaming `list-layout-store`** now that it holds two preferences. The
  storage key rename needs a migration; the CONTEXT.md entry was the cheaper
  correct move. Note `list-view-*` is forbidden as a name — *List View* is an
  `_Avoid_` for both List Layout and List Surface.
- **`formatProgress` from `stats-people`** for the copy. Different layout
  (split label), and `formatExactCount` on a two-digit count adds nothing. I
  did reuse `progressFraction` from that module rather than re-clamp.
