**Diagnosis.**
- FlashList fires `onEndReached` itself at first layout, so the `offset=3` request is already out before the test's first `reachEnd()`. That request fails fast.
- TanStack's `notifyManager` delivers the fetching and error states to React on a `setTimeout`. Until that tick runs, the `onEndReached` closure still reads `!isFetchingNextPage && !isFetchNextPageError`. Nothing is in flight to dedupe against, so `fetchNextPage({cancelRefetch:false})` re-requests the failed page.
- The duplicate comes from the test's **first** `reachEnd`: an instrumented run counted `offset3=2` when the error appeared. The three later calls were correctly refused.
- Deterministic repro: `notifyManager.setScheduler(cb => setTimeout(cb, 40))` fails 3/3 locally with the exact CI signature.
- Without it the test passed 5/5 sequentially (16.2s cold, then ~2.7s per run) and 36/36 at 8-way parallel. The host fence was idle at 01:33 UTC: the last job, 3294, finished at 01:31:59.

**Ruled out.**
- Query retries: the test client sets `retry: false`.
- FlashList calling with stale props: `checkBounds` reads `recyclerViewManager.props`, which is updated during render.
- Footer skeletons resetting `pendingEndReached`: they live in `ListFooterComponent`, not in `data`.
- Sibling #2189: a different test in the same file, already fixed by #1809.

**Key decisions.**
- Filed rather than fixed. A test-only change that skips the racy first `reachEnd` would hide a real product race the test correctly catches (guardrail 1).
- The issue body was written at `ensure` time, and `file` doesn't rewrite it. So the full diagnosis is in the issue comment, and I retitled the issue to name the hook race.
- `delegate.sh` was called 0 times. No slice was delegable: the fix is out of scope and the whole job was diagnosis.

**Files touched.** None committed. A temporary instrumentation of the test was restored, and the worktree is clean.
