## What landed

In Books Media Mode, Browse's filter sheet gains **Appearance** (a "Fade Read"
switch) and **Your Account** (Read and Wantlist rows), and the book grid narrows
the pages it has already loaded by the viewer's own Book Viewer State. These are
Browse's existing viewer keys, so a value set in Shows mode applies in Books and
back. No **Logged** row is drawn, applied or counted — Book Viewer State cannot
answer it yet (#3200), #3223 adds the row — but the `logged` route key is carried
through every Books write, Reset included.

## Key decisions

- `BookBrowseViewerFilters` is a `Pick` of `BrowseViewerFilters` that omits
  `logged`, so Books mode cannot draw, apply or count it by accident: the type
  enforces it rather than a convention.
- **Filtering is per entry, with no gate on whether the read answered for the
  surface.** The first cut gated on `answered`, mirroring the Shows grid. It was
  unnecessary (`matchesBookViewerFilters` keeps an entry-less book;
  `drawableEntries` gives a not-found chunk no entries) and harmful: it
  deadlocked a blank grid when a page held no books (no ids → no chunks →
  `isLoading: false` with an empty map → `answered` false for ever → no
  auto-fetch, no `onEndReached` at zero items, both empty states suppressed), and
  it flashed every hidden book back on screen on each appended page (20-book
  pages vs 50-book chunks ⇒ a new observer with no previous data). **Do not
  re-introduce that gate.**
- **FlashList's own `onEndReached` must stay inside the auto-fetch bound.** It
  resets `pendingEndReached` on every `data` change and reads content shorter
  than the viewport as near the end, and `handleEndReached` counts toward no
  budget — at 1–8 survivors the grid would walk the whole catalog, a viewer-state
  read per page. Verified in
  `node_modules/@shopify/flash-list/dist/recyclerview/hooks/useBoundDetection.js`.
  Guard: `visibleItems.length < BROWSE_AUTO_FETCH_TARGET` in `BookBrowseGridList`.
- `hasActiveBookAccountFilter` was deleted, not kept for #3223: the gate was its
  only caller, so it had become dead code kept alive by its own test.
- `bookBrowseActiveFilterCount` deliberately unchanged — the grid's book-filter
  empty title speaks for book filters alone. The badge uses the new
  `bookBrowseBadgeCount`.
- **Accepted, not fixed** (stated in the PR body): new books draw unfiltered
  until their chunk answers, and the account empty message can paint for ~a frame
  between auto-fetches. Both are the Shows grid's behaviour, and hiding covers
  before the read has spoken is what AC2 forbids.
- "Fade Read" vs "Fade Watched": the ticket asks for book wording, so this sheet
  says Fade Read; `BookShelfFiltersSheet` still says Fade Watched via the shared
  `FadeWatchedSection`. Aligning them is a follow-up.
