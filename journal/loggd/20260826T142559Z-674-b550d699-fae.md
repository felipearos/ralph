## What landed

A new top-level `security/` directory: six actors (anonymous, owner, unrelated
member, follower, moderator, administrator) driving PostgREST and Auth directly,
so grants and RLS are tested at the boundary rather than through application
query filters. `bun run test:security` wired into the E2E job on both control
planes *before* `bun run db:seed:e2e`, ordering pinned by a new conformance test.

Three decisions worth inheriting:

- **A todo is a rule the baseline does not enforce yet.** All 22 live assertions
  pass against the checked-in schema; anything needing #675–#681 is
  `it.todo("#680: …")`, and that ticket flips it into an assertion in its own PR.
  Nothing is inverted into asserting a vulnerability as the contract.
- **Denials need evidence.** RLS filters a SELECT rather than failing it, so
  `expectNotVisible` proves the row exists privileged first. Writes are worse:
  PostgREST's `RETURNING` projection is itself subject to the SELECT policy, so
  a write that *succeeded* against a row the actor may not read back also comes
  home as zero rows. `expectWriteDenied` therefore takes an `unchanged` witness
  and refuses a silent refusal without one. The spec review found this; it is
  the single most important fix in the diff.
- **No policy names anywhere.** Assertions read response shape only.

`reports.security.test.ts` carries a header comment naming a dependency the next
security ticket inherits: its two staff reads pass today **only because
`profiles` is world-readable**, which is exactly what #675 closes. When they go
red the fault is not in `report`.
