## The one decision that shaped everything: Books becomes drawable LAST

The first draft put "Books joins the set of modes this build can draw" in the vocabulary child and claimed every intermediate state was invisible to members. **That was false, and the spec review caught it.** #2937's criterion 2 makes the picker's modes `drawable ∩ settled server answer` — so the moment Books was drawable and #2936 had granted the preview, Books would have appeared in Settings → Media and in the Media Mode chip for Felipe's account and the `test` account, before any tab had an empty state and before the shows-or-movies reads were suppressed. #2936 is held by another loop and can land at any time, so the window was real.

Moving the drawable-set flip into #2954 fixed it **and** removed every sibling dependency among #2950–#2953: with Books unreachable, each of them reaches Books mode in tests directly. Verified in the code rather than assumed — `setMode` refuses a non-drawable mode (`mobile/stores/media-mode-store.ts:38`) but `useMediaModeStore.setState({ mode: "books" })` does not, and the existing tests already do exactly that (`mobile/__tests__/useHomeSections.test.tsx:122-124`).

## HARNESS BUG — `add-blocker` is broken, and every triager hits it

`triage/apply.ts:226-233` posts the dependency with `gh api -f issue_id=<n>`, which sends a **string**. GitHub's issue-dependencies endpoint requires an integer and answers HTTP 422: `Invalid property /issue_id: "6316130448" is not of type integer`. `-F` is the fix. It is deterministic, so exit 1's "re-run the same plan, the op ids make it idempotent" does **not** recover it — the second plan stopped at its first op with nothing written, and the sibling edges went in as prose instead (`set-section` on #2954's `## Blocked by`, which the frontier parses too). **Do not plan an `add-blocker` op until this is fixed.** Worth an issue on felipearos/ralph.

There is a second, smaller one: `triage-apply.ts` prints `refused, nothing written` and still **exits 0** on a validation refusal, where §4's table says 3. Caught here because the first dry run was read, not trusted to the exit code.

## Two other refusals worth knowing

- `decisions[]` takes **`rule`**, not `path` + `heading` (`triage/plan.ts:50-53`): one string, `path#Heading`, resolved at `origin/main` with `quote` checked verbatim.
- `CONTEXT.md`'s glossary entries are **bold runs, not markdown headings**, so `CONTEXT.md#Media Scope` is refused with "has no heading". Cite `CONTEXT.md` bare. And a cited rule must also be **named in a comment the same plan posts** — the citation and the comment are checked against each other.
