## READ THIS FIRST: `bun run typecheck` does not cover `mobile/`, and CI does

The root `typecheck` script is `tsc --noEmit` against the root tsconfig, which excludes `mobile/`. `mobile/package.json` has its own `typecheck`, and `.buildkite/pipeline.yml:239` runs `scripts/ci-run-if-scope.sh mobile bun run --cwd mobile typecheck` on any mobile-scoped change. So on a mobile-only branch the project's stated four-command gate is **green while CI is red**.

**Rule for every mobile ticket: run `bun run --cwd mobile typecheck` AND `npx eslint .` from `mobile/` in addition to the root pair.** `jest.mocked()` is stricter than the `as jest.Mock` in the older prior-art files; expect to fix mocks it exposes.

## What I changed after reading the diff

1. **`removeQueries({queryKey: ["review", id]})` → `type: "inactive"`.** Removing a query a mounted screen observes does not leave it empty: the observer rebuilds the query on its next render and fetches. The review screen deletes its own review and then pops, so an unfiltered removal would have had it refetch a deleted row, 404, and flash an error mid-pop. Verified in `query-core/build/modern/queryCache.js` — nothing listens for the `removed` event, so the refetch comes from `QueryObserver` rebuilding. `type: "inactive"` is a documented filter (`utils.js:39`).
2. **Rebuilt the Delete control's styling.** The executor gave it `flex-1 bg-danger` — equal visual weight to Save, and the only solid `bg-danger` in the whole app. Now an icon + `text-danger` on the left, Save keeps `flex-1`, matching the web dialog and the app's existing destructive vocabulary.

## The review axes earned their keep three times over

Three rounds, each finding something the previous one could not have:

1. **Round 1 (standards)**: the same Media Scope builder written three times, one per surface, with the narrowing guard duplicated in inverted form. Extracted. Also: the sheet derived its delete scope from the live `logScope` picker rather than from the log being edited — unreachable today (the selector is hidden in edit mode) but #1065 story 15 plans to show it.
2. **Round 2 (standards)**: my extraction's doc comment gave a **confidently wrong reason** — it said `mediaScopeSchema` rejects an explicit `null`. It is `.nullable().optional()` (`packages/shared/src/schemas.ts:105-110`); `logShowSchema` is the strict one, and this scope never reaches it. I had inherited that claim from `mediaScopeFields`' own comment and propagated it by copying. Also: the name `toMediaScope` **already exists** in `src/server/queries/mediaAction-write.ts` — same domain, object argument, normalizing the opposite way to `null`. And four positional args is a Data Clump: `toMediaScope("tv", 1396, 2, 5)` transposes silently.
3. **Round 2 (spec)**: the mobile typecheck failure above.
4. **Round 3 (standards)**: the *neighbouring* `mediaScopeFields` comment still carried the wrong claim I had just fixed ten lines up — two comments contradicting each other in one file.

**Lesson: a comment that states a confident reason is a claim, and a reviewer can falsify it.** Mine was folklore copied from a neighbour. Before writing "because schema X rejects Y", open schema X. And when you fix such a claim, grep the file for the same sentence — the neighbour it came from is still wrong.
