## What the spec review caught — five findings, all upheld, all now in the children

1. **P1 — B could have gone green with production still serving the pages.** The proxy matcher (`proxy.ts:427-428`) must be a literal, and `/<username>/…` reaches the proxy only on local or Tailscale hosts (`:430-433`). So `isDisabledPath("/alice/books") === true` plus a test on that helper satisfied criteria 1-4 while a production request rendered the page. B now requires the assertion to be on the **route's own answer**, and requires the matcher change when that route is taken.
2. **P2 — mocking `isMediaModeEnabled` cannot flip a derived gate.** `enabledMediaTypes()` (`:279-281`), `DISABLED_SUBDOMAIN_TARGETS` (`:421`), `DISABLED_PATH_BASES` (`:430`) and `isDisabledPath` (`:435-437`) are computed inside `media-types.ts` from `ENABLED_SUBDOMAIN_TARGETS` at module load. The parent's "flip the constant in a test" pointed at `search/route.test.ts:90-101`, which moves none of them. Both children now name `vi.resetModules()` + `vi.doMock("~/lib/media-types", …)` (`api/v1/books/[id]/route.test.ts:263-278`) for a derived gate. **This bites the obvious reviews-page fix**, which would copy `inArray(review.media_type, enabledMediaTypes())` from `diary.ts:81`.
3. **P2 — the overview has three more sections taking `mediaMode`** that the parent never named: `ProfileStatsSection` (`(profile)/page.tsx:197`, book shelf counts linking to `/<username>/books`), `WatchlistSection` (`:213`, want-to-read books with titles and covers) and `ProfileListsSection` (`:222`). A per-section fix passed the parent's criterion 2 with the watchlist sidebar still showing a book. A's seed now includes a `wantlist` book.
4. **P2 — `generateMetadata` leaks the book title** on all six `book/[slug]` pages (`activity/page.tsx:31`; `:34` in `diary`, `lists`, `reviews`; `generateBookReviewMetadata` for `(review)` and `r/[reviewNumber]`). A gate in `BookUserPageLayout` or after the fetches leaves the title in `<title>` and still calls Hardcover. B has its own criterion for it.
5. **P3 — "fixing the mode resolution itself" does not finish the reviews page.** `reviews/page.tsx:52` uses `getSubdomainMediaMode` + `parseMediaFilter(media)`; with no subdomain, `?media=books` and the default `"all"` are not mode resolution at all.
