## What the change does

`GET /api/v1/books/authors/<id>` takes optional, combinable `sort`
(`popularity|newest|oldest|az`), `genre` and `decade` from the shared Book Browse
Catalog, validated before any provider call and applied by the provider across
the whole bibliography, combinable with `role`. `getAuthorBooksPage` gained a
`filters` argument; its two static GraphQL strings became one builder over the
existing `BOOK_SHELF_ORDER` table and `pushBookFilters`. With no sort and no
filter the query and variables are byte-identical to before.

Files: `src/lib/hardcover.ts`, `src/app/api/v1/books/authors/[id]/route.ts`,
`packages/shared/src/book-author.ts` (doc only), both test files, `CONTEXT.md`.

## Key decisions

- `sort=rating` is refused although the catalog names it: the issue lists four sorts, and Browse's rating order needs its `ratings_count >= 25` floor, which a bibliography has none of.
- No current-year ceiling on `newest` (unlike Browse's popular grid), so an announced edition can lead the page. Deliberate.
- `roles` and their counts stay bibliography-wide; filters narrow `books` only.
- Dropped standards P3s: extracting the third copy of `singleParam` into `api-utils` (two routes this ticket does not own) and reshaping `getAuthorBooksPage` into an options object (other callers).
- Dropped spec suggestion: a full-text comparison of the unfiltered query against the base query — whitespace churn for no extra guarantee.
