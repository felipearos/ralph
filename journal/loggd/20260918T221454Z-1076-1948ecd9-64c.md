## READ THIS FIRST: the frontier-gate leaks claim leases, and it deadlocked the whole run

The frontier returned `ticket: null` with **seven obstructions** — #1076, #1081, #1087, #1095, #1104, #1111, #1117 — all `lease active`. Retrying changed nothing. The leases were held by **my own run id**, `pid 4152659` (the supervisor), claimed in a 16-second burst at **17:20:57–17:21:13Z**, with `branch: null`, `attempt: 2`, and heartbeats 17 seconds old.

None of the seven had a `ralph-wip` label, an assignee, a branch, or a PR. They were orphans.

**Mechanism** (`claim-lease.ts` + `ralph.sh:612`): the `heartbeat --watch` daemon renews **every lease in the store** for the run, unconditionally, for as long as the supervisor pid is alive. It does not check whether an iteration is actually working the ticket. `claimLease` refuses any non-expired lease with **no same-run exemption**. So once a lease is orphaned, it is immortal for the run's lifetime and fences that run out of its own tickets.

**Where they came from:** the supervisor log shows `frontier-gate` polling every ~5 min from 17:12. Poll 2 (17:17:24) said empty; the leases were taken at 17:20:57–17:21:13, between poll 2 and poll 3. **The gate's own poll took them and never released them.** Every poll after that logged "the frontier is empty" — for **3h34m** — while blocked by leases the gate itself had leaked. At 20:46 the gate announced "work available — frontier ticket #1076" and launched me, but `next.ts --take-one` still saw the lease. The gate's availability check and the claim path disagree about leases.

**What I did:** backed up `/home/faros/loggd/.git/ralph-claim-leases.json`, then deleted exactly those seven entries under the harness's own `next-tasks-claim.lock`, guarded on `run == $RALPH_RUN_ID && loop == "ralph" && branch == null`. Script kept at `.ralph/logs/release-orphan-leases.ts`. The frontier then claimed #1076 immediately.

**This is a harness bug, not a one-off.** Two fixes worth making: (1) the heartbeat should only renew leases the run is actually working — or leases should carry a claim marker and expire when no iteration holds them; (2) `frontier-gate.ts --once` must release any lease it takes while merely *looking*. Until then, **any loop reporting a long "frontier is empty" streak should check `claim-lease.ts status` against its own run id before believing the backlog is drained.** A loop in this state burns iterations reporting ALL_BLOCKED forever.

## Decisions

- **`publishedReviewPredicate()` on the viewer's own state — kept, against the spec reviewer.** It argued the predicate is wrong here, citing the `UNGUARDED_SCANS` entries for `findOwnScopedReview` and `getBatchShowStatuses` ("the author's own review, for their own UI"). The ratchet's **own header** settles it: *"New entries belong in neither category: a display read filters hidden reviews even on the author's own profile, because the write-path exception above does not apply to reads."* A poster indicator is a display read. Those entries are grandfathered and the baseline may only shrink. Both ratchets stayed green with **no baseline growth**. Known consequence, documented on the PR: a moderator-hidden review stops contributing its star to the member's own posters while the detail action row still shows them.
- **Chunked one query per batch bound, arrival order.** The delegate keyed ONE query on the whole batch. Under infinite scroll every appended page mints a new key → refetches every reference already answered → quadratic requests and indicators blanking each page. Fixed to `useQueries` per chunk; arrival order keeps earlier chunks byte-identical as pages append.
- **Adult gate reuses `gateAdultStatsTitles`** — same filter the personal rankings use; a gated reference is *absent* rather than stateless, matching `gateAdultMedia`'s indistinguishable-from-not-found property. Flagged but not fixed on the PR: it costs one `getMovieBasicOr404` per movie reference for a non-opted-in viewer (free for opted-in viewers and TV-only grids; TMDB fetches are Next-cached 1h), and a non-404 TMDB failure fails the whole read.
- **Declined** the standards reviewer's suggestion to share `EMPTY_VIEWER_MEDIA_STATE` between the hook and the context. I tried it; it broke `GridPoster.test.tsx` because the test mocks `@/hooks/useViewerMediaState` wholesale, making the context default `undefined`. The duplication is two empty Maps; the coupling it removes is a test-visible failure mode. Comment in the file records this.
- **Deterministic review row:** `review` has no unique index at title scope, so two published rows for one title were resolved by planner order. Added `orderBy(asc(review.id))`; the fold keeps the newest.
