## What shipped

`src/app/show/[id]/ShowContent.*` now imports its icons statically instead of
through `require()`, and a new ESLint rule in `eslint-rules/` bans `require()`
in client components so the pattern cannot come back. Supporting changes:
`eslint.config.mjs`, `vitest.config.ts`, `scripts/affected-scopes.*`,
`package.json`.

**700.6→545.9 KB gzip (−22.1%)**. Posted on the PR at 13:03 UTC.

## Key decisions

- **`delegate.sh` was used** for the implement phase; this session (and the
  several resume sessions before it) owned the brief, the diff review and the
  gates.
- **Head-mismatch round, resolved without a force-push.** CI wait round 1 came
  back head-mismatch: the PR head was `29daea3d2` while this loop had pushed
  `1412539b9`. The supervisor's framing ("was the push made?") was inverted —
  `1412539b9` was already in the PR and `29daea3d2` sat one commit on top of
  it: `fix(mobile): a stale end-reached joins the Diary's next page…`
  (`mobile/components/DiaryTab.tsx` + test) authored by @felipearosr, fixing
  the `diary-tab-virtualized` flake from main build 2645. This branch was the
  only ref containing it, so forcing back would have destroyed the only copy.
  The detached HEAD was fast-forwarded to match instead and the situation was
  flagged on the PR. That mobile commit rode in with the squash merge.
  **Caveat:** the two local review axes read the `1412539b9` diff, not the
  mobile commit; that commit is covered only by its own test and CI.
- **Round 2 red was a contention flake, given the one free re-run.** Build 2650
  failed one job of eight — `Playwright E2E (hermetic local stack)`, one test:
  `[chromium-authenticated] e2e/feed-controls.spec.ts:82:3 … category choices
  persist and reset restores the feed — Timed out after 30000ms waiting for
  … getByRole('switch', { name: 'Ratings' }). React had not hydrated the
  element.` Judged a flake on three grounds: the branch touches no feed code;
  `e2e/feed-controls.spec.ts` has a documented CPU-contention history (harness
  journal `20260916T053001Z-994-…`, #994 / PR #1003, same failure class); and
  the host was saturated (load 15.49 / 25.18 / 24.47 with an active
  buildkite-agent job). No Buildkite API token is available to this loop, so
  the re-run was triggered with an **empty commit** `e4d9face2` whose message
  records the reasoning — tree identical to `29daea3d2`. Round 3 (build 2654)
  came back green, confirming the judgement.
- **Earlier rounds 1–6 of CI were host saturation, not the diff**: build 2617's
  e2e died in setup (Supabase stack `HTTP 502 ×239`); build 2625 was red only
  on `src/server/imports/library-merge.integration.test.ts` "Test timed out in
  5000ms", a file this branch does not touch and a known host-load flake (the
  #1630 journal flags the same test).

`bun run test` / `typecheck` / `build` were **not** re-run on `29daea3d2` or

full local gate did pass on `1412539b9`, and the two later commits added no
web code (one mobile fix with its own test, one empty commit).
