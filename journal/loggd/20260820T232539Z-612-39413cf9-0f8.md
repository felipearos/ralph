# 2026-08-20 — #612 A Vercel Ignored Build Step over the existing scope detector

**Outcome: merged.** PR #616, squash-merged after one freshness round, issue auto-closed, both labelled `ralph-done`.

**What the ticket was.** Vercel had no Ignored Build Step and never has had one —
`commandForIgnoringBuildStep` was `null` across all 2,546 deployments this project
has made. This is the third adapter over the one scope detector, alongside
`buildkite-affected-scopes.sh` and `github-affected-scopes.sh`. Two new files
(`scripts/vercel-ignored-build-step.sh`, its test) plus two registrations and a
doc section. **It landed INERT**: the Vercel project setting is still unset, on
purpose, exactly as the detector itself landed inert in #442.

**Key decisions.**

- *`--decision-fields`, never `node ci-scope-guard.mjs web`.* The scope mode
  applies `buildOverrideReason`, which reads `BUILDKITE_*` — unset on a Vercel
  builder, and an unset `BUILDKITE_SOURCE` means "started by hand, run
  everything". Asked there it would answer BUILD on every deployment forever and
  the adapter would be silently inert while looking installed. The asymmetry is
  already documented in `ci-scope-guard.mjs`; the call site points at it.
- *The unshallow is gated on the clone being SHALLOW, not on the previous SHA
  being absent.* The first draft gated it on absence, which is a different
  question: a shallow clone can hold `previous` at its graft boundary and still
  have no merge base `previous...HEAD` can find. Standards review caught it; the
  sibling `ci-scope-decision.sh` had the condition right all along.
- *No refspec on the `--unshallow`, where the sibling passes one.* It cannot: this
  adapter holds a SHA and not a branch name, so there is nothing to spell.
  `--unshallow` deepens the clone's own configured refspec, which on Vercel's
  single-branch clone is the branch being deployed. Said so in the comment,
  because the divergence from the cited prior art otherwise reads as an omission.
- *Every build decision says `building` — including the ones reached by FAILING
  to decide.* The rollout step is "read the decisions in a few build logs", and
  an operator counting `building`/`skipping` would otherwise miss all three error
  branches. Every line is prefixed `vercel-ignored-build-step:` for the same
  reason: a Vercel build log is one undifferentiated stream.
- *The executable bit is load-bearing and both review axes caught it missing.* A
  bare dashboard path the builder cannot execute exits **126** — which means
  BUILD, silently, forever. That is the same silent-inertness failure the ticket
  spends three paragraphs on, and it is the one an operator can introduce from
  the dashboard alone. The doc now states the exact string to paste
  (`bash scripts/vercel-ignored-build-step.sh`) and why it is spelled with `bash`.
