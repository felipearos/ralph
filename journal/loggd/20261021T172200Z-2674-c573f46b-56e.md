## What the split decided, beyond repackaging

- **The `decideOnboardingStep` signature in #2656/#2674 is indicative, not binding.** `(state, hasUsername, submission, seenProgress)` carries neither `client.usernameStep` (gate 1, `:550`) nor `enforceSeenMinimum` (gate 4, `:626-627`). #2721 says the parameter list carries what the four gates read, and keeps the seen count lazy. **Stated as a departure from the spec's text in the triage comment** — a coder who follows the literal signature cannot implement two of the four gates.
- **"No gate remains inline" means the four.** The skip gate (`:616-619`) and `answerUsernameStep`'s refusals (`:385-393`) stay. Their order relative to gate 4 is observable behaviour and #2721 pins it with a criterion — see below.
- **The boolean flag opens a hole.** `src/app/api/import/jobs/route.ts:153` compares the flag to `user.id`, and that comparison is why a member who has finished setup, opening someone else's `?onboarding=` URL, is not swept back into setup. The proxy does NOT cover it: `isOnboardingImportHandoff` (`src/lib/supabase/middleware.ts:28-34`) only acts inside the first-run gate. #2722 replaces the comparison with "is this member still in setup", in `advanceImportSetupStep` so both transports get it from one place.

## Findings from the two review passes — what the next iteration should reuse

Pass 1 found eight, pass 2 found three more plus a wrong citation. The four that are worth carrying forward as patterns:

1. **A criterion pinned to the wrong test file passes vacuously.** Both import route tests mock `~/server/imports/onboarding-step` wholesale (`import/jobs/route.test.ts:51`, `v1/imports/jobs/route.test.ts:86`), so a "no `onboarding.step` audit is written" criterion pinned there can never fail — the audit lives inside the mock. It moved to `src/server/imports/onboarding-step.test.ts`. **Check what a test file mocks before pinning a criterion to it.**
2. **An ordering regression needs its own case.** The only existing test that hits the skip gate on the seen path (`onboarding.pglite.test.ts:118-123`) goes through `submitImportedSeenStep` with `enforceSeenMinimum: false`, so gate 4 never runs there and it stays green through exactly the regression. Pinned instead to `onboarding.username-gate.test.ts`, which feeds the seen count through the mocked `groupBy` (`:38-45`).
3. **A split can create a cross-group dependency through a deletion.** #2722 needs to read "is setup finished"; the cheap existing reader is `needsOnboarding`, which #2721 deletes in another group. Resolved by having #2722 read `onboarding_completed_at` in its own module rather than depending on, or re-adding to, #2721's file.
4. **A "grep finds nothing" criterion needs the false positives checked first.** `e2e/pool-restore-conformance.test.ts:81` carries the literal `/api/import/csv` inside a comment about that very string, so the criterion was reworded to name imports, fetches and route declarations.
