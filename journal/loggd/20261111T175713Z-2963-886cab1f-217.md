## What landed

The Activity read left books out only because the caller asked it to: the app
sent `exclude=follows,books` and `fetchBookKeys` ran whenever a request did not
name books, so the web — which sends no `exclude` — got a member's shelved
books. `readMemberActivityPage` now takes the DB media types of the Media Modes
the viewer may browse, and five sources narrow by it: `fetchBookKeys` in the
dispatch block, plus `fetchReviewKeys` (its `["tv","movie"]` hardcode replaced),
`fetchLikeKeys`, `fetchIncomingLikeKeys` and `fetchIncomingCommentKeys` in their
own condition lists. The argument is optional and **fails closed to the launch
configuration**, so the three web callers are correct passing nothing;
`GET /api/v1/activity` passes `viewerMediaTypes(browsableTargets)`. A request's
`exclude` can still narrow what a caller receives; it can never widen it.

Eight files, six commits `ef7b93075..ae093a5dd`. Production is
`src/server/queries/activity.ts` and `src/app/api/v1/activity/route.ts` only.

## Key decisions

- **The launch default resolves through the shared resolver, not a module
  constant.** `ENABLED_ONLY` in `media-mode-scope.ts` is computed at that
  module's load, so a per-request call does *not* make a stubbed launch constant
  take effect. An earlier comment claimed it did; two review axes caught it and
  `ae093a5dd` fixed the comment.
- **`fetchWatchlistKeys` keeps its `["tv","movie"]`.** `watchStatus` never holds
  a book — a wantlisted book is a `readStatus` row `fetchBookKeys` reads — and
  criterion 7's four sources do not include the watchlist.
- **The correctness axis's P2 was verified and deliberately not fixed.** A book
  `review`/`liked_review` row reaching a preview holder renders "Title
  unavailable", because `fetchMediaInfo` is keyed on `(tmdb_id, media_type)` and
  never sees `external_id` while book rows carry `tmdb_id: 0`. Criterion 4
  *requires* the row reach a preview holder, and the ticket says criterion 2
  removes the row rather than fixing hydration. Named as a follow-up in the PR
  body with `hydrateBookReviews` (`review-hydration.ts:142`) as the pattern.
- **tria point 15's premise was wrong:** a book review's `tmdb_id` is the `0`
  sentinel, not a Hardcover id, so the pre-fix path 404'd into "Title
  unavailable" rather than showing a wrong series.
- `src/server/queries/profile-reviews.ts` left alone on purpose (opposite
  default, owned by #2966).
