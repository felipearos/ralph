**What shipped.** The contract step of #1544. Three things, in one diff of 5 files, +318/-186:

1. `defaultQueryRetry` (`mobile/lib/query-client.ts`) stops comparing an error's *message* to
   `"Unauthorized"`. A known `ApiError` kind decides through `isRetryableApiError`; anything else is
   a plain error retried up to 3 times. Behaviour change pinned by a test: a bare
   `new Error("Unauthorized")` is now retried.
2. `src/app/api/v1/mobile-api-error-allowlist.ts` is **deleted**, and with it every allowlist and
   base-branch mechanism in the conformance test (`parseMobileEnvelopeCallers`, `allowlistGrowth`,
   the `~/test/ratchet-base` import). `MOBILE_ENVELOPE_CALLERS` held exactly one entry — the query
   client's legacy string branch — so removing that branch left nothing to list. The ratchet is now
   absolute: no mobile production file can opt out of any rule.
3. A fourth rule, `unforwarded-signal`: a TanStack `queryFn` that reaches the typed call must
   forward the query context's `AbortSignal`.

**Key decisions.**

- **The envelope's additive failure fields stay**, even though the ticket's literal condition for
  deleting them is met (nothing outside the transport and `api-call.ts` reads them). They are not a
  second way to read a failure — they are the *only* channel by which the transport tells the call
  what went wrong: `kind` for `network` and `account-changed` cannot be rebuilt from `status`
  (those failures have none), `cause` decides whether the message is replaced with plain copy, and
  `retryAfterSeconds` feeds the rate-limit message and the Import Job poll delay. Deleting them
  would undo #1544 itself. Argued in full in the PR body.
- **Finding the unforwarded-signal shape means reading query options wherever they are *written*,
  not where a query *runs*.** Both review axes independently caught the same real defect: the rule
  as first written missed the List detail `queryFn`, the very shape the ticket names as its reason
  for existing — it lives in a bare options object that another file spreads into
  `useInfiniteQuery`, so no query call is in sight. It also skipped the factories (`apiQueryFn`,
  `titleQueryFn`) that supply most mobile queryFn bodies. The fix reads a `queryFn` in any object
  literal carrying a `queryKey`, follows the same-file factory, and accepts all three member forms
  (`queryFn: fn`, shorthand, method). Because both rules share the extracted traversal,
  `raw-query-fn` gained the same reach.
- **A written-out options object must carry a signal**: `{}` and `{ signal: undefined }` say as
  little as a missing argument. Only a value the AST cannot see into (identifier, call, spread) is
  taken on trust, stated in the code as the deliberate blind spot it is.
- **One guard not in the ticket:** `scans the mobile production tree`. With no allowlist the
  contract is proved by an *empty* violation list, so a broken `walk` would read exactly like a
  clean branch. (The general lesson: assert the effect, not the mechanism.)
- **Declined as pre-existing and out of scope:** `inspectUnauthorized` not matching
  `.includes("Unauthorized")` (no such site exists); `sameFileFunctions` keying by bare name so two
  same-named functions collapse (documented at the map rather than changed — it bit my own first
  fixture, which is why the shorthand and method fixtures are two separate sources); the stale
  `code` doc comment in `api-client.ts`, left for #1521.
- Every rule was **mutation-tested against a real production file** (planted, flagged, restored),
  including the two shapes the reviews surfaced.
