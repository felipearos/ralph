## How to read a Buildkite job without the API token (this is the useful part)

The agent's build path is on the **host**: `BUILDKITE_BUILD_PATH` is
`/data/buildkite/builds/<agent>/felipe-aros/loggd`, readable without sudo
(git refuses "dubious ownership", but `ls -lat --time-style=+%H:%M:%S` and
plain file reads work). Combine three things:

- `docker logs --since 20m buildkite-agent` gives per-agent job start/finish
  and exit status (strip colour with `sed 's/\x1b\[[0-9;]*m//g'`).
- The build dir's mtimes are **local time (UTC-3 now)**; the agent log is UTC.
  The newest file tells you the last command that ran: here
  `tsconfig.tsbuildinfo` at 02:51:50 = typecheck finished, and `.git/FETCH_HEAD`
  was a zero-byte file from 02:51 = the very next pipeline command,
  `git fetch --depth=1 origin +refs/heads/main:…`, died. Exit 128 is git's.
- Durations distinguish jobs when the log won't: in green #1229 quality ran
  ~6m and e2e ~7m; a job matching one of those and passing is that step.

`git fetch --dry-run` of the same refspec from inside the agent container
succeeded minutes later and `ssh -T git@github.com` authenticated, so it was
transient. Exit 128 with a pass on the sibling job is the retry-once shape;
exit 1 is not.
