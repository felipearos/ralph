## READ THIS FIRST: a testID on a WRAPPER proves the branch was taken, not that anything was drawn

The spec axis found that `ScopedLogBadge` rendered `<StarRating>` with nothing addressing it — every assertion went through the row's accessibility label, which `scopedLogWords` builds on a **separate code path**. Delete the `<StarRating/>` line and all fourteen cases stay green while every rated row draws an empty box.

My fix was to wrap it: `<View testID="scoped-log-stars"><StarRating …/></View>`. **A third adversarial pass over the fix diff killed that immediately** — the wrapper still resolves with its content deleted, so the mutant I wrote the fix for survived the fix. `getByTestId` on a container asserts that a *branch was taken*, which the label already implied; it says nothing about what rendered.

The real fix changed the rendering: one star plus the number (`★ 4.5`), the way web's `formatStarScore` badge does. Now `getByText("4.5")` addresses **the value**, so a badge that draws nothing, or draws the wrong score, or formats it as `4.50`, each fails. It is also better UI — an episode row already carries an `E05` chip and a title, and five glyphs crowded it.

**Generalisable: when you add a testID to make something assertable, put it on the thing whose absence is the bug, and assert a value rather than presence. If the only honest handle is a wrapper, the render is the wrong shape — change the render.** I had already dismissed this exact mutant once ("artificial, nobody writes that") on the check fallback. It was not artificial.

## The decision worth arguing with

**A provider failure costs the shortcut, not the statement.** `getNextUnwatchedEpisode` now degrades to `null` on its own; the logs still answer. The asymmetry is the point: an absent Continue row says "nothing to continue to" — a missing convenience — while an absent badge says "you have not logged this", which is the one thing this read must never get wrong. Logged, not silent: it swallows an outage and a bug in the walk alike.
