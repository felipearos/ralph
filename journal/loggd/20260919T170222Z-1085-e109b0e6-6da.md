## READ THIS FIRST: three of the four review rounds found the SAME defect, one layer deeper each time

The shape of this ticket is "the sheet's form, mirrored into storage". Every
round of review found the mirror out of step somewhere new, and each fix
exposed the next one:

1. **Two rules for what a draft is.** The sheet asked "does the form still say
   what it said when it opened"; the storage hook asked, absolutely, "is there
   text, a rating, a tag or a flag". A member who changed only the watched date
   had the change written and then deleted. Fix: the absolute test is gone,
   the seed comparison is the only rule.
2. **The read was keyed on the storage key.** The draft is per Media
   Reference, so a sheet opened on an episode and one opened on the show share
   a key — reopening at another scope reused the previous opening's answer,
   reported "no draft" over one just written, and cleared it. Fix: the read is
   tagged `${opening}:${key}`, with the sheet counting its openings.
3. **The same thing one layer down.** The effect that flushes the parked,
   not-yet-debounced write was keyed on the key too, so it never ran on a
   reopen: the text died in `parked` instead of in storage. Fix: key that
   effect on the opening as well — React runs all destroys before any creates,
   so the flush lands before the new opening's read — and route the read
   through the same promise queue as the writes so it is ordered *behind* them
   rather than beside them.

If you touch this hook, the invariant to hold is: **one read per opening, and
every boundary flushes the parked write**. A key is not an opening.

## What the tests learned to do

- The first version of the background-flush test **passed with the background
  flush removed**: the round-trip went through a reopen, and the reopen's own
  cleanup flushed the write anyway. A "did it survive?" assertion cannot see
  *when* a write happened. The two timing tests now read the write's own
  arguments (`AsyncStorage.setItem` call values, not keys) so they fail if the
  flush or the debounce stops firing.
- Nine guards were mutation-tested; every one turns a test red when reverted.
  The spec reviewer independently mutation-tested the last two.

## React Native Testing Library traps this seam has

- `act(() => handler("background"))` — a **non-async** `act` around a call that
  kicks off promise work — poisons the renderer: every later state update in
  that test is silently deferred and never flushed, so a `waitFor` on the next
  screen change times out with no clue. Use `await act(async () => …)`. Two
  hours went into this one.
- `fireEvent.press` on a `Pressable` **host view found by label** does not
  dispatch when it is inside a `<Modal>` (the sheet's own Close control, which
  has only an icon to aim at). Pressing a `Text` child works. Drive the close
  through the context instead — or, as this suite ended up doing, avoid closing.
- After the modal unmounts, `screen` queries keep answering from the old tree
  even though the provider has re-rendered. `cleanup()` mid-test breaks the
  next `render()` ("waitFor was aborted by cleanup"). Modelling an app restart
  as a **second independent `render()`** works: `screen` scopes to the newest
  tree.
