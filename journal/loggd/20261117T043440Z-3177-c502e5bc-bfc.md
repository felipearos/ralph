**What shipped.** `GET /api/v1/books/authors/<id>` now answers `roles` (key,
label, count per Author Role, authorship first) on every page, and accepts
`role=<key>` to narrow the page to one role, with no role line on those cards.
The roles come from a new lightweight `AuthorCredits` provider call keyed on the
Author alone; the unnarrowed page query is byte-unchanged from main's.

**Key decisions.**
- Two-stage unknown-role validation — malformed key → 400 with no provider call;
  well-formed but not held by this Author → 400 after the cached credits call —
  because book roles are open-ended provider labels. Stated in the PR body as a
  reading of AC3 rather than passed silently.
- A blank `role=` is the unnarrowed read, following the `optionalTrimmedParam`
  precedent.
- Role counts come from the Author's first 1,000 books in readers order, the
  merged book shelf's (#3204) cap.
- Without a role the two provider calls go out together and a credits failure
  only empties `roles`, so the page survives it. With a role the credits call is
  fatal.
- A label the slug rule empties, or one too long to be a key, gets a stable
  opaque `role-<id>` key, so non-Latin labels are not folded into authorship.
- Blank authorship labels are kept verbatim in `labelsByKey`, so the count and
  the authorship page agree.
- A key the read gives out is a key it accepts (second-pass review fix).
- Kept and documented, not fixed: a rate-limited credits call still delays the
  unnarrowed response; credits and page calls cache separately, so a renamed
  label can leave a count over an empty page for up to an hour.
