## The four amendments (comment is the operative spec; body unchanged)

#2677 is `ready-for-agent`, so the Guardrails forbid rewriting its
`## Acceptance criteria` in place; the amendment is prose in the triage comment,
and the comment says so in its first paragraph.

1. **"With the web creation hook's interface" is a shape, not a copy.** The web
   hook (`src/app/list/new/_components/useListCreateSession.ts`) types its
   argument out of `~/server/db/schema` (`:157-166`) and publishes through the
   `createList` **Server Action** (`:438`). `mobile/CLAUDE.md:11` — "`~/` is the
   web-only alias" — makes both impossible, so the amendment binds the mobile
   vocabulary (`CreatableListType` from `@/hooks/useCreateList:8`,
   `LIST_VISIBILITIES` from `@loggd/shared/constants`), the publish path
   (`useCreateList` + `useIdempotencyKey`, `Promise<PublishOutcome>` via
   `mutateAsync`, no `auth` case, `created` carrying mobile's `CreatedList`
   fields), a **required minimum** list of returned keys, and three deliberate
   name departures (`selectType`, `invited` + the invitation handlers, no
   `isWriting`). Navigation and toasts stay in the screen.
2. **Criterion 1's "tests mirroring the web test file" cannot satisfy criterion
   4.** The web test file has no carried-title merge and no type lock — on web
   those live in `NewListForm.tsx:128-145` and `:177-192`, not in the hook. The
   amendment names three test sources: the web file's 11 cases (two ported under
   an adapted name, two marked N/A with the reason), six hook-level ports of
   `mobile/__tests__/list-draft.test.tsx` cases, and one type-lock case whose
   cover-pin half is a **new** assertion. The screen suites stay green and are
   not moved.
3. **Criterion 3 was not satisfiable: there is no shared maximum to read.**
   `packages/shared/src/schemas.ts:293` is an inline `.max(500)` and `:294`
   repeats it as `.max(499)`. Decided: export `CREATE_LIST_MAX_ITEMS = 500` from
   `packages/shared/src/constants.ts` (not `schemas.ts`, so mobile need not
   import the whole schemas module — reviewer's suggestion, taken), use it at
   `:293`/`:294`, read it in the hook from `@loggd/shared/constants`. No
   `createListSchema.shape.items` introspection. The value stays 500: the edit
   schema's own comment calls it "creation's 500".
4. **Criterion 2's "`useState` count is layout-only" was not checkable.** The
   amendment names the exact seven that stay (`:179`, `:243`, `:317`, `:318`,
   `:319`, `:326`, `:332`) and says everything else moves, including the
   `useMediaModeResetState` media mode at `:255`.

## Two real seams the amendments had to invent, not just restate

Both came out of the review, and both are behaviour, not style:

- **`query` is cleared by code that moves.** `selectType` clears it at `:388`
  *only inside the apply branch*, after the confirm is accepted, and `addItem`
  clears it at `:442`. A screen-side wrapper clearing `query` before calling the
  hook would clear it when the member **cancels** the type change. So the hook's
  `selectType` must report whether it applied and the screen clears on that
  signal — pinned by two tests, one at the hook and one in
  `create-list.test.tsx` beside the existing type-lock case at `:333`.
- **The once-read route-param snapshot.** `preselected` (`:211`) and
  `entryOrigin` (`:215`) are `useState` snapshots whose comment says
  "re-reading the params would put a removed title back". Neither is in the
  table of seven, so the guarantee had to move: the screen now calls
  `readPreselection(params)` every render with no `useState` and validates the
  audience itself (`isListAudience`, `:266-270`, "A URL parameter is
  untrusted"), and the **hook** snapshots on mount. A hook test pins it.
