## READ THIS FIRST: the review axes earned their keep, and a direct-render test cannot catch a lifetime bug

Three defects shipped into my branch and were caught by review, not by tests:

1. **The list picker was dead from a poster.** `MediaActionSheet.handleAddToList` does `onClose(); setListPickerOpen(true)`, and it owns `AddToListSheet` itself precisely so the picker survives the sheet closing. But the poster mounted the sheet as `{sheetOpen ? <Sheet visible/> : null}`, so `onClose` unmounted the subtree and took `listPickerOpen` with it.
2. **A failed one-tap action never alerted.** Same cause: `closeAfterAction` unmounts the sheet on the tap, and React Query does not run a per-call `mutate` callback once its observer unmounts. The rollback survived (it lives in `useMutation`'s own `onError`); the `Alert` did not.
3. **The poster indicator did not move if the action-state read had not landed.** The optimistic viewer write was gated on `if (previous)` — a projection off the cached `MediaActionState`. A poster's sheet only STARTS that read when it opens, so long-press-then-tap had nothing to project from. That is the acceptance criterion itself.

**The lesson for the next iteration is about test shape, not about these three bugs.** Every one of them is invisible to a test that renders the sheet directly, because such a test never unmounts anything and always seeds its own cache. I added `mobile/__tests__/poster-long-press-quick-actions.test.tsx`, which drives a **real `GridPoster`** with a real sheet and mocks only leaves; with the mount reverted, two of its four cases fail. **When a component's bug is about its LIFETIME or about what is NOT in cache, the test has to own the mount and start empty.**

Fix 3 changed the design: each title-scope action now declares a `viewerPatch(variables) => Partial<ViewerMediaStateEntry>` instead of deriving a full entry from an action state that may not exist. Variables always exist; the server's reply still reconciles afterwards.

## Decisions

- **The server field is the one thing outside `mobile/`, and I kept it.** #1064's Out of Scope says "any web change beyond the new versioned route"; `/api/v1/media-actions` is the *mobile* API, and the alternative is a client guess that is wrong for every ended show. Flagged on the PR with an offer to move it behind a query parameter. Both spec passes called it scope creep; I disagreed in writing rather than silently.
- **The sheet stays mounted once a poster has opened it.** This is the fix for 1 and 2. Cost: one mounted sheet per ever-long-pressed cell, bounded by FlashList recycling. A reviewer wanted a reset path; I declined because the transient it must survive (an in-flight write, a nested picker) is exactly what a reset would race.
- **Haptics on the tap, not the reply** — matching `MediaActionRow`. A spec reviewer read story 15's "on a completed action" as requiring the reply. Declined and documented: the failure still alerts.
- **Season and episode cards are out**, filed as **#1134**. #1078 says "poster and card primitives" and #1064 story 18 wants Media Scope honoured there, but a Media Reference is title-scope by construction and #1076's indicators are title-only, so a season card's sheet would have no indicator to move. Stated on the PR rather than quietly skipped.
- **Renamed `PosterActionSheet` → `PosterMediaActionSheet`:** `CONTEXT.md`'s Quick Action entry carries `_Avoid_: … Poster Action …`. The standards reviewer caught it; the glossary really is binding and I had walked straight into it.
- **Rollback restores the one title's row, not the whole chunk**, so a concurrent write to a different title in the same chunk survives this one's failure.

## Gotchas for the next iteration

- **`render` from `@testing-library/react-native` must be `await`ed in `mobile/`.** An un-awaited `render` gives "`render` function has not been called" from `screen` — and worse, un-awaited `renderHook` calls corrupt *later* tests in the same file, which reads as eight unrelated regressions. Every existing test awaits it; copy that.
- **`onMutate` is async** (it awaits `cancelQueries`), so a cache assertion straight after `mutate` is a frame early. Use `await act(async () => …)` then `waitFor`.
- **Prettier is NOT a CI gate here.** A reviewer claimed a formatting failure would trip CI; `mobile/components/GridPoster.tsx` fails `prettier --check` on `origin/main` today. Verify such a claim against `main` before reformatting files the diff barely touches.
- **A new field on a shared response type breaks exact-shape assertions far away.** `watchTarget` broke six `toEqual` cases in `src/server/queries/mediaAction-write.integration.test.ts` and three mobile fixture builders. Grep for the type's other fixtures before assuming your own tests are the blast radius.
- **`MediaScope` differs across the boundary:** the server's requires explicit `seasonNumber`/`episodeNumber` (nullable), mobile's makes them optional. TS7 catches it; the mobile typecheck will not.
- **Buildkite was busy for most of this iteration** (the other three loops). I deferred typecheck/lint/build to two measured quiet windows (`docker top buildkite-agent` ≤ 6 bun/node/next procs) rather than the start/finish log counts, which mislead — a 40-minute window can clip a job's start and make starts==finishes look idle while a job is running.
- **Watch the commit command.** A malformed `git commit` in a compound line landed a commit literally titled `x`; caught and amended before pushing, but it would have reached `main` unnoticed.
