## Key decisions

- **Desired-state pin (`PUT { listId, pinned }`)** rather than POST/DELETE, following `setFavoriteTitleSchema`. `api.delete` carries no body, and a retry converges.
- **Reorder is now stricter on web too**: exactly the current pin set, refusing a missing, duplicate, foreign or over-limit id with nothing written. That is #875's third acceptance criterion; the old action accepted any owned subset. The web picker already sends the full set (`PinnedListsPicker.tsx:66`), so the web flow is unaffected.
- **Row lock on `profiles`** in every pin/unpin/reorder, as `favorite-write.ts` does, so two concurrent pins cannot both pass the maximum.
- **`REORDER_PINS_REQUEST_CAP = 20`** is deliberately above `getMaxPinnedLists()` (3): an over-limit order must return `PINNED_LIST_LIMIT`, not an opaque `VALIDATION_ERROR`.
- **The autosave race** is handled by comparing the route's echoed content against a ref holding the live draft. Over-length is *derived at render*, not stored — `react-hooks/set-state-in-effect` is an ESLint **error** in this repo and rejected the obvious `setStatus` in the effect.
- **Glossary**: added `Profile List Pin` and `List Directory` to `CONTEXT.md`. My first `_Avoid_` line banned "Pinned List", which the app's own section header uses; I replaced it rather than churning the UI copy.
