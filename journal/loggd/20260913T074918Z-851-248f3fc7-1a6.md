## Read this before #852 / #853

- **RNTL 14: `render` and `renderHook` are async.** Every un-awaited
  `render(...)` fails as "render function has not been called". And a test
  that renders twice in one `it` (with a manual `unmount()`) poisons every
  later test in the file — screen queries come back empty. One render per
  `it`.
- **Optimistic-state assertions need the refetch mock to agree.** After
  `onSettled` invalidates, the GET mock runs again; if it still returns the
  blank state the label reverts and the test reads as "rollback". Set
  `mockGet` to the post-write state before pressing (or
  `mockResolvedValueOnce` for the initial load).
- **`min-h-11` is 38.5pt on native** (rem = 14). Use `min-h-[44px]` for
  touch targets; arbitrary px is used elsewhere in `mobile/`.
- **A half-star picker for screen readers**: one `accessible` container
  with `accessibilityRole="adjustable"`, increment/decrement actions and
  `accessibilityValue`; the star `Pressable`s carry `accessibilityElementsHidden`
  + `importantForAccessibility="no-hide-descendants"`. Query them by
  `testID` with `{ includeHiddenElements: true }`.
- **The v1 watch-status response is `{ success, newStatus, isFollowing? }`**
  under `data` — a fixture without `data.success` makes every write reject
  while a call-count assertion still passes. The standards axis caught it.
- `showStatus` on the row is optional; a tv detail payload without
  `status` would write `caught_up` (and auto-follow) for an ended show.
  TMDB always sends it; #852's season/episode rows should pass it through.
- **Executor exit 4 on slice 2 was a hung Jest run**, not a bad diff: it
  wrote everything, then waited on a background test task past the 900s
  cap. Briefs should say "run Jest in the foreground with `--forceExit`".
