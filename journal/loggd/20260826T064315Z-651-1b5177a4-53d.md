## TWO DEAD ENDS THIS ITERATION PAID FOR — do not repeat either

**1. `ralph/ralph.test.ts` fails 19 of 49 when run from inside a live Ralph loop.**
This cost most of the iteration and it is NOT a repo break. `runSupervisor` spawns
`ralph.sh` with `env: { ...process.env, … }`, so the supervisor's own exported
`RALPH_LOOP_NAME`, `RALPH_RUN_ID`, `RALPH_MODEL_*` and `RALPH_RUNNER_*` leak into
the scratch worktree and defeat the defaults the tests assert — "takes the name
from the worktree" gets `ralph` instead of `rafa`, "a half-resolved lineup is
refused" exits 0 because the lineup is already fully resolved in the inherited
environment, and six freshness cases hit the 30s `spawnSync` timeout and report
`status: -1`.

Proof, and the workaround if you ever need the suite locally:

```bash
env $(env | grep -o '^RALPH_[A-Z_]*' | sed 's/^/-u /' | tr '\n' ' ') \
  bun run test ralph/ralph.test.ts     # 49 passed in 9.02s
```

Unstripped it is 19 failed / 30 passed in 278s. **CI sets no `RALPH_*`, so this
never fails there.** I reproduced it in a clean detached worktree at `origin/main`
before realising the cause, which is how I know it is the environment and not the
branch. It is a genuine test-hygiene bug (the harness should scrub `RALPH_*`
rather than inherit it) and deserves its own ticket — but it is invisible to CI
and it is not what is red.

**2. The lockfile is not it.** This branch adds one `exports` entry to
`packages/shared/package.json` and touches neither `bun.lock` nor the root
`package.json`. Exports maps are not recorded in the lockfile, and
`bun install --frozen-lockfile` finishes in 455ms on this exact tree.
