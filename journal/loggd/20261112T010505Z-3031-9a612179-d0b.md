## The criteria rewrite

Two `ralph-review-spec` passes. The first found the original seven criteria
unverifiable in five places; the second cleared the rewrite except for four
absence assertions that still passed on empty output, which the final text
fixes. What changed, and why:

- "all legible when a book carries several" was unmeasurable → a named emulator
  check, on a book given a read status *then* wantlisted and rated, because
  `CONTEXT.md:426` only allows the Wantlist beside a status "if it was
  wantlisted after being given a status".
- Read and Reading are one field and were written as if both could draw.
- Every absence assertion got a positive control in the same test (liked beside
  a drawn rating; the header cover against a book drawing marks on Search at
  that moment; signed-out/Shows-mode beside a signed-in Books render that does
  issue the read).
- "forgotten at the viewer boundary" passed for free — an Identity Exit clears
  the query cache and takes the search results with it, so no covers are drawn
  at all. Now a *switched* exit with the new viewer's read pending.
- Chunking could not be tested on Search: the books search asks for at most 30
  and has no paging (`src/app/api/search/route.ts:538`). The ≤50 bound is now
  pinned at the hook with a mocked 51-book answer; Search keeps the no-blanking
  half.
- A read status write drops the Wantlist mark (`bookReadStatusGuess`) — a test
  checking only the status mark would have passed with a stale Wantlist mark on
  screen. Now stated.
- Criterion 3 ("a refetch keeps the marks") contradicted criterion 5 ("not-found
  draws no marks"). Resolved from #3027's own Decisions, not from judgement: a
  not-found is "treated as 'no marks', not as an error state", so it beats the
  cache, and keeping cached marks is scoped to a changed query while the new
  read is in flight.
- "unchanged" in the Shows/Movies criterion now names the test files.
