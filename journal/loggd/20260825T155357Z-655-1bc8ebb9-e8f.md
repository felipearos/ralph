## The thing that cost this iteration 12 minutes: commit authorship

The first CI run failed **Vercel** with "Git author second-account must have access
to the project on Vercel". Buildkite was green; only Vercel cared.

Cause: I authored the commits with `-c user.email=other@example.com`, taken
from the session's account email, when this checkout's configured git identity
is `owner@example.com`. Vercel gates preview deployments on the commit
author's GitHub account, and `second-account` is not on the project.

**Do not pass `-c user.name`/`-c user.email` to `git commit` at all.** The
worktree is already configured with the identity every commit on `main` uses;
overriding it can only get it wrong. Recovery, if it happens again:

```bash
head=$(git rev-parse HEAD)
git -c rebase.instructionFormat='%s' rebase --reset-author-date \
  --exec 'git commit --amend --no-edit --reset-author --no-verify -q' origin/main
git push --force-with-lease="<branch>:$head"
```

Then re-record the review marker (the shas all changed) and re-block on CI —
`gh pr checks` reported the *old* green results for about a minute after the
force-push, exactly as §5.6 warns.

**`gh pr create` also needs `--repo felipearosr/loggd --base main --head <branch>`.**
Bare `gh pr create` resolved the base to `felipearos/loggd` (the account's old
name, which still redirects) against a head in `felipearosr/loggd` and died with
"No commits between …". `gh issue comment`/`view`/`edit` are all fine bare.

**The lesson is not "2–3 files per brief" — it is about the work, not the file
count.** Slice 2 was one file and still timed out, because seven fixture groups
is seven independent pieces of writing. Count what the executor must *decide*,
not what it must open. And a `--continue` round appears to re-read the prior
session before starting, which eats clock it does not have; a fresh
`delegate.sh` on a self-contained brief may be the better second round.
