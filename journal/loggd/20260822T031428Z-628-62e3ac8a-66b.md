**What landed.** Push payload construction moved out of the creation sites into
the notification layer:

- `src/server/notifications/push-payload.ts` (new) — `buildPushPayload(delivery)`.
  Wording is the delivery's own `title`/`message`, so bell and push agree by
  default; an exhaustive `switch` with no `default` supplies per-type tag and
  destination, which makes a thirteenth type a compile error. One override,
  `new_episode`, for the native routing discriminator.
- `notify.ts` — `NotifyEvent.push` deleted. Payloads are built per eligible
  delivery after every gate, grouped by identical payload so a popular episode
  stays one dispatch, and sent sequentially.
- `checkNewEpisodes.ts` — no longer references push at all.
- `src/lib/push.ts` — **the load-bearing find of this iteration**: the native
  transport had `if (payload.type !== "new_episode") return {sent:0,failed:0}`.
  Centralising the builder without removing that guard would have satisfied the
  ticket on paper and left eleven of twelve types unable to reach a phone —
  exactly the failure #624's "Further Notes" warns about. Removed, with a
  `push.test.ts` case pinning that a non-episode payload reaches a native
  target. `createEpisodePayload` deleted: no callers left, and it was a second
  copy of the wording the ticket centralises.
- Conformance test — new rule mirroring the insert rule: no production file
  under `src/server` outside the layer may name `PushPayload` or reach the
  transport. `src/server/actions/pushTarget.ts` is a **named** exception (dev-only
  diagnostic, creates no notification) and the rule fails if that diagnostic
  ever disappears, so the exemption cannot rot.
