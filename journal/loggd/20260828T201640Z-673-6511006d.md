## Three bugs the delegate shipped that only running it would find

The delegated implementation typechecked, passed 17 of its own tests, and was
wrong in three ways that all shared one shape: **the tool reported, but nobody
had read what it reported.**

1. **The verdict was computed and thrown away.** `summariseVerdict` produced an
   exit status; `process.exitCode` was only ever set in the `catch`. A completed
   run always exited 0. The document offers "this command turning green" as the
   proof that #675/#676 closed the read surface — so the check that was supposed
   to confirm remediation would have confirmed it unconditionally, including
   right now, with the credentials still exposed.
2. **`count(<column>)` counts non-NULLs**, which on a `NOT NULL` boolean is just
   the row count. The evidence read `is_draft=1402` for a table with **five**
   drafts, and `is_banned=38` with **zero** bans. Fixed with a closed
   `notableWhen` enum (`present` / `true` / `not-default`) per column.
3. **The redactor ate the evidence.** `security/harness/redact` redacts by key
   name and `token` is on its list, so keying counts by the raw column name
   rendered `patreon_access_token=[redacted]` — the single most important number
   in the audit. `code` is on the list too, so the verdict printed
   `exit code [redacted]`.

The fix for (3) is the one worth remembering: **do not weaken the shared
redactor to make your report readable.** Carry the column name as a *value*
under a neutral key (`{ column: 'patreon_access_token', notableRowCount: 1 }`)
and rename `exitCode` → `exitStatus`. Both now carry a comment saying not to
rename them back, because the "obvious" name is the broken one.

## Dead ends and gotchas

- **`SUPABASE_DB_URL` is not in the `prd` Doppler config.** Only `DATABASE_URL`
  is (pooler, 6543). `scripts/check-production-migrations.ts` and the backup
  workflow use `SUPABASE_DB_URL`, so the convention is genuinely split; the tool
  prefers the direct URL and falls back, which is what makes the documented
  `doppler run --project loggd-web --config prd` invocation work at all.
- **`scripts/` → `security/` was a new import direction.** Taken deliberately
  for the redactor. The reverse direction already existed
  (`security/harness/env.ts` imports `../../scripts/env-file`).
- **One transient `getaddrinfo ENOTFOUND` on the Supabase host** aborted a whole
  run while `curl` and a bare `bun fetch` to the same host both worked seconds
  later. Retrying was enough. A per-probe catch that records `inconclusive`
  instead of aborting the run is still worth adding — the classifier already
  treats inconclusive as non-passing, so it would fail closed *and* keep the
  evidence.
- `.security-evidence/` is git-ignored on purpose. Verify it stays out of
  `git status` after any `.gitignore` edit.
