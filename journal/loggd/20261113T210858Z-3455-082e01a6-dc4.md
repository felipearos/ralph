the memory fence on the service (`mem_limit: 20g`, `oom_score_adj: 500`, lines
187–189), but an OOM kill under `restart: always` restarts. Only the host's
`journalctl` / `docker events` for that day settles it.

`felipearos/ralph`. Nothing here polls Buildkite for build or agent health:
`scripts/configure-buildkite-schedules.sh` touches `api.buildkite.com` only to
set schedules, and `bk-log.ts` / `merge-wait.ts` are referenced by
`docs/merge-gates.md` but are not tracked files.

a `healthcheck:` on the `agent` service (it has none; `dind-buildkite` has one at
lines 151–158) plus an autoheal sidecar, because plain Compose does not restart
an unhealthy container. That is a redeploy of the symlinked Compose project at
`~/loggd-buildkite` (`docs/buildkite-standby.md:38-70`) verified by killing the
agent on this workstation — no unit test, lint or `buildkite/loggd` job can prove
it.
