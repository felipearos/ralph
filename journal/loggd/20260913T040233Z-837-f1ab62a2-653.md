## Read this before the next #819 child

- **`ALTER TYPE … ADD VALUE` and a CHECK that names the new value cannot
  share a transaction** unless the check compares `event_type::text`. Drizzle
  and PGlite both run a migration file in one transaction, so the first
  generated 0057 would have failed at apply. The `::text` cast is in the
  schema `sql` template with a comment; keep it if you touch that check.
- **`bun run db:generate` works with no database** — drizzle.config only
  needs `DATABASE_URL` to parse. Node modules were missing in this worktree;
  `bun install --frozen-lockfile` first.
- **Paid access is decided in more places than `is_pro`.** The spec axis
  found `src/lib/tier.ts#getUserTier` and `isProOwner` read `patreon_tier`
  alone; without that fix a comp gave the badge and nothing else. #840's
  "every server-side paid-entitlement decision" AC should start from
  `getUserTier` and `isProOwner`; the spec re-review's sweep found no other
  gate, only display reads.
- **What #838 inherits, on purpose:** the refresh cron still overwrites
  `is_pro` for a *linked* comp, and a comp whose preserved non-default tier
  has no link still raises the tier's unbacked finding. Both are #838's ACs.
- **Result-type split, again** (#772/#773): the action returns
  `ActionResult<{grantedAt}>` without the core's reason union, else TS2322.
- Standards judgement calls declined: `isProOwner` duplicating
  `getUserTier`'s rule (pre-existing row-shaped helper), a rollback test for
  the event insert (the transaction is the mechanism; conformance fences
  scope), the max-length check living in both zod and the core (the core is
  the rule).
