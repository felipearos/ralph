## What the spec review caught — five findings, all upheld, two of them load-bearing

Comment-only unit, so §3 does not owe the review. Ran it anyway (third iteration running), and it paid for itself again.

1. **P2, and the biggest thing missing from both the ticket and my draft: the soft-404 policy.** `src/app/soft-404-policy.test.ts:8-11` + `docs/soft-404-policy.md`: "under Cache Components every route streams a static shell before it can reach a `notFound()`, so a missing resource answers HTTP 200 with the not-found UI streamed in after." `[username]` has a `loading.tsx`, and so do A and B. So **a page gate answers a soft 404 (200 + noindex) and a proxy gate answers a hard 404 with a null body (`proxy.ts:178-180`)** — two different answers to criterion 1's "the project's not-found behaviour", and only the page gate matches what an unknown username gets. A test asserting `status === 404` passes on one route and fails on the other with the gate working in both. This is now constraint 1 and it is the strongest input to criterion 7's write-up.
