## What shipped on the branch

`account_authority.media_mode_previews text[] NOT NULL DEFAULT '{}'` holds a
per-account grant, and `browsableMediaModeTargets` (`src/lib/media-types.ts`) is
the one answer every consumer asks: the launch's enabled Subdomain Targets plus
that account's previews, in `ALL_SUBDOMAIN_TARGETS` order. The grant joins the
existing single `select` in `readAccountAccess`, so an authenticated request
pays no extra round trip; `requireMemberForRequest` carries the read on its
resolution, the API wrapper turns it into `ctx.browsableTargets`, and
`resolveMediaModeScope` gates on that instead of `isMediaModeEnabled`.
`GET`/`PATCH /v1/users/me` report and accept the viewer's own answer. The web's
gate is untouched and `isMediaModeEnabled` keeps its signature. Nothing is
cached across requests. Glossary entry, `docs/media-mode-previews.md` runbook,
and a sensitive-column probe row came with it.

## Decisions — do not re-derive

- **Threading via an optional `access` on `MemberResolution`**, not via a new
  exported `requestAccountAccess(request)`. About twenty test files do
  `vi.mock("~/server/auth/acting-member", () => ({ requireMemberForRequest:
  requestMemberMock(...) }))`; a second export consumed by `api-utils` would be
  `undefined` in every one of them. Optional means absent ⇒ enabled modes only
  ⇒ today's behaviour, which is what kept criterion 9's four pinned suites green
  unchanged.
- **Previews are not part of `MemberAuthority`.** A browsing grant says nothing
  about standing, so `judgeStanding` never sees them; they sit on
  `AccountAccess` beside it.
- **`resolveMediaModeScope`'s third argument is optional**, defaulting to
  enabled-only. That is what left the existing suite and the member-list
  contract untouched.
- **Adding `browsableTargets` to the handler context broke 31 existing
  `api-utils.test.ts` `toHaveBeenCalledWith(request, { user })` assertions**,
  and both `disableMovies()` helpers had been spying on `isMediaModeEnabled`,
  which the gate no longer calls. Expect that cost if you widen the ctx again.
- **`notableWhen: 'present'` is wrong for any NOT NULL column** in
  `scripts/deployed-security-baseline.ts`: the verifier turns it into
  `is not null`, which counts every row — the misleading count that file's own
  comment warns about. Use `not-default` with a `defaultValue`. I confirmed
  against the running local stack that `text[] is distinct from '{}'` as a
  postgres.js parameter counts only the granted rows. **Also:**
  `scripts/deployed-security-baseline.test.ts` pins each table's column list by
  set equality, so a new probe row must be listed there too.
- **Left alone on purpose:** the v1 onboarding media step still filters to
  `ENABLED_SUBDOMAIN_TARGETS`, so a preview account re-submitting it has
  `shows,books` rewritten to `shows`. The issue scopes onboarding into the web
  gate; recorded in the PR body for #2938's author rather than fixed here.
- **No CHECK constraint on the column.** A typo'd grant fails silently, which is
  the price of unknown values being ignored so that retiring a mode never
  strands a row. The runbook warns instead.
