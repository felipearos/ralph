## The decision: no split

The three surfaces are three words, not three changes. The mapper read
`origin/main` and the whole ticket is one production edit plus tests:

- `src/app/api/v1/reports/route.ts:29-33` is literally parameterised on this
  ticket today — `isListTarget ? viewerMediaTypes(browsableTargets) : enabledMediaTypes()`,
  with the comment "Review targets stay on the launch-enabled media types (#3233)
  until #3259". The ternary goes away; every target type takes the browsable modes.
- `report-write.ts` needs nothing: `contentReportableBy` already filters `review`
  (:138-152) and `review_comment` (:153-169) by `inArray(review.media_type, actableMediaTypes)`
  on top of `publishedReviewPredicate()` and `reviewComment.is_hidden = false`, so
  every AC-2 refusal falls out of predicates that exist. `report-write.visibility.integration.test.ts:273`
  already proves the core files the book rows when `book` is in the actable list.
- `src/server/actions/report.ts:84` passes `enabledMediaTypes()` unconditionally,
  so AC 3's web half is a pinning test, not an edit.
- There is no mobile client code at all — "mobile" here is the mobile *API* route.

So a `web` child would be one test and an `api` child would be the whole ticket,
and either would need the parent's body to be understood. That is the test for a
bad split, so it stays whole. The marker keeps the oversize bucket from offering
it again while the body is unchanged.
