## What I decided and why

**The learning's premise is stale, and that IS the finding.** The ticket says
"`Vercel` is in the ruleset's required set, so the PR stays BLOCKED". It is not,
and has not been since 2026-10-13:

- the live `Protect main` ruleset (13676910) has
  `required_status_checks: [{"context":"buildkite/loggd"}]` — read with
  `gh api repos/felipearos/loggd/rulesets/13676910`;
- `.mergify.yml:44,47` has only `check-success = buildkite/loggd`;
- `.ralph/config.json:28-30` `requiredChecks` is `["buildkite/loggd"]`;
- `docs/merge-gates.md:71-80` records the change and the Ignored Build Step
  ("Don't build anything"), so a head usually carries no Vercel status at all.

So the 30-minute wait and the `RETRY_LATER` handoff answer a gate that no longer
exists. That is cited as the decision (`docs/merge-gates.md`, quote "As of
2026-10-13, Vercel is optional again to reduce") — note the citation has to be
spelled in a comment ON the issue too, or the apply refuses it (see Gotchas).

**What is left is real: two tracked sentences still say the opposite.**
`CLAUDE.md:45` ("requires `buildkite/loggd` and `Vercel`") and
`docs/dependency-policy.md:207` ("the active `Protect main` ruleset now requires
`buildkite/loggd` and `Vercel`"). `AGENTS.md:50` was corrected by #2357
(3eb54cdc8, 2026-10-13); CLAUDE.md was missed. CLAUDE.md is loaded into every
Claude session, so that one line is the mechanism that produced the wait and the
empty re-trigger commit on PR #2305.

Scope written into the body, four items: fix `CLAUDE.md:45` (bullet identical to
`AGENTS.md:50-56` apart from wrapping), fix `docs/dependency-policy.md:207`, add
a case to `scripts/agent-instructions.test.ts` tying the entrypoints'
`ruleset requires` clause to `.ralph/config.json`'s `requiredChecks`, and record
the 2026-10-12 incident in `docs/merge-gates.md` (including that an empty
same-tree re-trigger commit got no status of its own and is never the remedy).

**No hook change.** I considered a `git commit --allow-empty` rail and rejected
it: nothing in the repo parses `git commit` (only `gh`-shaped commands, via
`.claude/hooks/gh_command.py`), `pre-merge-green.py` already ignores Vercel
because it judges only `requiredChecks`, and once no instruction file claims
Vercel is required there is nothing left to re-trigger for. A new hook would be
new territory for a problem the doc fix removes.
