## Read this before the next #844 child

- **The production-migration ledger check fails a branch that predates a
  migration main just gained.** My first build died in 26 s at
  `db:check-production-migrations` because #892's 0057 had been applied to
  prod and merged while my branch was cut before it. A rebase is the fix; do
  not read that failure as your own diff. Main's own build 1344 was red the
  same way (merge before apply), and the sibling PR went green minutes later.
- **Buildkite job logs are unreadable here** (API token withheld). The
  agent's `docker logs` give job start/finish and exit status per job; a
  ~26 s quality failure is the ledger check, ~2–3 min is lint, ~5 min is a
  pass. The quality/e2e concurrency group serialises across builds, so a
  build behind two others waits ~20 min before its quality job starts.
- **`review` has no unique index over a scope.** The advisory lock fences
  only the two quick-action cores; `logShowCore` and the external quick cores
  insert without it. A partial unique index is the durable fix and needs a
  migration (needs-migration path).
- **Pre-existing movie quick ratings live in `tv` rows** with the movie's id;
  they are indistinguishable from real show rows with the colliding id, so no
  backfill is possible. They were already invisible to the movie UI's reads.
- **Season "contextual watched"** needs TMDB's released-episode count; the
  read fetches `getSeasonDetails` for season scope only and returns
  `progress: { watched, released }` for #852 to render.
- **Result-type pattern** (again): the cores never return `success: false`
  (failures throw) but keep `ActionResult` because the ratchet requires it;
  routes narrow on `success` for TS.
- Declined from review: a concurrency test for the lock (PGlite is one
  connection), the `Pick<typeof db,"select"> | Pick<Transaction,"select">`
  executor type (siblings pass `tx`; a union of the raw types is not callable),
  and `progress`/`scope` in the GET payload (kept, see above).
