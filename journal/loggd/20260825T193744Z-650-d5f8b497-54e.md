## The failure: a new e2e case the browser refused before React saw it

`e2e/sign-up-validation.spec.ts` → *"should refuse a password shorter than the
shared minimum before calling the API"*, added by the previous iteration. It
filled a 7-character password, clicked **Create account**, and expected the JS
guard's `bg-danger` banner.

It never got there. The field carries the shared minimum as `minLength`,
Playwright's `fill()` sets `element.value` through the IDL setter — which sets
the **dirty value flag** — so Chromium's own interactive constraint validation
refuses the submit and `handleSignUp` never runs. The test's own comment said
the form was "submitted programmatically"; it was submitted by clicking a
`type="submit"` button, which is the opposite.

**The general lesson, and it is not about this form:** an e2e assertion that
names WHICH layer refused something is a bet on the order the layers fire in.
The rewritten case asserts what is true under either — the request never leaves
and the form is still there — using `page.waitForRequest(..., {timeout})` and
expecting the wait to time out, rather than reading a `requested` flag
microseconds after the click. (`expect.poll` was the reviewer's suggestion and
is wrong here: poll retries until an assertion PASSES, so `poll(...).toBe(false)`
succeeds instantly and proves nothing about a request that arrives later.)

## Also worth knowing

- Rate limiting is **inert in e2e** — no Upstash configured, so `checkRateLimit`
  fails open and returns success. That is why moving sign-up from its own
  `auth:sign-up:${ip}` bucket onto the shared `rateLimitIdentifier` bucket
  (`auth` is only 5 req/min) did not break the suite. It would matter a great
  deal if Upstash were ever configured for the hermetic stack.
- `git push` needs `--force-with-lease=<branch>:<sha>` pinned to the sha you
  rebased from, and `gh pr create` needs `--repo felipearosr/loggd`; the remote
  still prints a "this repository moved" notice for `felipearos/loggd`.
- Do not pass `-c user.email` to `git commit` — carried forward from the #655
  entry, still true, Vercel gates preview deploys on the commit author.
