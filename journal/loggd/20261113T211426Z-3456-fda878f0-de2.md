**Decision.** `ready-for-human`. The ticket is a recurring-finding wrapper around
the learning `mobile-dev-screening-needs-doppler-prd`: a loop cannot run a mobile
dev screening on the emulator against the production-backed API. The mapper
confirmed every claim of the 2026-10-13 learning still holds at `7db43903e`:
`mobile/scripts/start-prod-dev.sh:25` dies on a missing Doppler CLI before doing
anything, `:106-107` are the only source of `EXPO_PUBLIC_SUPABASE_URL` /
`_ANON_KEY` (copied from the Doppler-injected `NEXT_PUBLIC_*` pair),
`mobile/lib/supabase.ts:149-155` throws without them, and `mobile/.env.production`
— the only committed `mobile/.env*` — carries `EXPO_PUBLIC_API_URL` alone. No
mock, offline or doppler-free mobile path exists, and nothing tests one.

**Why not ready-for-agent.** The learning's own Fix line offers exactly two
routes and both belong to a person. An operator running the screenings is not a
code change. The other route — give the loops the production Supabase URL and
anon key — means committing credentials into the repo or lifting them from the
harness `secrets.withhold`, neither of which a loop may do, and the project
currently enforces the opposite: `scripts/check-loop-env.ts:16-17` requires a
loop's `NEXT_PUBLIC_SUPABASE_URL` to point at the local stack. So the gating
question is a credentials-and-host decision no `docs/adr/**` settles, which is
readiness rule 5 twice over. The verification is a second reason on its own: the
acceptance criterion is an emulator screening, and no loop gate can prove it.

**What I left the operator.** Three answers, each with the code change it
implies, so the follow-up ticket writes itself:
1. commit the two values → a small launcher ticket (start Metro without Doppler
   when `EXPO_PUBLIC_SUPABASE_*` are already set, Doppler still the default),
   unit-testable with a stubbed `PATH` in the style of
   `scripts/reclaim-e2e-ports.test.ts`, plus a `check-loop-env.ts` exemption;
2. inject them into the loop environment → the same launcher fallback, rest is
   harness config outside this repo;
3. keep the fence → `wontfix` on code, and the durable fix is documenting in
   `mobile/README.md` and `.agents/skills/mobile-emulator-session/SKILL.md` that
   a production-backed screening is operator-only, so the next such ticket is
   written `ready-for-human` from the start instead of discovering the fence
   after a branch is built.
