## Judgement calls a later pass should not re-derive

1. **The v1 conformance checks are not a seam.** `src/app/api/v1/route-conformance.test.ts` and `profile-subject-conformance.test.ts` **walk the directory**, so a new route needs no edit there. Treating "registered with the v1 conformance and contract checks" as a shared edit would have put the whole tree back in one group — i.e. the legacy behaviour this pass replaces. The only explicit route table is `src/app/api/v1/media-reference-refusal.test.ts`; if coders register book routes in it, it is a one-line append, left to rebase.
2. **`packages/shared/src/media-filter.ts` and `src/lib/media-filter.ts` are two different files** (2345 and 1241 bytes; `mediaModeToMediaType` vs `buildMediaCondition`). The mapper's SHARED FILES table conflated them into one row, which would have forced `mobile-mode-shell` and `books-api-gate` to merge and destroyed the wave-1 parallelism. **Checked directly before acting.** #2938 edits the shared package; #2941's candidate is the web one. They do not collide.
3. **#2938 shares `discover.tsx`, `browse.tsx`, `profile.tsx` and the Home titles tab with #2939, #2947, #2948 and #2946** across group lines. Every such pair is already serialised by `## Blocked by` — all four sit downstream of #2938 — so a shared group would have bought nothing.
4. Where it was genuinely unclear, the tickets share the group.
