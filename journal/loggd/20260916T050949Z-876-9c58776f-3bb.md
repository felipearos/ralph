## Key decisions

- **`withAuth` gained an option rather than the route using `withOptionalAuth`.** `withOptionalAuth("data_export", …, { checkStanding: false })` plus a manual 401 would have reused existing semantics with no wrapper change — but it collapses `unavailable` into `user: null`, so a Supabase outage would answer 401 and the app would sign the member out on an outage. The option preserves the `unavailable → 500` path.
- **Cancellation is not a distinct state, deliberately.** `Sharing.shareAsync` resolves `void` and reports nothing about what the member chose, so saving, cancelling and a sheet that failed to open converge on one cleanup path and the copy says the file was *offered*, never saved. This is the one acceptance criterion answered differently from how it is worded, and the PR body says so.
- **No `app.json` plugin entry for `expo-sharing`.** Its config plugin builds a share-*into* extension (receiving shares), which this does not use; `shareAsync` needs autolinking alone. Adding the plugin would have created an unwanted iOS share extension.
- **Filename gated on the sweep's own regex.** The client does not trust `Content-Disposition`. The file is written `overwrite: true`, so a header naming `Documents.json` would have clobbered an unrelated cache entry *and* fallen outside the sweep, leaving a snapshot on the device forever.
- **Glossary:** `CONTEXT.md` gains **Account Export**. Its `_Avoid_` line rules out bare "export" where an Import Run is also in view, which is why the settings section is titled "Account Export" and not "Export" — the standards axis caught my own new rule biting my own screen.

## Review findings worth keeping

Both axes ran **three** rounds (standards on glm-5.3-flash via `inspect.sh`, spec as an Opus `Agent`), because each fix round added code paths the previous round had not read. The spec axis earned its keep twice:

- **The P1 nobody else would have found:** `expectedUserId` was checked pre-flight and on a 401, but never on a **200**. A whole-account download can outlive the session that asked for it — sign out and back in as somebody else mid-flight and the server answers 200 to a token that was valid when it was sent, so neither existing check fires and account A's snapshot reaches account B's share sheet. Fixed in `getFileText`, mutation-checked.
- **A guard with no test, twice over.** The "nothing private is logged" assertions all ran with the client mocked out — they could not have failed. And `isAccountDeletionPending`, the only thing between `checkStanding: false` and an account mid-deletion exporting itself, had **no test anywhere in the repo**: deleting that line left the whole suite green. Both now have tests that bite.
- **Declined, with reasons:** the copy strings duplicated between screen and test (pinning UI copy literally is the point; a shared constant would let both drift together), the call-order assertions (the ordering *is* a contract — availability is checked before an export is spent), and the `expo-file-system` mock called "dead" (the import panel on the same screen really does use it).
- **Left as a known residue, stated rather than papered over:** `withAuth`'s catch logs a `userId` beside any unexpected throw. That is every v1 route's behaviour, so narrowing it is a change to the shared wrapper. A comment on the route says so; my first attempt at that comment claimed it did not happen, and the standards axis caught the lie.
