**Key decisions.**

**The rank is the screen index, never `position`.** `src/app/api/v1/lists/[id]/route.ts`
filters book and music entries out *before* `slice(offset, limit)`, so a List whose
curator ordered ten titles can hand mobile three with positions 3, 7 and 9. Drawing
`position` would label entry three "9". The index is what the reader counts down the
screen, it stays contiguous across pages because the offset advances by the count of
returned items, and it is what the web does. The fixture carries gapped positions so the
test fails against the wrong answer rather than merely passing against the right one.

**Notes render in both layouts, where the web draws them only in its list view.** The
grid is the default, so a reader would otherwise have to discover the toggle before
learning the curator had written anything at all. Grid gets two truncated lines; the row
is where a note becomes readable, which is what parent story 10 asks the toggle for.

**"Persists per viewer" was only half deliverable, and I said so instead of ticking it.**
The layout lives under one device-global AsyncStorage key with a `reset()` on sign-out,
deletion and identity change — `media-mode-store`'s exact pattern. That buys *isolation*
(your layout never greets the next account) but not *persistence across a sign-out*.
Changing it means changing both stores and deciding what a signed-out reader gets, which
is a decision, not an implementation detail. Filed as **#1166**; the PR body states the
gap rather than claiming the criterion met.

## READ THIS FIRST: a mutation run caught my own test seeding storage in the wrong order

The spec axis found that a member tapping the toggle before AsyncStorage's async read
lands has their choice overwritten by `merge` — the control snaps back under their finger.
Real bug; the fix is a `chosen` flag that makes an explicit choice outrank a rehydration.

The test I wrote for it **passed with the guard deleted**, and only the mutation run said
so. I had seeded storage with `"grid"`, then called `setLayout("list")`, then rehydrated —
but `setLayout`'s own persist write overwrote the seed, so rehydration read back `"list"`
and the assertion held either way. Seeding *after* the tap is what models the read that
was already in flight when the member tapped.

**Generalisable: when you test a race against a store that writes on every set, the
write you are racing has to be staged after the action, not before it.** Ordering the
fixture the way the timeline reads is exactly what makes it vacuous.

That is three vacuous assertions this iteration — the other two were the executor's
(`within(poster.parent)` for a note that is the poster's *sibling*, and a "persists across
a remount" test that a module-level store passes with `persist` deleted). Every one was
found by mutation, none by reading. **Mutation-test the guard even when you wrote it.**
