## Third `oversize` false positive in a row, and this time the code says why

#3044, #3054 and now #3056. The frontier's test (`frontier/next-tasks.ts:1312-1325`)
is lexical: `>8` criteria, or `>=3` of the surface words. #3056 has **7** criteria
and matches `web` on the single clause "as the web stores it", plus `mobile` and
`api` from the phrase "the mobile API" — one phrase, two surfaces. **Every
Books-preview API ticket in the #3053 tree is phrased that way**, so expect this
bucket to keep offering them. The verdict is cheap to reach (count the criteria,
then grep the body for the four words) but the mapper call that makes the comment
worth posting is not, so decide "whole or split" BEFORE mapping.

## Why it stayed whole, and where the first draft was wrong

The app side is already a separate ticket (#3061, which blocks on #3056), so the
surface seam this project splits along was already cut. My first draft also
claimed there was no internal seam; **the spec reviewer showed that was wrong** —
a writes/reads split is perfectly shippable, because `favorite-titles.ts:45`
already omits `book` rows and the strict schemas already refuse a book write, so
neither half leaks without the other. The non-split verdict rests on size alone:
7 criteria, one surface, ~5 production files. The comment now says that instead of
the false claim. Lesson: "there is no seam" is a much stronger claim than "the
seam is not worth cutting", and only the second one was true.

## The two decisions, and the rule behind both

Both cite `CONTEXT.md` → *Unavailable Title*. `triage-apply.ts` resolves the
citation at the base branch and checks the quote verbatim, so:

1. A provider failure degrades the `books` entries, never the read: catch
   `getSeveralBooks`, answer placeholders, leave the shows and movies sections
   alone.
2. Label mapping: the batch **answered** and omitted the id → "Title unavailable"
   (`media-hydrate.ts:86`), `resolved: false`; the batch **threw** → `Book #<id>`
   (`mediaPlaceholderName`, `media-hydrate.ts:65`), `resolved: false`. That is the
   rule's own permanent-vs-transient distinction, and it is what makes AC3's entry
   shape testable.

Left open for Felipe: the summary filter (default: do not filter here), and the
djb2 note as a heads-up.
