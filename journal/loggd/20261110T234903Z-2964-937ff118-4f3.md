1. **`track` is in no mode's list types.** `LIST_TYPES_BY_MODE` maps `music` to **two** types, `album` and `artist` — there is no `music` value in `ListType` — and `ListType` also has `track` (`schema.ts:1834-1842`), which appears in no mode's entry while members can still create track Lists. So the narrowing silently stops answering liked `track` Lists. Criterion 3 said "a music List", which is not a `list_type` at all. Amended to seed `album`, `artist` **and** `track`. `ROUTE_OWNER` does map `track: "music"` — that is route ownership, not a mode's list types, and the amendment says so because a coder grepping `track` will hit it.
2. **Three absence assertions could pass vacuously** (criteria 1, 3 and 4). The seed file this ticket must extend already carries private, hidden, friends-only and blocked-owner Lists, any of which makes "is not answered" pass whether or not the `list_type` narrowing exists. 3. **Criterion 5 was a `[] == []` check waiting to happen.** "The endpoint's other liked types return exactly what they return at `main`" proves nothing for a category the seed gives the subject nothing in.
