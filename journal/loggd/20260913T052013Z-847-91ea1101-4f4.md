## What shipped

**Server**
- `GET /api/v1/users/stats?username=&section=summary` returns `{section:"summary", averageRating, watchStreakDays, hoursWatched}`. It resolves the subject once and applies the access rule before any section loads. Refusals: 400 for missing username/section or an unsupported section, 404 for an unknown member, 403 `FORBIDDEN` with no data for anyone who is neither the owner nor a Supporter (including anonymous).
- `canViewFullStatistics(viewerId, subjectId)` in `src/lib/tier.ts` is the one rule; the web `/[username]/stats` page uses it too.
- **`cached-stats.ts` moved** from `src/app/[username]/(profile)/stats/_lib/` to `src/server/queries/cached-stats.ts`. It gained wrappers for average rating, streak and hours under the same `stats-${userId}` tag. **The next #843 sections (`years`, `hero`, …) should add cases to `STATS_SECTIONS` in the route and wrappers in that file, never a new route.**
- **`logShowCore` now calls `revalidateUserStats(userId)`** after the replay guard. The Server Action's duplicate call is gone. Before this, `POST /api/v1/reviews` (mobile) never expired stats for a movie log.

**Mobile**
- `useUserStatsSummary` throws `StatsForbiddenError`, which is never retried. `defaultQueryRetry` is exported from `mobile/lib/query-client.ts`.
- Formatting lives in `mobile/lib/stats-summary.ts`.
- Insights shows real values: "4.2", "12 days", "~340h", with empty copy and never `--`. It adds a See all stats row.
- New route `mobile/app/profile/[username]/stats.tsx` covers block gate, loading, access (sign-in vs Supporter copy), error+retry, empty, and populated, with pull-to-refresh.
- `LogSheet` invalidates `["profile"]` after every successful log, not only edits.
- Maestro flow `mobile/.maestro/profile-stats.yml` was committed but not run (device constraint).
