## What shipped

Mobile email confirmation hung on "Confirming your account…" forever when the
link opened a Loggd that was already running. `mobile/app/auth/confirm.tsx` read
the link with `Linking.useURL()`, which seeds from `getInitialURL()` — the URL
that *launched* the app. On a warm start the app was launched from the icon (so
that is null) and expo-router had already consumed the `url` event to navigate
to `/auth/confirm` before the screen mounted, so the URL stayed null forever.
It now uses `Linking.useLinkingURL()`, which seeds from `getLinkingURL()` (the
most recent link) and still tracks later links. A second effect lands a
never-arriving link in the screen's existing "Couldn't confirm your account"
state after `NO_LINK_TIMEOUT_MS` (5 s) instead of spinning. Only `mobile/` is
touched.

## Key decisions

- **The screen suite alone could not prove the fix.** It mocks `expo-linking`
  wholesale, so its warm-start tests pin the hook's *name*: five tests that
  predate the fix set the mocked hook to return a URL on first render and
  passed while the bug was live. Both review axes found this independently.
  Hence `mobile/__tests__/expo-linking-warm-start.test.tsx`, which uses the
  real hooks and mocks only the `ExpoLinking` native module and RN's `Linking`.
  Mutation-checked: a harness reading `useURL` fails warm start and **still
  passes cold start** — which is exactly why the bug survived.
- That test reaches `../../node_modules/expo-linking/build/ExpoLinking` by
  relative path. The alternatives were ruled out by the standards axis:
  jest-expo ships no `ExpoLinking` mock, overriding `expo-modules-core` would
  displace jest-expo's own `doMock`, and a `moduleNameMapper` entry would
  change resolution suite-wide for one file. Both reasons for the path (the
  `exports` map, and bun hoisting the package to the repo root) are documented
  in the file.
- **Acceptance criterion 5 cannot be met by a loop**, and is called out as such
  on the PR rather than claimed. The supported emulator-against-production path
  needs `doppler run -p loggd-web -c prd`; loops may not run Doppler and the
  prd credentials are withheld. A dev client cannot stand in — Loggd Dev drops
  every verified link. Cited the open learning
  `mobile-dev-screening-needs-doppler-prd` instead of rediscovering it.
