**Why a split.** #2695 names three surfaces — the v1 API, the web activity pages
and the mobile Activity tab — so it is oversize by the project rule even though
it has only five acceptance criteria. The honest seam was NOT the surface seam
as written: the mapper found that the whole production change lives in
`src/server/queries/activity.ts`, and that the v1 route (`route.ts:110`) and the
server action (`actions/activity.ts:44`) already pass a server-resolved viewer.
So the split is one implementation child plus two coverage children, with the
mobile one kept separate so no child names three surfaces and bounces back to
intake.

- **#2735 — `activity-reader-adult-gate`.** Thread `viewerId` through
  `readMemberActivityPage` → `getActivity` → `hydrateActivityPage`, and gate the
  page with ONE `gateAdultStatsTitles` call (`{ dropFailedLookups: true }`) over
  a tagged array of the review, watchlist, like and comment rows.
- **#2736 — `activity-v1-viewer-contract`.** Tests-only: the signed-in
  `friends`, `incoming` and named `user` tabs, a signed-out read of a public tab,
  a type-level check that the action's input cannot carry a viewer, and two greps
  over the web components.
- **#2737 — `mobile-activity-api-fidelity`.** Tests-only under `mobile/`: the tab
  renders exactly the API's items, a short page still pages, the hook's transform
  filters nothing.

**Four decisions the split made, all from the code, none from precedent or
taste.**

1. **Gate AFTER row hydration, not "before hydration" as #2695 says.** Keys of
   kind `watchlist | like | commented` carry `{ kind, id, timestamp }` alone
   (`activity.ts:357`); only `review` keys carry a media reference (`:338-348`).
   The first point where every movie on the page is known is between the two
   `Promise.all`s (`:960-968` and `:979-998`) — still before any title, poster or
   profile is fetched, so the media cache stays viewer-agnostic as #2695 requires.
2. **One gate call per page.** `gateAdultStatsTitles` reads the preference and
   batches `resolveMovieAdultFlags` itself (`adult-gate.ts:136-162`), so four
   calls would be four `show_adult_content` reads and four flag batches.
3. **The gate reddens existing suites, and that is #2735's work.** `migrate()`
   leaves PGlite without `media_metadata` (`src/test/stats-section-test-db.ts:49-51`)
   and `resolveMovieAdultFlags` throws for the whole batch, which
   `dropFailedLookups` does not cover. Named in the body: the scope, media-type,
   page-hydration and server-action integration suites need
   `createMediaMetadataTestTable`, and the unit suite's queued `db.select`
   results (`activity.test.ts:169-190`, `:555-566`) would be consumed by the
   preference read.
4. **The offset drift is NOT in any child.** Both clients advance by
   `items.length` (`ActivityFeed.tsx:64`, `mobile/hooks/useApi.ts:224-227`) while
   the server slices by entry count (`activity.ts:1299-1300`), so a short page
   re-requests consumed entries. Pre-existing — hydration has always dropped
   deleted and unpublished rows — and fixing it is four files on three surfaces
   #2695 does not ask for. #2737 pins today's behaviour and says not to change
   it. **A follow-up worth filing by someone who can scope it.**
