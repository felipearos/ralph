## What shipped

- **`src/server/patreon/entitlement.ts#recordPatreonTier(tx, userId, tier, at)`** is now the only place Patreon activity writes to the Account Authority.
  - It always records `patreon_tier`.
  - It writes `is_pro` via `CASE WHEN entitlement_source = 'patreon' THEN <tier = pro>::boolean ELSE is_pro END`.
  - The decision is in the UPDATE itself, so a comp granted concurrently (`grantCompedProCore` locks the row `FOR UPDATE`) is re-evaluated against the row Postgres finally locks.
- **Callers:** `refreshPatreonTiersJob`, the OAuth callback (link and re-link), the pledge webhook (create/update/delete), and `unlinkPatreon`. Before this, each wrote `set({ patreon_tier, is_pro })` itself, so any of them silently revoked a comp.
- **The re-sync deliberately still includes comped members.** Credentials keep rotating and the tier stays current for reconciliation. The #819 spec text said "skip rows where source <> patreon"; #838's acceptance criteria supersede that.
- **Rotation audit:** the `unbacked-entitlement` why-text for a comp beside a zero-pledge tier said "is_pro is not set". It now says "is_pro is explained by the comp, not by this tier". Rows that aren't comps are unchanged.
- **Glossary:** the Comped Entitlement entry gains one sentence. Patreon activity keeps the tier current underneath the comp, but only a `patreon`-sourced entitlement lets the tier decide Pro.

## Read this before #839 / #840

- **A revoke or expiry must set `entitlement_source = 'patreon'` in the same statement that derives `is_pro` from `patreon_tier`.** `recordPatreonTier` leaves `is_pro` alone until the source is `patreon`, so doing those two steps in separate statements leaves a window where a refresh changes nothing.
- A revoke that runs at the same time as a refresh can read a stale tier. That race is #839's to settle; the row lock in the grant core is the pattern to copy.
- `patreon_tier` is the whole of the "trusted Patreon state". The pledge sits on the Patreon Link and is deleted on unlink, and unlink also sets the tier to `none`. Nothing else is needed to restore the member's backed access.
- **Audit grading for a comp beside a backed tier:** medium `entitlement` + low `modified-since-creation` + an inventory line. That is exactly how a backed Patreon member's tier grades, and the spec re-review accepted it as "expected inventory".
