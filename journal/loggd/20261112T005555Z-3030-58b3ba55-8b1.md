## What I decided

Verdict **ready** → `ready-for-agent`. The ticket already had all five managed
sections, a real `Blocked by: None`, and no migration. What it lacked was
checkability and a few facts that disagree with `main`. I replaced `What to
build` and `Acceptance criteria` (allowed: the issue was untriaged and
unlabelled) and left `Parent` and `Blocked by` alone.

Substantive corrections, each from mapper or spec-review evidence:

- **Not implemented.** `src/app/api/v1/books/` holds only `[id]/`. No batch read.
- **The parent spec's "beside the Trending and Popular book reads" is false** —
  there are no v1 book Trending/Popular routes. Said so in the ticket.
- **`withAuth` vs `withOptionalAuth`:** the ticket named both. `withAuth`'s
  `requireAuth` 401s a signed-out request inside the wrapper, so it could never
  give the bare not-found the read owes a signed-out visitor. Now names
  `withOptionalAuth` only, with the reason.
- **The signed-out guard must be separate from the Books gate.**
  `withOptionalAuth` gives a signed-out visitor the generally enabled Media
  Modes, so once Books joins `ENABLED_SUBDOMAIN_TARGETS` the gate stops
  stopping them. #3027's user story 22 and its "signed out included … before the
  ids are parsed" already decided this, so it is the parent spec's call, not a
  product decision of mine. No `decisions` block in the plan for that reason.
- **One query change put in scope deliberately:** the Book detail read takes
  `liked`/`score` from the lowest `review.id`
  (`src/server/queries/externalStatus.ts:171-178`, whose comment says duplicate
  title-scope reviews already exist), while the batch's review `select`
  (`:287-296`) has no `orderBy` and its loop overwrites. So AC1's "matches the
  Book detail read" was unachievable as the code stands. The ticket now asks for
  that ordering clause and names the two web callers whose tests must stay green
  (`src/app/books/browse/page.tsx`, `src/app/[username]/(profile)/books/page.tsx`).
- **Smaller:** 50 bound counted before dedupe (matches the precedent schema);
  the 400-on-unservable-id departure from the detail route's 404 explained so a
  reviewer does not flag it; `~/lib/hardcover` and `~/lib/api/adult-gate` named
  as the mock-and-throw targets (books have no adult gate — do not copy
  `gateAdultStatsTitles`); the integration test now exercises `liked`, one of the
  four fields it was not writing.

match both. Split into two named pairs. All round-2 findings folded in; no
round 3.
