**Key decisions.**

- `planFeedSections` cannot plan one section (it requires all five), hence a
  real `planFeedSection` rather than calling the plural form with four stub
  sections, which would have produced bogus fallback-source coverage.
- `planFeedSection` returns `Extract<FeedSectionPlanEntry<Items>, {section: S}>`.
  That narrowing is what lets the tab read `state.items` with no runtime
  `kind` check.
- Removed deliberately, per AC1: the "hidden by your activity filters" copy,
  the muted-accounts copy and the "Manage feed settings" link. Flagged in the
  PR body for the owner to decide whether the shared plan should carry a muted
  hint.
- Added an `ErrorState` with retry: the plan has an `error` state the old tab
  had no render for — it fell through to the empty copy.
- The fallback "Popular Reviews" now sits above the tab's own community-wide
  "Popular This Week". The ticket asks for the fallback in those words, so it
  shipped, flagged in the PR body.
- `isViewerFeedSectionKey` deliberately does not count key elements: a length
  check would silently stop matching — and stop marking these reads stale —
  the day the key gained one.
- `feedSectionReadState` takes the three read fields, not the query object, so
  a caller's `useMemo` depends only on the fields it reads. Declining the
  reviewer's "pass the query" simplification is deliberate and documented in
  the helper.
