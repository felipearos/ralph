**Key decisions.**

- *"All media" is a constant on a ranking, viewer-derived on the directory.*
  Rankings are cached per media type with nothing viewer-specific in the key, so
  a viewer-derived set would either leak across viewers or force the browsable
  modes into the cache key. The directory is per-viewer: web
  `enabledMediaTypes()`, mobile API `viewerMediaTypes(browsableTargets)`.
- *Both new arguments are required, deliberately.* `rankGlobalReviews`'
  `mediaType` and `profile-tags`' `mediaTypes` being non-optional is what caught
  the one stale caller and what stops the easily-missed web sidebar at
  `tag/[tag]/reviews/page.tsx:102` from going unguarded.
- *The three existing `eq(review.media_type, …)` sites moved onto the parameter
  in the same change.* Left behind they would have ANDed with the new predicate,
  so a preview viewer asking `media=books` would silently have got nothing. Four
  tests pin that trap.
- *The tag directory needed two rules, not one.* The predicate on the review
  join alone answers a book-only tag at **zero** rather than omitting it; a
  FILTERed count plus `HAVING` omits it while keeping the zero row for a tag
  with no published review at all.
- A domain note went into `CONTEXT.md` under **Media Mode Preview**: what "all
  media" means for a ranking versus a per-viewer directory.
