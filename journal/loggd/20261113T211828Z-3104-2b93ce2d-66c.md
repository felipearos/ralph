## What landed

`GET /api/v1/users/reviews` now answers each book row a `book` entry — the
book's whole Media Reference plus title, authorship credits, `coverUrl`,
`releaseYear` and slug — and fills the row's `showName`/`year` from the book.
`BookBasics` gained `authors`, filtered by `isAuthorCredit`. Only `tv`/`movie`
rows go to TMDB. The diary read is unchanged, only newly tested. New PGlite
integration file `src/app/api/v1/users/profile-book-reviews.integration.test.ts`
(27 tests).

## Key decisions

- Book facts travel nested under `book` with the whole Media Reference, not as
  a bare `externalId` — CONTEXT.md and the `FeedSectionBookItem` precedent.
- `releaseYear: number | null`, matching the v1 book card family, not the diary
  row's `year` string.
- A book row with a null `external_id` answers `book: null` and the `Book #0`
  placeholder (dropped correctness P3): a reference built from a missing id
  would claim a book no client can open, and the diary read agrees on the name.
- **Started Date is out of scope and stated everywhere.** No column stores one;
  #3098 owns that migration and is `needs-info`. After the merge this session
  commented on #3098 that this read needs `startedAt` once the column lands.
