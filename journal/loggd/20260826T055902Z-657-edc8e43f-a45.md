## The bug the characterization suite found: #690

Writing the profile test surfaced a live, shipping defect:

```ts
p.includes("he") ? "he_him" : p.includes("she") ? "she_her" : p.includes("they") ? "they_them" : undefined
```

`"she/her"` contains `"he"`. So does `"they/them"`. The `"he"` arm is tested
first, so **every Letterboxd member who is not he/him is recorded as he/him** on
import, and only he/him is correct by accident.

Pinned rather than fixed — a no-behaviour-change refactor cannot fix behaviour
without destroying the characterization it exists to prove. The test is named
*"misreads she/her and they/them as he/him — pinned, not endorsed"*, points at
**#690**, and #690's acceptance criteria say to invert that test rather than
delete it. Both review axes agreed pinning was the right call.

**Generalise it:** a substring test over a token set where one token contains
another is always ordered wrong somewhere. Worth grepping for elsewhere.
