## Three findings from review that changed the design

1. **Capture must track the path, not sample it.** The first draft snapshotted
   `usePathname()` into a mount-time ref. For a signed-out member the gate has
   been mounted since launch, so that ref reads `"/"` — a member who browsed to
   a show and then signed in went nowhere. Following `[pathname, userId]` is
   what makes "survives sign-in" actually true.
2. **`bindPendingIntent` was a race and is gone.** Adopting an unbound record at
   sign-in is a read-modify-write against the gate's read-delete; a write landing
   after the delete resurrects a spent intent. An unbound record is instead
   simply consumable by whoever arrives, which is what a pre-sign-in capture
   means. Fewer moving parts and no race.
3. **The confirmation link's `redirect` must stay unread.** I had wired it, then
   found `/api/v1/auth/sign-up` refuses a caller-named destination on purpose
   (#650/#651) — so the parameter is always `/` for a mobile link and only an
   attacker has a reason to set it. Reverted to comment-only. The limit, stated
   on the PR: the local record is device-local, so a link followed on another
   device or after a reinstall resumes nothing.

**`jest.spyOn(AsyncStorage, 'setItem').mockRestore()` silently breaks every
later write in the file.** The library's jest mock defines its methods as plain
`jest.fn`s holding the in-memory store, so restoring a spy over one leaves a bare
mock behind and the store stops working — with no error, just tests reading
`null`. Swap the property by hand and put the original back instead. Both new
test files carry a `withFailing()` helper that does it.
