# 2026-09-30 — #1893 Sweep the remaining confirmed CI flakes

**Outcome: merged.** PR #1900, merged via the Mergify queue at 12:29:53Z as `cf9a67a0d`.

**What shipped.** Five confirmed CI flakes, one root cause each.

1. The 84-file PGlite bootstrap: `createTestDatabase()` replayed 43 migrations plus `initdb`
   in every integration file's `beforeAll` (1250–1520 ms each). Now replayed once per run in
   `globalSetup` into a gzipped data directory that each call boots from via `loadDataDir`.
   Kept **synchronous** — which is why the mechanism is `dumpDataDir("gzip")` + `readFileSync`
   — so all 89 call sites are untouched. Cache key is a SHA-256 of the migrations' SQL **and**
   the installed PGlite version; a miss falls back to a full replay, and `globalSetup`
   swallows a build failure because a cache miss must not fail the hundreds of suites that
   never touch a database. `backdrop-write` went 3066 ms → 1051 ms at load 44.
2. `pristine: true` + `PRISTINE_MIGRATION_HOOK_MS` for the five suites that test a migration
   and must start empty; `migrate({ before })` over a snapshot now throws and names the option.
3. `bun --no-env-file run` in `verify-deployed-security.test.ts` — `bun run` was loading
   `.env.test` and handing the script the `DATABASE_URL` the case withholds, so it did real
   network I/O and **passed for the wrong reason**. 1.5 s → 97 ms.
4. `PREFERENCES_SAVED` + `test.slow()` in `feed-controls.spec.ts`: the fieldset is disabled for
   a transition that also awaits `router.refresh()`, so a looped `toBeEnabled()` was waiting on
   the previous iteration's refresh.
5. `test.slow()` in `list-collaboration.spec.ts` — the journey is simply bigger than 30 s.

**Key decisions and dead ends.**

- Measured and rejected two snapshot alternatives: a pre-migrated dir + `cpSync` (faster boot,
  but 43 MB of writes per file and temp-dir cleanup) and batching the DDL into one `exec`
  (346 ms vs 1250 ms, but still pays `initdb`).
- Declined moving `router.refresh()` out of `FeedPreferencesForm`'s transition — it would
  re-enable the switches before the feed refreshes, which is a product decision, not a test fix.
- Declined a per-`before` snapshot for the five `pristine` suites: `before` is known only after
  construction, so it needs an API change. Written into #1898's scope instead.
- Three rounds of both review axes. Rounds 1–2 found real defects: a cache key missing the
  PGlite-version term, a `catch` that swallowed EACCES as a cache miss, a repo-wide
  `hookTimeout` justified by only five suites' evidence, and two comments claiming
  measurements they did not have. Removing one catch-all exposed a mock that had never
  delegated at all. Round 3 found no hard violations.
- `delegate.sh` for three of five slices (the snapshot helper + tests, `--no-env-file`, the two
  e2e specs), one round each, all exit 0. The orchestrator wrote `PRISTINE_MIGRATION_HOOK_MS`,
  the cache pruning, the `globalSetup` resilience and every review-round fix.

**Two process lessons worth keeping.** (a) After the second flake red the iteration did *not*
re-run into a busy host — that is how rulo parked PR #1814 — it ended `RETRY_LATER` and let the
supervisor's backoff provide the wait. (b) Iteration 11 gated the eventual re-run on "loadavg
back under 15", which on a box four loops keep warm may never happen and would park the PR
forever. Iteration 12 replaced it with the reachable signal: **no more than one build job in
flight**, i.e. a free agent for this build to take. Use that, not loadavg.
