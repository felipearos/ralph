- **P2 1: TV activity years missed quick-marked episodes.** `getUserActivityYears` read `review.watched_at` only, while the TV hero counts `episode_watch_status`, so episode-only years had no chip and a deep-linked year was cleared. (`review.rewatched` is nullable, hence `IS NOT TRUE`.)

## Read this before touching stats queries

- **`src/server/queries/stats.integration.test.ts` is the first PGlite suite for `stats.ts`.** Three things it needs that other suites don't:
  - PGlite's raw `db.execute(sql)` resolves to `{ rows }`, not postgres-js's array, so the suite wraps `execute` in `rowsOf`.
  - `media_metadata` has no replayable CREATE in `./drizzle` (0015 is an ALTER, skipped by `isSupabaseBaselineMediaMetadataMigration`), so the suite creates it, with `UNIQUE (tmdb_id, media_type)`.
  - `SET TIME ZONE 'UTC'` is required: this host is America/Santiago and `EXTRACT(YEAR …)` uses the session zone.
  If a second suite needs `media_metadata`, move that DDL into `src/test/database.ts` as an opt-in helper; `database.ts`'s own comment argues against per-suite copies. I declined the move for one suite.
- **Mutation-checked:** all new regression tests go red against the original SQL, and the round-2 cases go red against the round-1 SQL.
- **Pre-existing gaps, not fixed (possible tickets):**
  - `rangeForStatsYear` ends a year at Jan 1 00:00 of the next year and every hero query uses `<=`, so an entry at exactly midnight on Jan 1 counts in both years.
  - In an episode-only year the TV hero shows `shows = 0` beside non-zero episodes and hours, because `shows` counts review rows only.
  - `getUserDailyActivity` (web heatmap) counts review rows only, so an episode-only year renders an empty heatmap.
