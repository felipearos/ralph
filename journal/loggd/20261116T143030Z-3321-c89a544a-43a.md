## What the unit was, and the verdict

#3321 was a product question — should the Tags directory and a tag's screen follow the
Media Mode — and Felipe answered it on 2026-11-15 in a comment: fully mode-scoped for
shows and movies, on web and mobile, the directory counting only the current mode's
items, Books left to #3317/#3318. So the verdict was not `needs-info`: it was
**oversize**, because the decision reaches the v1 API with its server queries, the web
app and the Expo app — three surfaces, this project's split line.

- **#3517** — the API and the server queries: `{ media: "filter" }` on

## Decisions, and where they came from

Felipe owned the product call. Four mechanical calls sat under it:

1. **Movies gets a titles category of its own** (`category=movies`,
   `/tag/{tag}/movies`), rather than `shows` changing meaning. Cited in `decisions`:
   `CONTEXT.md` Media Mode — "which scopes every surface they reach" — plus the wire
   type's hard-coded `mediaType: "show"` (`packages/shared/src/tags.ts:73-77`). The
   Likes surface already has separate `shows` and `movies` web sub-paths, which is the
   same shape.
2. **Seasons and Episodes stay in Shows mode.** Cited: `src/lib/media-types.ts`,
   `tv: ["show", "season", "episode"],`.
3. **`media=books` reads as `all`**, so the directory and every category answer for a
   preview viewer exactly what they answer today and #3317 stays purely additive. The
   one forced change is the wrapper's refusal for a viewer without the preview — which
   #3317's own body already asks for.
4. **No out-of-mode redirect or 404 on web** — a conformance call, not a product one:
   the profile Movies page has no mode check and only a launch-disabled mode calls
   `notFound()` (`media-mode-gate.ts:18-20`). What follows the mode is the tab set and
   the default-category redirect. At the API an out-of-mode titles category answers an
   empty page, so the endpoint itself is mode-scoped.

Also written in because of my adult-gate lens: the tagged-titles read gains the viewer,
because `hydrateShowBasics` applies no adult gate; the children point at the movie
hydration `getLikedTitles` already uses (`liked-titles.ts:328-366`) and require
`resolved: false` for a withheld or unavailable movie.

## Stages

- **mapper: two calls, both worth it.** The first mapped every route, query, page,
  screen, hook and test, and established that nothing under Tags reads the mode today.
  The second found the thing that changed the web child: this project's convention for
  an out-of-mode surface is to render in place with an empty state, not to redirect, and
  the only page-level 404 is for a launch-disabled mode. It also found that web's
  `modes` tab gate has exactly one user (Following) and that mobile has none.
- **review.spec: three rounds, and each of the first two found real blockers.** Round 1
  (13 findings): the Books scope contradiction; that adding `movies` to
  `TAGGED_CATEGORIES` would show a fifth mobile "Movies" tab listing shows between
  children 1 and 3; a mobile criterion built on a List tag chip that passes its category
  explicitly. Round 2 (3 P1s): child A would red the root typecheck unless it also fixed
  the three web call sites of the queries it re-signs; `getProfileTags`' `HAVING` keeps
  zero-use tags at count 0, which made two seed criteria false on correct code; B's
  Tags-total criterion was self-contradictory. Round 3 (1 P1): the tag route's
  `api-utils` mock is two-argument, so every test in `route.test.ts` fails the moment
  the media argument is passed — the mock must forward it, and the `VALIDATION_ERROR` /
  `MEDIA_MODE_DISABLED` cases belong where the wrapper is real.
  **Third time this role has learned the same thing: on a split whose children assert
  current behaviour, rounds 2 and 3 pay for themselves, because round 1's fixes are
  themselves wrong.** See the #3320 and #2716 entries.
