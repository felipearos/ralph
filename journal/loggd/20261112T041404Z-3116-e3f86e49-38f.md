## Evidence worth keeping (mapper, at `origin/main`)

- **There is no v1 route registry or contract-snapshot file.** Every child's
  "registered with the v1 conformance and contract checks" reads like a shared
  list; it is not one.
  `src/app/api/v1/route-conformance.test.ts`,
  `src/app/api/v1/mobile-api-error-conformance.test.ts` and
  `src/server/db/review-visibility-conformance.test.ts` all **walk the
  directory**. #3030 (`5e2d9b153`) added `books/viewer-state` with no registry
  edit. This is why the five server reads are five groups and not one — worth
  remembering for every future Books-API tree.
- **`FriendsActivityStatus`** (`packages/shared/src/friends-activity-types.ts`)
  is `"reviewed" | "watched" | "watching" | "caught_up"` — no book words.
  Widening it breaks the exhaustive switch in
  `mobile/components/friends-activity-label.ts`, which has **no `default`**.
  #3119 lands first (it blocks #3129), so it owns the fix. Noted in the triage
  comment, not written into any ticket.
- **`packages/shared/package.json` `exports`** takes one appended line per new
  `@loggd/shared/<x>` module, so #3119/#3120/#3121/#3123/#3179 may each append.
  Append-only and trivial; deliberately not grouped on, or all five collapse.
- Movie analogues are TMDB-bound and cannot serve a Hardcover id:
  `src/lib/api/media-subresources.ts` (`parseMediaId` uses `parseInt`,
  `toMediaScope`, `gateAdultMedia`) and `src/lib/api/title-sections.ts`
  (`handleTitleSections`, whose `parseSectionsParam`/`unpack` are not
  exported — #3179 most likely exports them).
- `mobile/app/book/[id]/_layout.tsx` is a bare `<Stack>` with no screen
  entries, so new subpages are just new files (as `app/movie/[id]/(subpages)/*`
  are). **There is no book gate on `main` yet** — #3040 adds it, and it blocks
  #3129/#3131/#3133/#3135.
- `mobile/lib/list-surfaces.ts:144` (`mediaListsPredicate`) only knows numeric
  TMDB ids, so #3133 likely has to edit it.
