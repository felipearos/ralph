## Review findings acted on (review.spec via `ralph-review-spec`, verdict NOT READY, four blocking)

All four were verified against the code before being written up; the reviewer's citations all checked out.

1. **Criterion 6 was unsatisfiable as written.** It asks the scope resolver to answer `MEDIA_MODE_DISABLED` for "every other viewer" on a `media` value naming Books — but only the `filter` wire kind can express Books (`MODE_BY_FILTER.books`, `src/lib/api/media-mode-scope.ts:46`). `MODE_BY_MEMBER_LIST_MEDIA` is shows/movies only (`:49-52`) and the `showsOrMovies` parser accepts only `tv|movie|shows|movies` (`:115-124`); both refuse `books` with `VALIDATION_ERROR` via `refuse()` before the gate, for a preview viewer too. **Verified by reading the file**, not taken on the reviewer's word. Resolved against the ticket's own criterion 9, which pins the member-list contract test green and unchanged — so widening those kinds is forbidden by the ticket itself. **This was not a product decision and needed no `decisions` citation**: the ticket contradicted itself and criterion 9 is the binding half.
2. **Criterion 7 hid a caching rule.** "Takes effect on the next request" is a no-cross-request-cache requirement. It holds today only because `readAccountAccess` is memoised per `Request` in the `bearerRequests` WeakMap (`src/server/auth/acting-member.ts:241,318`). Amended to state the rule, to prescribe a two-request route test, and to put the app's own cached `availableTargets` out of scope.
3. **The migration-seeds-no-grants conflict.** "Felipe's account and the `test` account get the Books preview" reads as a deliverable while criterion 1 says *empty by default* and the Operator step makes the grants the operator's, by account id. A loop holds no account ids and no prod access, so it could plausibly seed them with a `username='test'` subquery — wrong for prod, and it turns an additive migration into a data migration. Amended: column empty, placeholder SQL in the PR body, **and the red migration-ledger check is expected and not the loop's to fix**.
4. **Criterion 8's "each of the requests above" did not resolve** (criterion 2 is a function, criterion 3 is a cost). Amended to name GET and PATCH `/api/v1/users/me` plus one `withAuth` and one `withOptionalAuth` `filter`-kind route.
