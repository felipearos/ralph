## READ THIS FIRST: excluding a reference from the READ does not exclude it from the LOOKUP

The one real bug in this branch, and I shipped it past my own brief. The List detail grid holds title, season and episode entries. I correctly left season/episode entries out of the reference set the provider reads — and thought that was the whole job. It is not. `GridPoster` still called `useViewerMediaStateFor({ mediaType, tmdbId })`, and **a season carries its title's provider id**. So in a List holding both "Severance" and "Severance Season 2", the season poster looked up `tv:1`, found the title's entry put there by the title's own row, and drew the show's watched check and 5-star on the season.

A provider/context pair has two ends. Fencing the *request* end says nothing about the *read* end when two rows share a key. The fix made `GridPoster` scope-aware (`seasonNumber`/`episodeNumber`, title-scope only reads the lookup), which also sets up #1079.

**My own test missed it because the fixture was too convenient**: the season entry I used had tmdbId 42, which was in no other row, so "shows no indicators" passed for the wrong reason. The replacement drives a list where the season and the title share an id, and it fails with the gate removed. *A test for "X does not inherit Y" must put X and Y in the same lookup.*

The **spec axis (opus) found this, not the standards axis, and not the gates.** Typecheck, lint, build and 185 mobile suites were all green over the bug.
