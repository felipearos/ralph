## The four findings worth keeping, whichever branch ships

1. **The row's navigating `Pressable` steals the Watched tap.** React Native's Pressability returns `!disabled` from `onStartShouldSetResponder`, so while this row's Viewer Media State read is unanswered the disabled chip declines the touch and the ancestor row takes it and navigates. A member tapping Watched early is silently sent to the episode screen. I close it by claiming the start responder on the actions strip — responder negotiation is deepest-first on the bubbling start phase, so an enabled chip still wins its own touch.
   **And that fix has a trap of its own**, which the Standards axis caught and I had not: the strip sits in the row's `flex: 1` text column, which stretches its children, so claiming the responder over it made **most of the row a dead tap**. `alignSelf: "flex-start"` is load-bearing, not cosmetic. The repo's own prior art (b6190c0a, `EpisodeCard`) solved the same problem structurally, by hoisting the control out as a sibling of the navigating pressable; the reviewer said decline was defensible for this PR's size but that they would still hoist, and I think they are right in the long run — the invariant is a style property that nothing enforces.
2. **Batch what you draw.** Deriving the batched Viewer Media State references from the page of notifications rather than from the built list fetches a collapsed show group's episodes for rows that do not exist. Taking `NotificationListItem[]` fixes it and makes expansion append a chunk. Trade-off the Spec axis named: the reference list now moves with expand/collapse, so each toggle re-keys the single chunk and unrelated chips blink disabled. Correct, not free.
3. **Three mocks the screen harnesses need.** `LogButton` reads `useRouter()` while the notification screens use the `router` singleton, so the `expo-router` mock must alias both to **one object** or the screen throws on render. The screens mount no `LogProvider`, so `@/components/log/LogContext` needs mocking. And without an `@/stores/auth-store` session mock, `useViewerMediaState` is `enabled: false` — which makes a "no read happened" assertion pass for free. That last one is the #1118 trap in a new costume.
4. **The chip needs the tile's icon-colour state signal.** Both review axes found this independently: the chip drew a white check on both backgrounds, so unwatched read as watched.
