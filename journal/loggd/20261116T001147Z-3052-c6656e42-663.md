## What landed

Home's titles tab in Books mode now draws a "Currently Reading" row above
Trending for a signed-in member: their own Reading shelf, read through the
existing Book Shelves read (no new route), each card showing its Reading
Progress and opening the Book screen. The row is absent whenever it has no
books (pending, first-failed, empty), and a failure never touches Trending or
Popular. It shares the cache entry `["profile", <username>, "books",
"reading"]` with the profile Reading shelf, which is how a status write shows
on Home without a pull.

## Key decisions

- The pull refetches the shelf only once it has answered
  (`reading.isPending ? null : reading.refetch`), following
  `BookShelves.tsx:132`. Without it TanStack's `refetch()` ignores `enabled`,
  and a pull while signed out asked for an empty username — the one P2 all
  three review axes found independently.
- The row draws `pages[0]` only, through an exported `currentlyReadingItems`
  that Home's `bookIds` shares, so the marks read covers exactly the drawn
  cards. The Reading ids go last in Home's single Book Viewer State read.
- Books already drawn survive a failed refetch (hide only when there are no
  entries), following `BookRow`.
- Kept and raised in the PR body as a question: the row's covers draw full
  marks rather than rating alone. CONTEXT.md's own-shelf exception is written
  for the profile page, and rating-only here would cost a second marks read.
- Dropped P3s, stated in the PR body: Home refetches every cached page of the
  shelf; a pull cannot recover the row after `/users/me` itself failed.
- No `CONTEXT.md` change — the ticket settles no new domain term.
