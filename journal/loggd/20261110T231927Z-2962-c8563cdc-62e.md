## The two findings that earned the body edit

Two review passes (`ralph-review-spec`, spec re-fetched between them). Both passes were worth running — the first found two of my points overstated, the second found two citations wrong *and* the finding below, which neither the ticket nor I had.

1. **Criterion 6 is vacuous for criteria 1 and 2 under the obvious mutation.** `diaryMediaCondition` already falls back to the global `enabledMediaTypes()` (`diary.ts:81`), which excludes books. So on the preview-less path "remove the v1 narrowing" removes *nothing*, and the "answers no book row" assertions cannot be made to fail. The mutation must **widen** the v1 path instead (hand every viewer the preview set, or drop the shared fallback for the v1 call). This is `feedback_assert_effect_not_mechanism` in a new costume: the guard proves a mechanism and the absence assertion passes on an unchanged world.
2. **`getCachedUserDailyActivityRange` keys per subject, not per viewer** (`cached-stats.ts:25-33`, `cacheTag(userStatsTag(userId))`), and the cache is **inert under vitest** (`next/cache` mocked at `activity/route.integration.test.ts:27`), so no test can prove the key either way. The remedy is not a test: `use cache` keys on arguments and that wrapper forwards `SkipFirst<Parameters<…>>`, so the viewer's set passed as an argument is keyed automatically. Resolving the viewer *inside* the cached scope is what breaks — at request time, with a clean `next build` (`.agents/skills/next-partial-prefetching-adoption/SKILL.md:83`).

My first draft got (2) wrong in a way worth recording: it demanded a test proving the cache key. Under a mocked `next/cache` that test passes regardless — the draft's own "the one way CI stays green while production is wrong" applied to its own proof.
