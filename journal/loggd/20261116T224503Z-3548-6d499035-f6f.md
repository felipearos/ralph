## The shared-hydrator trap, and the decision I made rather than deferred

`hydrateReviews` is shared with `GET /api/v1/reviews/friends` (`friends/route.ts:16-25`,
same `{ media: "filter" }` wrapper). `getGlobalFriendReviews(…, "book")` already returns
book rows (`community-rankings.media-guard.pglite.test.ts:145`, `:151`) and
`friends/route.test.ts:307-314` already lets a preview holder through — so a book branch
placed inside `hydrateReviews` widens that read too, untested, under no criterion.

My first draft laid out both shapes and handed the choice to the coder. **review.spec
called that ducking, and it was right**: this is a scope question, not a product one, and
the ticket's own Out of scope section already settles it. The posted comment states the
call — build it so the friends read's answers are byte-identical — with the ping to
@felipearosr for a follow-up ticket if he wants books there. Supporting facts: nothing in
`src/` or `mobile/` calls `/reviews/friends` besides its test, and `mapCommonFields`
(`review-hydration.ts:37`) is **not exported**, so a route-local path would have to copy
it; the comment asks for an exported sibling in that file instead, leaving `hydrateReviews`
untouched.

Also worth carrying: under a `books` scope `rankingMediaCondition` makes *every* row a
book, and with no media the ranking is shows and movies only. There is never a mixed page.
My draft's "split book rows out" implied a merge that cannot happen; it now says
"branch on the scope".
