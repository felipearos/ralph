**Decisions worth keeping.**

- **#424's fence is a label, not a marker.** It landed in `frontier-gate.ts`,
  not `frontier/next-tasks.ts`: `adoptedBy` (`:210-227`) reads the
  `<medic>-wip` label on the pull request and nothing else. Written into the
  ticket, because an adoption that does not label the pull request reopens the
  race #415 is about.
- **The closed adopted pull request had no ending.** The body asked which of
  `--state open` and `claimPr`'s re-read catches one; the answer is neither —
  the poll lists open pull requests only (`gate.ts:486`) and a resumed case
  returns at `gate.ts:530`, before `claimPr`. Left there, the `-wip` stays and
  the supervisor keeps renewing that ticket's lease, so under the
  one-lease-at-a-time rule the medic never adopts again for the rest of its run.
  The ticket now requires the gate to release it — but on proof, not absence:
  `PR_LIST_LIMIT` is 40, so a missing pull request is re-read and released only
  when that read succeeds and shows it not open. Pinned in the fifth criterion,
  in `gate.test.ts` rather than `case.test.ts`.
- **The moved draft skip needs `operator: false`.** The first criterion wants
  the resumed check before the `agentOwner` skip, but today the draft skip is
  after it (`gate.ts:248`). Moving the draft skip first is safe only if it
  carries `operator: false` for a non-operator branch, because `idleWhy` counts
  only `operator: true` skips (`gate.ts:422-423`) and the idle line would
  otherwise report a loop's draft as an operator pull request.
- **`migration-applied` ordering, without a ninth checkbox.** The earlier #417
  pass asked that the adopter prefer a `migration-applied` pull request. Folded
  into the fourth criterion rather than added as a ninth, because this project
  calls more than 8 checkboxes oversize and a split here would undo #415's own.
  The gate picks at most one adoptable orphan per poll — labelled first, then
  lowest number — leaving `casesOf` alone, so the preference chooses which
  orphan and never outranks the operator's own red pull request.
- **#432 is deliberately not a blocker.** It creates the `migration-applied`
  label, but the comparator reads a label name and its test builds the fixture,
  so a blocker there would stall #425 for nothing.
