file set, so they cannot be written past each other.

**The overlap accepted deliberately:** #393 meets #396/#397 in
`project-config.ts`, `roles.ts` and `preflight.ts`, and #397 meets #395/#398 in
`clerk/jira.ts`. Those are additive edits in separate blocks (a clerk Linear
target and a clerk label check against a `triage` block, a triager label and a
Jira token check; `clerk/jira.ts` is a client #397 reuses rather than rewrites).
Folding on them would have transitively merged all six implementation tickets
into one group — which is precisely what the legacy tree already does, so the
staffing unit would have changed nothing. The prompt's "when in doubt, share the
group" was weighed against that: a group annotation that reproduces the legacy
fence is not an annotation. #393 ∥ #396 may therefore cost a rebase on a config
hunk; #394 ∥ #395 ∥ #397, which would have cost rewrites of the same functions,
is fenced.
