## Key decisions

- `urgent` is **absent** rather than `false` when unused, so the no-label case
  is byte-identical on every surface. A test pins the exact key set.
- `--take-one` carries `urgent` although the issue named only `--json`: AC 1's
  own surface (`--take-one --dry-run`) prints nothing else.
- `--tree` was restating `readyTasks` (insertion order, no ordering keys), so
  the two terminal views could disagree about which ticket is next even before
  this change. It now reads `orderedGroups`.
- `roles.ts` keeps a second `"priority:urgent"` literal and must: it imports
  nothing from the harness and this module imports it, so an import would be a
  cycle. `triage/validate.ts` had no such excuse and now imports the constant.
- **Nothing writes the label yet** — `roles.ts` only declares it as one the
  project must have. Raised in the PR body as the spec owner's call, with the
  Jav consequence: with routing on, an urgent ticket carrying no difficulty
  label is offered to nobody, and the doctor's filings carry none. Worth a
  follow-up ticket.
