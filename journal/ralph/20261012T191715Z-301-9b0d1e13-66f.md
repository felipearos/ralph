# 2026-10-12 — #301 Dashboard: refuse cross-site writes and unknown Host names

**Outcome: merged.** PR #309, squash-merged as `f34e813`, issue #301 auto-closed.

**What shipped.** The local dashboard has no login by design, so any page in a
browser on this host — or any tailnet device, since `tailscale serve` publishes
it — could POST to every write route (Stop now, clone a repo, open a setup PR),
and with no `Host` check a DNS-rebinding page could read the responses. The
dispatcher now refuses, before any route runs, an unknown `Host` (403
`UnknownHost`, the name on stderr) and a non-GET the browser reports as
cross-site (403 `CrossOrigin`). A client that sends neither header is not a
browser and passes, which is what keeps the bridge relay and `curl` working.
The predicates live in the import-free `dashboard/routes.ts`;
`RALPH_DASHBOARD_HOSTS` carries the operator's extra names.

**Key decisions.**

- *A pre-existing 500 this closes.* Round 2 of the standards review flagged a
  WHY comment claiming a `Host`-less request "falls back to the address Bun
  bound, so it passes". Probed: an in-process `Request` carries no `host`
  header, so the URL fallback is load-bearing for the 17 test files that call
  `createHandler` directly — the review's proposed fix (delete the fallback)
  would have 403'd them all, and was refused. On a real socket with no `Host`
  (HTTP/1.0) Bun hands over a *relative* url, so `new URL` threw and the server
  answered 500 with Bun's dev error page, ~50 KB quoting source and cwd.
  `hostFromUrl` + `URL.canParse` makes that a 236-byte 403, pinned by a
  raw-socket assertion. An absolute-form request line cannot smuggle a host
  through the fallback — checked.
- *Port strip on `RALPH_DASHBOARD_HOSTS`:* the refusal prints the raw `Host`
  with its port and tells the operator to paste it back; without the strip it
  could never match.
- *`"::1"` dropped from `LOOPBACK_HOSTS`:* dead, since the port strip turns a
  bare `::1` into `::`. Behavioural no-op; `[::1]` is what browsers send.
- *Review findings refused, with reasons both axes accepted:* renaming
  `sameSiteWrite` (an acceptance criterion names the export verbatim — worth a
  follow-up ticket), `notFoundPage` for page paths (choosing a body by path
  shape is routing, and the criterion says the refusal precedes any route),
  rewriting `agents-http.test.ts`'s fixture URLs (the plan prescribes injecting
  `hosts`).
- *Residuals named in the PR body, not fixed:* cross-site GETs can still cause
  work (SSE, usage spawns) though CORS hides the responses; behind
  `tailscale serve` the `Origin` fallback would refuse a legitimate write from a
  browser that sends no `Sec-Fetch-Site`; standalone `bun lineup/server.ts` is
  outside the gate.
