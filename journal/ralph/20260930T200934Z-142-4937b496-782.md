## What the change is

`triage-apply.ts` plus a `triage/` directory — the one place a triager's GitHub writes are made.
The triager model never runs `gh issue edit`, `create` or `close`; it writes a plan to
`.ralph/logs/triage-plan-<unit>.json` and this tool validates, simulates, orders, applies, verifies
and releases it. A refusal makes zero GitHub writes, because a half-applied split is a backlog
nobody can reason about. Modules: `plan.ts` (types + structural parse), `validate.ts` (pure rules,
every world fact injected), `simulate.ts` (the frontier the plan would leave, from the real
`buildTickets`/`classify`), `order.ts` (the split recipe as phases), `apply.ts` (paced, idempotent,
body-reversible writes), `body.ts` (one-section edits and op markers), `ledger.ts` (append-only
replay log). Also `claim-lease.ts` gains `releaseLease` and a `release` command, and
`frontier/next-tasks.ts` exports `READY_LABEL`/`SPEC_LABEL` instead of having them re-declared.

## Key decisions

- **The §7 release marker deviates from the issue deliberately.** Spelled literally as
  `<!-- ralph-triage v1 loop=… -->` it would not parse in `triage-marker.ts`, so `hasCurrentTriage`
  would never see the decision and every triaged issue would sit in the intake bucket forever. The
  fields ride as extra keys on the format that module already reads, percent-encoded so a label like
  `good first issue` cannot break it. Both review axes judged the deviation defensible.
- **`unblock` is not implemented** — #150 owns it, and an op name with no implementation behind it
  is configuration that looks live.
- **Lease release is best-effort** and non-fatal; the TTL covers a failure, and aborting there would
  leave the `-wip` off with no marker.
- **Known gap, stated in the PR rather than papered over:** the `frontier/next.ts --dry-run --json`
  subprocess is not driven in a test, because it materialises its payload from the harness's
  `origin/main` and a test of it would be a network test. `frontierVerdict` and `release` are
  exported and directly tested instead.

## The local review earned its keep

Nine real defects, all fixed before the PR. The first would have parked the frontier for every loop
on the project: a created issue's op marker was **appended**, landing inside the body's last
section — for a split child that is `## Staffing group`, whose content `parseStaffingGroup` requires
to be one kebab-case word. It throws, `buildTickets` calls it for every body, and no revert could
undo it, since only `set-section` ops keep a before-image. Also: `append` was not a fixed point and
the section skip compared against a raw CRLF body (a rerun duplicated acceptance criteria on any
issue GitHub's web editor had touched); `applySection` collapsed blank lines across the whole body,
rewriting authored fenced blocks; the release marker was posted unconditionally, so every rerun
added another while reporting zero writes; `labels=` was unencoded; `add-blocker` and `close` had
ledger-only idempotency; the tool's own `duplicate` label bypassed every label rule; the write cap
counted `plan.ops` rather than the writes ordering derives; and a non-zero `next.ts` exit read as
"the frontier cannot read this", so a throttled census would have reverted a correct apply. The
spec axis found AC 5 argued in a comment rather than enforced — `stepwiseRefusals` enforces it now,
substituting and classifying after every ordered write.
