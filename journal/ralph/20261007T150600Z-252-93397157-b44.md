## What landed

The server half of the unblocker chat. `dashboard/chat.ts` resolves the Claude
session behind a halted loop or a blocked ticket, forks it, runs the turns and
streams them back through the live pane's redactor into
`.ralph/logs/chat-<id>.jsonl`. `dashboard/chat-routes.ts` serves the four
routes plus DELETE under `/api/p/:project/`. No UI (#256) and no modes (#253,
#254): v1 refuses every tool.

## Key decisions

- **The issue's premise is wrong, and the code now says so.** The
  `=== … session <uuid> ===` header lives in the SUPERVISOR log, not the
  iteration log. The join between a loop and its session is the timestamp in
  the iteration log's *name*.
- **Journal entries are deliberately not a resolution source.** They live in
  the harness repo and their filenames carry only a twelve-character session
  fragment, which is not resumable.
- `read-only.test.ts` refused a SIGTERM handler in `server.ts`: signalling is
  reserved to `interrupt.ts`. The chat's cancellation goes through that module.
- The fake-claude test fixture numbers its argv files instead of using
  `mktemp`, so the assertions can address a specific turn.
