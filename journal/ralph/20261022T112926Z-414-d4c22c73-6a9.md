## What I decided and why

#414 ("an errored loop is never retried") arrived unlabelled with 5 ACs, so the
frontier gave it to intake. The mapper confirmed nothing of it is on `main`:
`dashboard/reconcile.ts`'s `decide()` refuses every non-null `stopReason`, and
`reconcile.test.ts` pins all four stop kinds as "decisions, not deaths". But
the work crosses three of this project's areas — supervisor (`ralph.sh`,
`preflight.ts`), durable state (`loop-state.ts`), dashboard — so it is oversize
by `CLAUDE.md`'s own count, and the verdict is a split rather than a promotion.

Children, in dependency order:

- **#418 supervisor** (`ready-for-agent`, group `supervisor`) — widen
  `checkDopplerScope` so a transient read is `unavailable` (the loop waits in
  place) and keep the raw Doppler output in the denied reason; record the
  failing check NAMES in durable state; records for the secrets-env failure
  (today `exit 1` with none) and for the usage-limit no-sigil ending; one alert
  bounding an unbounded `preflight-wait`.
- **#419 loop-state** (`ready-for-agent`, group `loop-state`) — "when the loop
  last finished an iteration", carried ACROSS runs as a documented exception to
  `applyRecord`'s run boundary, plus `lastEvent` on `LoopStateReport`.
- **#420 reconcile** (no state label, group `reconcile`) — the retryable set
  read from `lastEvent.name`, the 5/15/45-then-hourly seven-attempt schedule
  under its own `loop-retried` record kind, the capped escalation, e2e.
- **#421 dashboard** (no state label, group `reconcile`) — the retries on the
  loop card.

**#420 and #421 deliberately carry no state label.** A plan cannot name an
issue number that does not exist yet (`add-blocker.issue` must be a real
number, only `blockedBy` may be a ref), so the edges #420←#418,#419 and
#421←#420 could not be written in the plan that created them. Shipping them
`ready-for-agent` would have left them unfenced, so they went out unlabelled —
no coder is offered them — and their `## Blocked by` says the next triage pass
records the native dependencies and promotes them. **That is the next
triager's first job**, and it is cheap: two `add-blocker` ops plus
`ready-for-agent`, once #418 and #419 exist (they do).

## Decisions cited

`preflight.ts` design note 3 — "Denied and unavailable are different answers" —
settles the boot case: a Doppler API that cannot be reached is a wait, not a
refusal. The loops stopped at 08:19 only because `checkDopplerScope` falls back
to `denied` for any output `UNAVAILABLE_EVIDENCE` does not match. Fixed twice
over on purpose: #418 widens the classification AND #420 still retries a
`preflight-denied` whose failing checks are all `doppler-scope`, which is the
mechanism the issue itself asked for.

Other decisions, all in the issue comment: the retryable set is read from
`lastEvent.name`, never the stop kind (an operator's orderly stop is also
`failed`); the usage-limit no-sigil gets its own event name, because
`kindFromExit` makes `runner-error` the fallback for every non-zero exit and so
cannot separate them; the new schedule is a second path with its own record
kind, because the dead-supervisor path's attempts are deliberately unspaced for
#346; a stretch is delimited by when the loop last finished an iteration, not
by `stopReason.at` and not by run identity.

## Spec review

Seven rounds of `ralph-review-spec` against the fetched issue. Worth knowing,
because each round changed the product:

1. The first draft would have retried genuine expired-auth denials by check
   name, ignoring preflight's `denied`/`unavailable` split.
2. Fixing that at the source dropped the issue's own retry mechanism and left
   no fallback if a future Doppler message reads as denied — so the final spec
   does both.
3. Three rounds on the retry count: keying it off `stopReason.at` reset the
   schedule for ever (cap never fires); keying it off "the run that stopped
   finished no iteration" let a stretch capped last week swallow tonight's
   outage; keying it off "which run the attempt started" had a hole on either
   side, because a refused start leaves no new run. The rule that survived
   names no runs at all: count the `loop-retried` records raised after the
   loop last finished an iteration.

A review brief for this role has to BE the change — there is no diff — and the
reviewer needs the mapper's codebase facts in the brief, or it re-derives them
every round.
