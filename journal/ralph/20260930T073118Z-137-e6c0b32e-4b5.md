F5 of the roles foundation (parent #130, row 6).

**What shipped.** A role declares its intake as descriptor fields in `roles.ts` (`intakeGate`,
`frontierBucket`, `javRouted`). `frontier/next.ts --take-one --role <role>` dispatches to that
role's bucket under the same claim lock, label and lease as before. `claim-lease.ts claim <n>
[--label <l>]` claims a single issue by number outside the frontier, exiting 3 when the ticket
is already held. `ralph.sh` runs the gate the role declares, reads the case off whichever
gate's verdict line answered, and exports it as `RALPH_INTAKE_CASE`. A coder's behaviour is
unchanged by construction: the flag defaults to `coder`, JSON keys are untouched, and the probe
argv is byte-identical.

**Key decisions.** Intake lives on the role descriptor rather than in a supervisor `case`
statement, so adding a role does not edit `ralph.sh`. Claim-by-number reuses the existing lease
rather than a second locking scheme, which is why it can exit 3 on a held ticket. The
supervisor reads the case off a generic verdict line so any gate can answer, not just the
coder's frontier.

**CI took two rounds, and round 1's red was a real bug in a test fixture, not a flake.** Head
`e21f708` failed `dashboard/adapter-performance.test.ts > retries after a shared snapshot fails
instead of retaining its rejection` with `RalphContractError: frontier contract drift: stdout
was not JSON` — a file this diff does not touch. The cause: that test rewrote the fake `bun`
shell script *in place* while children spawned by the two failed reads were still executing it.
`writeFileSync` truncates first, so a child `sh` could read half a script, exit before its
trailing `exec bun "$@"`, and hand the adapter empty stdout. `d84e0b1` fixes it in
`dashboard/fixtures.ts`: `fakeBun` writes to a staging path and `renameSync`s it over, so a
running `sh` keeps the inode it opened and every reader sees one whole script or the other.
`adapter-performance.test.ts` now restores through `f.fakeBun(original)` too. CI's runner takes
406s where this host takes 124s, which is why the window opens there and not locally — it never
reproduced here in 5×3 runs on the unfixed commit. Round 2 green: 2787 tests, `test` the only
required check.

Two traps around that trap. **In zsh, `env $unsetargs …` does not word-split** — an earlier

polluted shell reproduces the same 121 failures: useful for "not my code", useless for "not the
environment", because both runs are polluted identically. Clear first, then compare. `git push`
needs the same treatment or the pre-push hook fails on the same pollution — and
`RALPH_SKIP_PRE_PUSH=1` is not the answer (§5.6 forbids prefixing a gate's override, and the
