# 2026-10-03 — #159 CI doctor: create and claim a case's ci-health issue

**Outcome: merged.** PR #218, squash-merged as `2fb55ff`, issue #159 auto-closed.

**What shipped.** `ci-doctor/case-issue.ts` (~640 lines) plus its test (46
tests) and a README section. The doctor finds or creates the case's
`ci-health` issue — identity is a sha256 prefix of the case key carried in the
issue body — claims it through `claimByNumberWithLock`, and on a second failed
fix releases the claim and relabels the issue for the coders. CLI surface:
`ensure` / `file` / `fix-failed`. `claim-lease.ts` gained one export,
`withLeaseStoreLock`.

**Key decisions.** (1) The issue is created with `ci-health` alone: the ticket
asks for `doc-wip` at creation, but `loopClaimObstruction` would then refuse
the very claim the ticket mandates. (2) AC 1 is satisfiable only as "never
OFFERED", so the test asserts it on the frontier's buckets rather than its
rendering. (3) AC 3 holds per git common dir; `fileForCoders` takes no case
lease. (4) The doctor owns its `gh issue list` rather than reading the gate's
registry. (5) The branch/phases/`doc-done` lifecycle belongs to #157 and is
deliberately not implemented here.

**The review round that mattered.** Round 1 released the claim AFTER
relabeling; round 2 found that order wrong and inverted it. The failure mode
it avoids is worth remembering: a ticket offered in READY that nobody can
claim. Releasing first is the safe order.
