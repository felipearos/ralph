## What the evidence changed about the ticket's own diagnosis

The ticket's **What to do** says: for each of the three tests, find the
fixed-time assumption and replace it with a predicate wait. That is wrong for two
of the three, and the CI logs say so. `gh run view --log-failed`:

- run `39441760438` (`b4a88ac`): `codex-executor.test.ts:175:84`,
  `AssertionError: status 0; stderr: : expected '' to be 'M src/app.ts'`
- run `39443046745` (`06c115f`): `codex-executor.test.ts:131:27`,
  `expected '' to be 'M src/app.ts'`

Both are assertion failures, **not** timeouts: the script exited 0 with empty
stderr and the sandboxed `git status --short` reported a clean worktree. A mapper
pass confirmed there is no fixed-time element to replace in that half at all —
`codex-executor.sh` has no `sleep`, `timeout`, `kill` or `trap` in its 241 lines,
and the only budget is the 30 s `subprocessSuite(...)` at
`codex-executor.test.ts:29`, which neither case came near. Only
`experiments.test.ts:131-142` matches the ticket's premise, and it has two fixed
assumptions, not one: the hardcoded `1000` ms passed to `runCommand` and the
single unwaited `/proc/<pid>/stat` read at `:136-141`.

The managed sections carry that split, and say explicitly that **What to do**
holds for the third case only, so the coder does not go hunting for a settle
window that does not exist.

## What three rounds of spec review bought

`ralph-review-spec` against the fetched issue (`.ralph/logs/spec-353.md`) with
the proposed text pasted into the brief as the change under review
(`brief-353-ready.md`, `-r2.md`, `-r3.md`). Round 1: 7 findings, 2 high. Round 2:
2 blockers. Round 3: no blockers, 5 one-line edits, all applied.

- **A fixture-only fix would have hidden a production defect.** The fixture's two
  versions of `src/app.ts` are both 20 bytes, so a coder could have made the
  flake vanish by changing the edit's length. The criteria now put the fix in
  `codex-executor.sh` unless the PR proves a real executor run cannot hit the
  cause, and forbid loosening either `M src/app.ts` expectation.
- **"Ten green runs" cannot tell fixed from unfixed** for a case that failed
  about once a day, so a deterministic regression case that fails on
  `origin/main` is its own criterion.
- **`utimesSync` alone cannot force the stat cache:** it moves ctime to now and
  git compares ctime unless `core.trustctime=false`, and ctime cannot be set from
  userland. Written into the criterion so the coder does not lose a round to it,
  together with the back-date-before-`git add` note (a commit landing in the same
  tick smudges the racily clean entry and `main` reports `M` anyway).
- **The `child.pid` predicate asks for a positive integer, not for the file to
  exist:** the shell's `>` creates it before `echo` writes, and `Number("")` is
  `0`, whose `/proc/0/stat` raises ENOENT — which the dead-check counts as dead,
  so the test would have passed while checking nothing.
- **The load criterion demands `--reporter=verbose` proof the codex cases ran**
  rather than skipping on `describe.skipIf(!canSandbox)`: a skip reports the file
  as passing.
- **A stated negative outcome** on the first criterion (hypothesis ruled out with
  evidence, codex half to a linked follow-up) keeps the ticket finishable in one
  iteration if the cause does not fall out. Merging two criteria into one kept the
  count at eight — a ninth would have made it oversize by this project's own rule.
