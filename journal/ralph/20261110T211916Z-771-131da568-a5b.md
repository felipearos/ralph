## What I decided and why
The ticket asks the supervisor to sleep after an `ALL_BLOCKED` and check the
frontier cheaply in shell instead of starting iterations. The mapper found that
is already what a `start.sh` loop does, so there were no acceptance criteria to
write without the filer choosing which residual gap they meant — `needs-info`
rather than `ready-for-human`: the questions are the filer's to answer in a
sentence each, not a design nobody has rules for.

## Mapper evidence (origin/main, citations re-checked by hand in ralph.sh)
Already implemented:
- ``ALL_BLOCKED`` handler `ralph.sh:2989-2995` calls `wait_or_stop`, which sleeps
  one interval (`control_sleep`, `ralph.sh:1790`) and `continue`s — it does not
  spawn.
- The loop then blocks in a model-free shell poll on the intake gate,
  `run_intake_gate` (`ralph.sh:2510`) = `frontier-gate.ts` blocking mode
  (`:1215-1263`); probes are read-only `gh`/`git`, cheapest first (`:929-996`).

  the ungated path (`ralph.sh:2595-2616`).

  Documented in the header comment `ralph.sh:96-104`.
- `backoff.ts:15-22`, `:305-329` — no trigger keyed on an empty frontier.

Genuinely missing:
1. Gate-vs-iteration disagreement: gate says work, iteration says `ALL_BLOCKED`,
   supervisor sleeps one interval and spawns **another** iteration on the same

   `:1776-1785`). Nothing waits for the gate's answer to change. This, not a hot
   spin, is where the idle Opus turns the ticket counts come from.
2. Ungated `ralph.sh N` still exits on `ALL_BLOCKED` (`ralph.sh:1763-1767`), by
   design.
