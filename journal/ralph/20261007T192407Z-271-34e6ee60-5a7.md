# 2026-10-07 — #271 Tests leak temp dirs into /tmp until it runs out of inodes

**Outcome: merged.** PR #273, squash-merged as 347a6d0, issue #271 auto-closed.

**What landed.** `/tmp` had hit 99% of its inodes because 112 test files call
`mkdtemp` and nothing removed what they made. `test-tmp.global.ts` now gives
the whole run one root under the host temp dir, points `TMPDIR` at it, and
removes it on teardown — which relocates every `mkdtemp` in the suite and every
child a test spawns into that root. `test-scratch.ts` adds `scratchDir` /
`fileScratchDir` for per-test and per-file dirs; `test-config-home.setup.ts`
and the suites behind every prefix in the ticket's table use them. The guard is
two-part: `test-mkdtemp.ts` statically flags a test source that makes a temp
dir and names no removal (or imports `scratchProject` without draining the
fixtures), and `test-tmp.global.ts` runs a census of the run root that fails
above `LEAK_CAP`, naming the offending prefixes.

**Key decisions.**
- A **host-wide "/tmp grew" check was rejected**, twice. Five loops and the CI
  runner share this box; during one measurement the ralph runner was itself
  running vitest on `main` (which still leaked) and its 173 directories read as
  this run's growth. The ticket allows the static guard *or* the growth count —
  this takes the static one plus a census scoped to the run's own root.
- **AC 2's first fix was wrong and the local review caught it.** Keying the
  config home by `process.pid` does nothing: vitest's forks pool gives every
  test FILE its own process, so it was still one directory per file. It is
  `mkdtemp` + `afterAll` now.
- `afterAll` hooks run **LIFO**, which is what makes a setup file's cleanup run
  after the test file's own hooks. Pinned by a test in `test-scratch.test.ts`.
- `removeScratchDir` lives in `test-tmp.ts` (vitest-free) and is re-exported
  from `dashboard/fixtures.ts`. Its `attempts` parameter is named, because
  `.forEach(removeScratchDir)` had been passing the array index as the retry
  budget.
- Left alone deliberately: the ~90 `mkdtemp` sites that already clean up.
