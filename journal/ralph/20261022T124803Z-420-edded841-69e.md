## What I decided and why

#420 ("reconcile: retry an errored loop on a capped, spaced schedule and
escalate when it is spent") is the third child of spec #414. It arrived with no
state label on purpose: the split plan that created the four children could not
name an issue number that did not exist yet, so its `## Blocked by` was prose
asking the next triage pass to record the edges and promote it. Both blockers
have since merged — #418 (PR #426, a73683c) and #419 (PR #422, 4e69eec) — so
the promotion was due. Verdict: **ready**.

A mapper pass over `origin/main` confirmed none of it is built: `decide()` still
returns `restart: false` for any non-null `stopReason`
(`dashboard/reconcile.ts:340-342`), there is no `loop-retried` kind in
`NOTIFICATION_KINDS` (`push-notification.ts:48-84`) or `RECONCILE_SURFACE`
(`dashboard/reconcile.ts:73-80`), there is no retry schedule or
`RALPH_DASHBOARD_RETRY_SCHEDULE`, and nothing reads `lastEvent` to tell a
retryable ending from a final one. The inputs the criteria need DO exist, which
is the whole point of the two merged siblings: `lastEvent` (`loop-state.ts:273`),
`lastIterationEndAt` (`:300`), and the refusing check names in the
`preflight-denied` detail (`ralph.sh:2006`, with `doppler-scope` a real check
name at `preflight.ts:871-885`).

Not oversize: 8 criteria, and one area — `decide()` and its bound in
`dashboard/reconcile.ts`, two notification kinds, new `push` flags,
`dashboard/README.md`. Not `ready-for-human`: no secrets, no host state, no
criterion measured on a live loop (every one is pinned with an injected clock).
Jav is off here and lists no labels, so no difficulty label was applied.

## The criteria were rewritten, not merely promoted

#420 carried no state label, so its `## Acceptance criteria` were mine to
replace, and two rounds of `ralph-review-spec` found four gaps that would each
have let two coders write different passing tests. `## What to build` gained a
"pinned by triage" block and the criteria are written against it:

1. **Where a gap starts** was unspecified for attempt 1. Seven gaps for seven
   attempts means a gap before every attempt, so the first needs an anchor, and
   the body's "do not key the count off `stopReason.at`" reads at a glance as
   forbidding the only candidate. Pinned: the first gap runs from the stop that
   opened the stretch; every later gap from the previous attempt's own
   `loop-retried` record; the COUNT still comes only from those records and
   `lastIterationEndAt`, exactly as the body already said.
2. **How an attempt's three values are carried** was "a form a reader can get at
   without parsing prose", and no such field exists: `PushInput` and the raised
   `FeedLine` (`push-notification.ts:111-145`) have nowhere to put them. That
   left two incompatible shapes (new fields, or packing them into the occurrence
   id) and #421 reads exactly these three values, so it is a contract between two
   tickets. Pinned: `retry: { attempt, of, cause }` on the raised feed line, set
   through new `push` flags. Pinned in #420 only — #421 already defers to it
   ("the record carries the first three") — which is the same trick that worked
   on the #417 split.
3. **The capped record gets its own kind, `loop-retry-capped`.** The body left
   the choice conditional ("reuse `loop-restart-capped` if the record can be told
   apart"). It cannot be: the dead-supervisor path takes its last alert from
   `raisedAt(feed, "loop-restart-capped")[0]` and dedupes against it
   (`dashboard/reconcile.ts:538`, `:549`, `:579-580`), so a record raised by the
   new path would suppress that path's own alert, and preventing it would mean
   rewriting `pastAttempts` — which criterion 5 ("the dead-supervisor path is
   unchanged") forbids. Criterion 6 now tests non-interference both ways, and
   criterion 5 names the one existing test that must change: the
   `RECONCILE_SURFACE` `toEqual` shape test at `dashboard/read-only.test.ts:571-579`.
4. **A missing signal is not retried.** `ralph.sh:2008-2010` records a
   `preflight-denied` with no `--detail` when `preflight_failed_checks` comes
   back empty (and that helper swallows its own errors), so "the recorded failing
   checks are all `doppler-scope`" is vacuously true of an empty list and a
   straight `every()` would retry an unknown denial. Criterion 1 now requires a
   non-empty list and pins as never-retried: the empty case, a `failed` stop with
   no `lastEvent` at all, `gate-broken`, and an unknown event name.

Smaller review notes folded in: criterion 1 names `lastEvent.detail` as where
the check names live, scopes `control-stop` to the kinds it actually records
(`completed`, `blocked`, `failed` — `controls.ts:235-237`; `stop-now` records
`interrupted`, already covered), and cites the existing test by its `it` title
rather than by an internal comment; criterion 2 requires positive integers and a
test of the override itself; criterion 4 says an unparsable `at` is ignored
rather than fatal, erring toward one more attempt as
`dashboard/reconcile.ts:539-547` already does; criterion 7 notes the injected
clock must be set relative to real time, since the records are stamped with
wall-clock.

## The decision, with evidence

One product question, decided from a documented rule and carried in the plan's
`decisions`: whether an unreadable `preflight-denied` is retryable, and what a
malformed `RALPH_DASHBOARD_RETRY_SCHEDULE` falls back to. `CLAUDE.md`:
"malformed signal falls back to existing behaviour, never to a stuck loop." The
first half says an unreadable denial is not retried; the second says a bad
override still retries on the DEFAULT gaps rather than not at all, because a
loop down in silence is the stuck loop that rule forbids.
