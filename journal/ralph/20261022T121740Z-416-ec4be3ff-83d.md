## The decisions, with evidence

- **A check-level key cannot identify a cause.** loggd runs its whole pipeline
  behind one required check (`fixtures/loggd/.ralph/config.json:28`), so
  `check:buildkite/loggd` would merge two unrelated reds into one shared wait
  and one false escalation. Hence `ci:<check>:<step>`, and hence a
  supervisor-DERIVED key is recorded `shared: false` and never joins the store:
  the supervisor can see a failing check name (`pr-wait.ts:59-73`) but never a
  step, which lives only in the ci-doctor's Buildkite store and `bk-log`.
- **"Once" has to be claimed in the shared store**, the way
  `ci-doctor/gate.ts:844-853` does it, not in the pusher. The same argument
  forced `exhaustedNotified` and a `backoff-exhausted-shared` record into #431:
  N loops exhausting together would otherwise be 2N pushes.
- **A green `main` is not automatically a clear.** The base-branch probe is
  armed only when the episode recorded the check already FAILING on the base
  (`baseFailing`); otherwise any unrelated merge wakes every loop, each rejoins
  on its still-red PR, and the rejoin opens a new episode that escalates again.
- **The flake path (`prompt.md:713-716`) is deliberately out of #428.** A key
  of `ci:<check>:test` would merge two unrelated flaky tests; a flaky test is
  the ci-doctor's (felipearos/ralph#155), not a shared external blocker. Two
  prompt sites are changed, not eight, and the four throttle-only role prompts
  are untouched: a GitHub throttle is not a shared blocker.
- No `decisions` block in the plan: every call above is forced by code the
  mapper cited, and #416's own text settles the rest ("or the same blocker
  reference in the RETRY_LATER handoff" is why `ref:` is a key form).
