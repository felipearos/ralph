## What changed
In `dashboard/server.ts`, the project handler keeps the last successful runtime snapshot for `RUNTIME_REUSE_MS` = 4000 ms, measured from when the read started, which is under `POLL_MS` (5000), so the poll interval's freshness promise holds. Concurrent requests join the adapter's in-flight read. A WeakMap dates each joined read by its first caller's start and generation. A non-GET request bumps the generation, so a snapshot read before a write is never kept. `freshDashboard` (the stream's recompute) always reads afresh. `compose.ts` and `preview.ts` pass the setting through; reuse is off in preview. README updated. `server-handler.test.ts` pins the read count for a `/loops` + `/controls` pair.
