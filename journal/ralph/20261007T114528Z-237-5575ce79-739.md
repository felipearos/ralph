## What the change does

A jest `● describe › test` block names no file, and `identify` resolved one only
when the job's digest named exactly one test file — so every failure out of a
mobile job (hundreds of files) landed `file: null` with a test id of just
`describe > test`. Three commits:

- `315287d` slice A — `bk-log.ts` attaches jest's `FAIL <path>` header to each
  `●` block (`Failure.file`, `TEST_FILE_HEADER`); `identify(title, files, file?)`
  prefers it; call sites `ci-doctor/scan.ts:140` and `ci-doctor/known.ts`.
- `6b71532` slice B — new `ci-doctor/rekey.ts`, called from `applyBatch` after
  `prune` and before `classify`/`mergeCases`: AC 2's rekey of cases stored
  under the old bare key.
- `a12d007` slice C — the three ways a rekeyed case still paged twice, found by
  the local two-axis review.

## Key decisions

- The file travels as structured data, not inside the `●` title: the title is
  what the digest dedupes on and what verdicts are looked up by.
- **AC 2 is a real rekey; "let it age out" was never available.** `prune`
  prunes builds, failures, `jobsSeen` and metrics — never `cases` — and
  `mergeCases` keeps every `MANAGED_STATES` case and every `confirmed` flake
  for good, so a `filed` case under the old key never retires. The first
  implementation's comment claimed otherwise; the review caught it.
- **The identity lives in TWO places and both had to move.** The store's half
  is the case key; GitHub's half is `caseToken(key)` in the issue body, there
  deliberately so AC 2 survives a lost store. `readCaseIssue` re-checks the
  marker against the key it was asked about, so a rekeyed case read its own
  issue as somebody else's and `ensureCaseIssue` opened a second one. Fixed
  with `Case.filedAs` as a one-time bridge plus a re-stamp of the body; the old
  marker stays so a doctor on an older deploy still finds the issue.
- The rekey also moves `store.leases`, a `parked:<n>` case's `unparks` keys and
  its `rule`, `retries.byCase` (keyed by test id) and `reverts[*].case`.
- The digest now dedupes by file AND title. By title alone, two files sharing a
  describe title in one job collapsed to one row carrying the FIRST file — with
  slice A that is worse than the old drop, since it names a file the failure is
  not in and `greenNextWithoutTouching` then tests the wrong path.
- No `CI_HEALTH_VERSION` bump: it would discard the live 72-hour window and the
  `filed` state the rekey exists to preserve. `filedAs` is optional and absent
  on every case never rekeyed.
- `infra:` and `parked:` keys are never rekeyed — a signature and an issue
  number, neither a test id.

## Known limits (both recorded in the code)

- A vitest row can be the single claimant of a jest bare id: the ambiguity
  guard refuses two files, not one wrong file, and nothing in the store says
  which runner a row came from. Accepted residue, reason in `rekey.ts`'s header.
- `gate.ts`'s `testIdOf` resolves only the FILE from the new `— <file>` suffix,
  so `actionable` misses the `flake:<file> > <test>` key. It missed the same way
  before (resolved to null), so nothing regresses. Its own ticket.
