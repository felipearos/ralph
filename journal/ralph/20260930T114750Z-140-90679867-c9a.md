## Key decisions

- The four sigil literals in `ralph.sh` stay byte-identical (`phase.test.ts` pins
  those lines) and are narrowed after. `has_sigil` refuses an empty pattern,
  because `grep -E ''` matches every line. The literal `<ralph>X</ralph>` reads at
  the end of the loop needed `stop_sigil_seen` too — narrowing `STOP_SIGILS`
  alone would still have settled a ci-doctor's `COMPLETE` as a drained backlog.
- A `gate` secret and each secret's check export INSIDE a subshell. An
  `env NAME=value …` prefix would put the credential in argv, where `ps` shows it.
- `manager: false` also drops `development-env.sh` from `RALPH_ENV_FILTER`: with
  nothing injected, the project's env check would refuse every triager start.
- `RESUME_PHASE`/`RESUME_AFTER`/`RESUME_PROMPT`/`RESUME_WHY` are cleared in the
  iteration body, not only inside `phase_resume`, which a phaseless role never
  calls (`set -u`).
- Deferred, each named in a comment: `preflight.ts` still asks for the project's
  secrets manager for a role given no environment (#158), and `budget_handoff`'s
  prompt is still coder-shaped.

## For the next iteration

- **This project has no merge queue.** No `mergeQueue` key in `.ralph/config.json`,
  no `.mergify.yml`, and `ralph.sh` renders an empty enqueue block, so §5.6's
  enqueue path does not apply here: merge directly with `gh pr merge --squash`.
  Handing back `AWAIT_PR <pr> merge` on this repo waits 60 minutes for a merge
  nobody performs. The §5.6 prose that forbids `gh pr merge` describes loggd's
  hook, not this repo, which has only a `pre-push` hook.
- **`Closes #140` did not auto-close the issue.** Always re-read the issue state
  after merging rather than trusting the link; #140 was closed by hand.
- Run every gate and `git push` with `RALPH_*` cleared — the loop's own
  environment fails 121 tests, and the pre-push hook runs the suite.
- `ralph.test.ts` copies an EXPLICIT file list into its scratch `$RALPH_HOME`, and
  the fake `bun` needs a `*role-behaviour.ts) exec REAL_BUN` branch; the fake's
  default branch answers as the gate, so without it the supervisor evals gate prose.
- `dashboard/interrupt-channel.test.ts > ends a loop mid-turn …` flaked once under
  full-suite load (`supervisor unknown` from `loop-state.ts`); it passed alone and
  on two further full runs. Not this diff, but a candidate for a real fix.
