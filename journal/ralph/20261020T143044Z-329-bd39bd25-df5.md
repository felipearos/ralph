## What the spec review changed

Two rounds of `ralph-review-spec` against the fetched issue
(`.ralph/logs spec-329.md`), with the proposed child bodies pasted into the
brief as the change under review (`.ralph/logs/brief-329-split.md`, then
`-r2.md`). Round 1: 14 findings, round 2: 5 against the rewrite. Coverage of the
parent was confirmed in both rounds. What the findings bought:

- **The bound would never have tripped.** `push-notification.ts:416-418` drops a
  second push under the same `<run>:<occurrence>` key, and a loop that dies
  before writing a new `state.json` keeps the old run id — so counting restarts
  from the feed records one restart however many happen. #346 now specifies an
  occurrence key carrying the attempt's timestamp, and a test whose fixture
  keeps one run id across three restarts.
- **`prepareStart` refusals.** First draft said a refusal "counts against the
  bound" while the bound counted only successes: a loop the gate keeps refusing
  would re-read git every 60s for ever. Now every ATTEMPT writes a record with
  its outcome, so a refusal is counted and capped like a failure.
- **`classifyLoop` is wider than the issue's words.** It also answers `stale` for
  liveness `unknown` with an old heartbeat. "Restart what it calls stale" would
  restart a loop whose supervisor may be alive, so #346 restarts on `stopReason`
  null AND liveness `dead`, and tests the `unknown` case explicitly.
- **The GUI may not import ralph TypeScript** (`dashboard/read-only.test.ts`), so
  the push is a pinned CLI invocation with `RALPH_STATE_ROOT`,
  `RALPH_LOOP_NAME` and `RALPH_RUN_ID` set — unset, `push()` records
  `run: "adhoc"` and `loop: null`.
- **`--collect` does not free a name held by orphans.** `kill -9` on a supervisor
  can leave `claude` or a vitest run inside the scope, which stays active, so
  `systemd-run --unit` would refuse the restart in exactly the case #329 exists
  for. #347 now stops a stale unit first, and only when no live supervisor
  matches the worktree.
- **The suite must not create units on the host.** CI here is the self-hosted
  runner that also hosts the live loops, and `start.test.ts` runs the real
  `start.sh`; #347 carries a criterion that the suite leaves no `ralph-loop-*`
  unit behind.
- **`<project>` is a registry id `start.sh` cannot know** (`.ralph/loop-name`
  gives it the loop only). #347 says the start route passes it in and a hand run
  falls back to the worktree's basename.

Two findings were declined, both for the same reason, and both recorded in the
round-2 brief: "make #347 blocked by #346" and "split #347 into a coder child
and an operator child". `add-blocker`'s target must be an existing issue number
and a `## Blocked by` section cannot name a number that does not exist yet, so
one plan cannot express a dependency between two issues it creates. The ordering
is in #347's prose instead: run its two come-back drills once #346 has merged
and been deployed.
