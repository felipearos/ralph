## What shipped

A Jav route may name only a loop that picks from the frontier. `validateJav` judges targets against
`routableLoops(roster)`, which reads `roleDescriptor(role).javRouted` — the same field the frontier
gates a route on. The stranded-label check counts those loops only, resolving each through its own
route then `default`, so `default` drains a label only when a picker actually falls back to it.
Claim-label reservation still spans the whole roster. `JavRoster` became an element union accepting
bare names (each a coder — the pre-roles judgement) or `RosterEntry[]`, and every reader was migrated
to pass roles: `frontier/next-tasks.ts`, `preflight.ts`, `triage-apply.ts`, and `jav.ts`'s CLI.

## Key decisions

- **Deliberate deviation from the spec, stated in the PR.** The spec asked for `loopsWithRole("coder")`.
  `jav.ts` cannot import `roster.ts` at runtime (the frontier imports `jav.ts` and runs it from a
  pinned temp copy) and `loopsWithRole` cannot type a bare-name roster, so `routableLoops` lives in
  `jav.ts` and reads the descriptor instead. The spec reviewer judged this equivalent for every
  roster the project can have.
- Named `routableLoops`, not `coderLoops`, and gated on `javRouted` rather than `role === "coder"`,
  per `roles.ts:11-14`'s own convention — otherwise a fourth role with `javRouted: true` would be
  offered a route by the frontier and refused one by Jav.
- `JavRoster` is an element union (`readonly (string | RosterEntry)[]`), not a union of array types:
  both concrete forms are assignable and the helpers map over it without a cast.
- `loopRoster()` derives from `loopRosterEntries()` — `loadProjectConfig` does no caching, so two
  independent lazy caches could have left the claim fences on one roster and Jav's targets on another.
- Rejected a reviewer suggestion on evidence: rewording `'zed' is not a loop (…)` would have broken
  the pre-existing CLI assertion AC 4 protects. Declined renaming `rosterNames` over a cross-module
  collision with `dashboard/contracts.ts` (different types, different modules).
