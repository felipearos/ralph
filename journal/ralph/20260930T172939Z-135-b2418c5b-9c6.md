# 2026-09-30 — #135 Roles: each role has its own stage set and default lineup

**Outcome: merged.** PR #205, squash-merged as `00bf8f9`, issue #135 auto-closed.

**What shipped.** A role declares which lineup stages it runs (`roles.ts` `stages`): coder and
ci-doctor all five, triager `orchestrator`/`mapper`/`review.spec`. The stage vocabulary moved
into `roles.ts` (with `models.ts` re-exporting it) so a role's set is a typed subset of one
list. A resolved `Lineup` holds only that role's stages, which makes every reporter role-correct
without a second lookup. A block written FOR a role is refused for naming a stage outside its set;
`default` blocks stay complete over all five. Resolution gained `<project>.@<role>` between the
loop's own block and the project's `default`, reported as `source: 'role'`. `--role R` selects
it on every command, and without the flag the roster answers for the loop being resolved.

**Key decisions.**
- The vocabulary had to MOVE to `roles.ts`, not be duplicated: `models.ts` imports `roles.ts`,
  so an import back would be a cycle. Same argument the file already records for `PREFLIGHT_CHECKS`.
- `Lineup` is `Partial<Record<Stage, ResolvedStage>> & { orchestrator }`. Honest, and it forced
  an explicit `!` or a guard at every index — which is what surfaced the `preflight.ts` executor path.
- The out-of-role refusal must NOT apply to a block every role falls back to (a `default`); the
  order test caught the first version refusing a project's shared `default`.
- Validation learns a loop block's role from a caller-supplied map; `--role` pins this run's loop.
  Unknown means coder, which is the pre-roles judgement.
- The local two-axis review found **six real defects**, all fixed in `61be23c` and each reproduced
  first: `--validate` ignoring `--role`, `rosterRoles()` mis-keying a foreign roster, the
  out-of-set check keying on shape, the lost `RALPH_RUNNER_EXECUTOR` short-circuit, the editor
  enumerating `@triager` as a loop, and `inspect.sh`/`delegate.sh` passing `--role coder` when
  none was exported.
- Deliberately deferred to #139: the dashboard's role SOURCE. The editor offers the stages the
  resolver reports, but the adapter edits harness checkouts where a project's roster is not
  reachable, so a triager's per-loop block still validates as a coder's there. `@role` defaults
  are editor-safe. Called out in the PR body and in `lineup/adapter.ts`.
