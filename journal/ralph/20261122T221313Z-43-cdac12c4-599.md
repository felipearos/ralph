## What changed
- `name-guard.ts` `commitsToPush`: on an update push it now scans `rev-list --ignore-missing <new> ^<old> --not <tips>`, where the tips come from `git ls-remote <push URL>` at push time, not `old..new`. A failed ls-remote throws, so the push is refused. `main` passes the pre-push hook's argv[2] (the push URL), falling back to the remote name, then `origin`.
- The header comment now says what "on the remote" means. Hook tests cover a rebased force-push, a stale remote-tracking ref, a pushurl that differs from the fetch URL, and a tag on a blob.

## Decisions / dead ends
- The first version trusted `--remotes=<remote>` tracking refs. Qodo's High finding was right: a stale `origin/x` for a branch someone else deleted hid unscanned commits. Fixed by switching to ls-remote.
- ls-remote on the remote name reads the fetch URL. Qodo's second High was right too: pushurl can differ. Fixed by using the push URL.
- Qodo's Medium ("a non-commit tag blocks branch pushes") was disputed with evidence: git rev-list accepts blobs and tags on blobs under `--not`. A test pins it and passes on the CI runner. Qodo deferred dismissal to the operator, and the merge went ahead under §5.5's disputed-with-evidence rule.
