## What the spec review changed

Two rounds of `ralph-review-spec` against the fetched issue
(`.ralph/logs/spec-125.md`), with the proposed text as the change under review
(`.ralph/logs/proposed-125.md`) — this role holds no diff, so the brief says so
in as many words. Round 1 found five defects, round 2 four more, all wording. The
two that would have shipped a checklist that lies:

- **`merge-base --is-ancestor` exits 0 for "behind or equal"** (that is how
  `dashboard/agents.ts:504` uses it), so the "worktree at origin/<base>" item had
  to be an exact `rev-parse` comparison. Otherwise a worktree left stale after the
  roster PR merged — the second thing missed when `testo` failed to start on
  2026-09-28, i.e. the issue's own motivating failure — would have read as a pass.
- **`preflight.ts --json` runs `gh auth status` (`:624`), its own
  `gh label list` (`:669`) and `doppler secrets` (`:730`)**, and
  `GET /api/agents` is polled every 5 s (`dashboard/ui/agents.tsx:106`). The
  preflight item is now explicitly kept off that poll — otherwise the feature
  would have bought three network calls per ready agent every five seconds on a
  project that has already met gh's burst limit.

Also folded in: the role is read from the roster (base ref for a `ready` agent,
the roster PR's head ref for a `pending-merge` one, `project-config.ts --json
--at` already being in the surface) and never defaulted to `coder`
(`dashboard/agents.ts:364-367` says why); `models.ts --json` needs
`RALPH_PROJECT_ID` as well as `RALPH_LOOP_NAME` or the source reads `default`
where it should read `project` (`models.ts:839`); and the "no second copy of the
guide" criterion names what it compares (table cells over 20 characters) instead
of saying "a search finds nothing".
