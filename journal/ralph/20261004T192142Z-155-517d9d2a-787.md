# 2026-10-04 — #155 CI doctor: unpark tickets parked on a flake

**Outcome: merged.** PR #221, squash-merged as `16c0841`, issue #155 auto-closed.

**What shipped.** `ci-doctor/unpark.ts`, a new CLI that puts a coder ticket
parked as a draft PR on a flaky test back in front of its coder: comment the
diagnosis, drop the owner's `<loop>-blocked`, `gh pr ready`, then record in the
ci-health store. Step 3 is last on purpose, so an interruption leaves a visibly
unfinished draft rather than a silently-lost one. `block-reason.ts` gains a
`ci-flake` kind and the dashboard's stuck chips now say `flaky test`.

**Key decisions.**

1. `ci-flake` is `isFlakeBlock` promoted into the discriminant, matched on the
   existing `\bflak\w*` stem — NOT the narrower regex the issue names, which
   would have dropped two reworded blocks `block-reason.test.ts` already pins.
   Raised in the PR body as the spec owner's call; `isFlakeBlock` deleted as
   dead code.
2. Outstanding work is read off GitHub every run, and "nothing to do" is asked
   from the three steps alone. That single choice satisfies AC 1 and AC 2 with
   no special case.
3. The budget is counted off the comment markers, not the store, which is a
   documented cache. A refusal gets its own `unpark-declined` marker.
4. A re-park is told from a crash-resume by comment ORDER, and the newer block
   record's kind picks the refusal.
5. The store record is keyed the way the gate reads it — the parked case's own
   `rule`, not `--diagnosis`, which must itself be a `flake:` key.
6. Records on `unpark`, `nothing` and `declined`; never on `fault`.
7. Scope taken beyond the issue: the dashboard chip change (the issue asks for
   it, and it was false as written) and `contract-parity.test.ts`.
8. Deliberately NOT done: nothing calls `unpark.ts` yet — `prompts/ci-doctor.md`
   is #157's placeholder. README's "What is live" now says so.
