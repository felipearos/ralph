## What changed
- The dashboard's gh lookup for an open sentinel/verifier rules PR now sits behind a per-process 60s TTL cache on a monotonic clock. A save writes the new entry straight into the cache.

- A read that overlaps a save answers with what the save wrote. Qodo flagged that the overlapping read could get a stale "none", so `pendingRulesPr` now returns the newer entry first. Tests pin it.
- dashboard/README.md documents the cache and names `?pending=skip`.
