**Key decisions.**

- The GitHub budget is **per doctor loop**, not per store. A shared allowance starves a second
  doctor, whose cadence marks would say a read had just run while it held none of the answer.
- **`Case.fixedAt`** is new, optional, and written by nobody in this PR. Priority 6 needs a
  recurrence boundary `cost72h` cannot give; absence fails closed; #159/#162 owns the writer, and
  since `mergeCases` already carries the field that ticket needs nothing else here.
- **`ciDoctor` config is not typed or validated** — #158 owns that. `pollSeconds` is read
  leniently (config → supervisor argv → 300, ±20% jitter).
- The three new store fields are optional and absent from `emptyStore()`. Bumping
  `CI_HEALTH_VERSION` for them would make `readStore` discard a live 72-hour window on deploy.
- The throttle wait is flat (5 min), not `frontier-gate.ts`'s streak-grown backoff, because the
  issue spells out the flat rule. `retryAfterSeconds` is structurally null for `gh pr list` and
  `gh issue list` (no headers without `gh api --include`); said so in a comment rather than
  leaving a field that looks unimplemented.

**What the two-axis review caught.** Six real defects, all fixed in `b4bbd19`. Two were found
independently by both axes and both were hidden by a fake in my own tests: the lease recorded the
**gate's** pid, so it fenced nothing once the gate exited (every test injected `alive: () => true`),
and `mergeCases` **erased `notified`** and deleted `infra:check:*` outright, so the record that
beats `push-notification.ts`'s per-run dedupe never survived a single poll — the test now folds a

invariant the module exists to hold.

**For the next iteration to know or skip.**

- **This project has no merge queue** — 0 rulesets, `main` unprotected, empty enqueue block. §5.6's
  enqueue path does not apply: merge with `gh pr merge --squash`. Handing back `AWAIT_PR <pr> merge`
  here would burn 60 minutes waiting for a merge nobody performs.
- **This project is on GitHub Actions, not Buildkite.** `bk-log.ts` cannot read these logs
  (`no Buildkite token`) and never will. Use `gh run view --job <id> --log`; `--log-failed` prints
  nothing when the job was cancelled by the cap, which is exactly the timeout case you most want.
