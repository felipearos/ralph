## Five review rounds, and the one finding worth the whole iteration

`ralph-review-spec` ran four times (rounds 2-5 of the brief). The P1 of round 3 is
the one to remember, because it is a trap this tree will lay again:

**A field that exists is not the field you want.** The ticket's item 2 gates the
shared wait on "two or more live waiters". But sibling C joins the store on every
settle of a `shared: true` blocker, so a loop waiting ALONE on a `ci:` key also has
a store record with a `first` — and the age of `first` always runs ahead of this
loop's `waitedSeconds`, which counts sleep only (`backoff.ts:359`) and not the
iterations between waits. Measuring the budget from `first` whenever a record exists
would therefore have exhausted a lone waiter *earlier* than today, breaking item 1's
"today's backoff, unchanged" — while passing every criterion written under a fake
clock whose `sleep` does not move time. The fix is the store's **`notified`** field
(`blocker-store.ts:64`, set by C exactly when it first sees a second waiter): it is
what makes an EPISODE shared, where the live count only makes THIS WAIT shared. The
gates are now three, read once at the top of each `wait`, and the two things that
must outlive a drop back to one waiter — seeing `clearedAt`, and exhausting from
`first` — hang off `notified` alone, so the last waiter left still clears the
blocker and still stops.

The other four pins, each of which would have cost a coder a round:

- **The exhaustion record is `ralph.sh`'s, not `backoff.ts`'s.** `backoff.ts` only
  logs and returns `EXHAUSTED_EXIT` (`:520-524`); `ralph.sh:2105-2110` writes the
  `record --event backoff-exhausted --stop blocked --why …`. Item 4's two records
  and its `--why` are unreachable from TypeScript, so the ticket now reuses sibling
  A's file seam — `.ralph/logs/backoff-exhausted.json`, written on the shared path
  only, `rm -f`'d at `ralph.sh:1588`, with a missing or unparseable file falling back
  to today's record verbatim. Both `why` texts are pinned, and the loser's does NOT
  name the winner: `exhaustedNotified` holds a timestamp, not a name (`setOnce`,
  `blocker-store.ts:148-153`), and `markExhausted` returns only whether this call
  won.
- **The clear must be read BEFORE the fingerprint wake.** The key's check reaching
  `pass` on a waiter's own PR also changes that PR's fingerprint, which carries every
  check's state (`backoff.ts:144-151`). A poll that kept today's order would `break`
  with `changed` before anything called `markCleared`, and every other loop would go
  on waiting on a blocker that had cleared. Item 3 fails silently that way.
- **`parseCheck` is GraphQL-shaped and must not be reused for the base head.** It
  tests `"COMPLETED"` and `"SUCCESS"` (`pr-wait.ts:118-121`); the REST endpoints
  `host-lease.ts:500-501` reads answer lowercase, which is why the code there
  compares `"completed"` and `"pending"` (`:505,508`). Fed a REST entry it reads
  every check as `pending`, so the base probe would never clear — and the key #416
  exists for, `ci:buildkite/loggd:production-migrations`, is a legacy StatusContext
  only the combined-status endpoint reports. The ticket now asks for a separate
  exported `parseRestCheck`.
- **A `ci:` key cannot be compared to a check name raw.** `normaliseBlockerKey`
  (`:161-176`) lowercases the key and replaces anything outside `[a-z0-9:#/+._-]`
  with `-`. Pinned: an exported `parseCiKey`, and a candidate matched by putting its
  name through `normaliseBlockerKey("ci:" + name + ":x")`.

Also pinned, more briefly: `shared?: SharedWait` on `WaitDeps` supersedes item 3's
`blockerCleared()` name (a coder reading item 3 would otherwise add both); a
`ProbeReader` seam so criteria 3-6 need no `gh`; `clearedProbe(reader, repo)`,
because `parseClearedBy("#n", null)` is null (`backoff.ts:186-197`); what the `wait`
CLI wires, honouring `RALPH_BLOCKER_STORE` (`blocker-store.ts:309`); that
`backoff-exhausted-shared` is a free-form record event (`loop-state.ts:1256` takes
`--event` as given) and not a notification kind, so only the `run-finished` list
changes (`push-notification.ts:256`); and item 4's stale citation, `:459-463` rather
than `:436-460`.
