# 2026-10-20 — #346 The dashboard restarts a loop whose supervisor died

**Outcome: merged.** PR #355, squash-merged as `4afe02b`, issue #346 auto-closed.

**What shipped.** A reconciler in the dashboard: a loop whose supervisor died
without writing an ending is restarted through the real `start.sh`, and every
attempt lands in that loop's own notification feed. New `dashboard/reconcile.ts`
(decision, pass, windowed bound, push surface, env, schedule), `parseLoopState`
in `dashboard/lifecycle-adapter.ts`, `raisedAt` in `dashboard/records.ts`, two
`NOTIFICATION_KINDS`, one `schedule(...)` in `main()`, and
`RALPH_DASHBOARD_RECONCILE_MS=0` as an off switch. Seven commits,
`3edb992`..`754013f`. This closes the loss path memory records as
"loops die on reboot or oomd": a dead supervisor needed a human hitting
`/api/p/<project>/start`.

**Key decisions.**

1. Three review rounds, and **each round found a real defect in the previous
   round's fix.** The memory ceiling was inert (`main()` never passed it), then
   unwindowed (a permanent bound plus an alert every pass), and then the e2e
   reaper's `kill(-pid)` signalled a group that does not exist — `start.sh`
   publishes a CHILD of its `setsid` wrapper, so the pid is not a group leader,
   and after a pid recycle that kill could have hit an unrelated group on the
   host that runs the live loops. Reviewing the fix, not just the original diff,
   is what caught two of the three.
2. Spacing the restart attempts across the hour was **refused**: it would mean
   three attempts in a row never reach the bound, which AC4 requires. The cost
   is stated in the prose and in the README rather than hidden.
3. The off switch exists because `server.test.ts` caught the startup pass
   running the real `start.sh` over fixture worktrees — the suite needed a way
   to say "not here".
4. The two env vars live in `reconcile.ts`, not `config.ts`, whose import
   allow-list is `node:path` + `./contracts`.

**Delegation.** `delegate.sh` was called once, on slice A
(`.ralph/logs/brief-346-a-loop-state-read.md`): exit 4 `runner-error` with an
empty log, the open harness learning `opencode-subscription-lapsed`. Every
slice and both review axes therefore ran in session on opus. No new learning:
the cause is already open under that slug, and no open entry names #346, so
this PR closes none.

**CI.** Green first round on the required check `test` alone. CI here is GitHub
Actions on the self-hosted `[self-hosted, ralph]` runner — the same host as the
live loops — so `bk-log.ts` cannot read a failure; `gh run view <id>
--log-failed` is the route. This repo has no merge queue, so the merge was
`gh pr merge 355 --squash`; `AWAIT_PR 355 merge` would have waited on nothing.

**Files touched.** `dashboard/reconcile.ts` (new) and its tests,
`dashboard/lifecycle-adapter.ts`, `dashboard/records.ts`,
`dashboard/notifications` kinds, `dashboard/server.ts` (`main()`),
`dashboard/server.test.ts`, `dashboard/README.md`.

**For the next iteration.** The reconciler is live in the dashboard's startup
path, so a dashboard restart now also revives loops that died unflagged —
expect `/api/p/<project>/start` to be needed less often. If a test ever needs
the dashboard without it, set `RALPH_DASHBOARD_RECONCILE_MS=0` rather than
stubbing `start.sh`. Follow-ups #328/#329 remain open and untouched.
