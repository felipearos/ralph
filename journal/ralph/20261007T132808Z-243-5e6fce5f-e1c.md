# 2026-10-07 — #243 Retry an intake gate that never reached a verdict

**Outcome: merged.** PR #250, squash-merged as `8a4a54b`, issue #243 auto-closed.

**What shipped.** `ralph.sh` treated any intake-gate exit that was not a
verdict as fatal, at both call sites, so a transient spawn failure
(`ETXTBSY: text file is busy, posix_spawn 'bun'` — loggd's rafa, 2026-10-07
12:03Z, self-hosted runner writing the binary) stopped the loop and sat the
supervisor down for 25 minutes over a frontier that was merely empty. Such an
ask is now retried: `RALPH_GATE_RETRY_MAX` (3) asks, waiting
`RALPH_GATE_RETRY_SECONDS` (15) and doubling to `RALPH_GATE_RETRY_MAX_SECONDS`
(120), through the control inbox so a stop is not slept through. Each try is
recorded in `.ralph/logs/runner-failures.jsonl` under a new `gate` stage,
classified by a new `spawn-failure` signal kind. Only a gate that keeps
failing stops the loop, with the message, event and exit status it always had.

**Key decisions.**
- `backoff.ts` is MIRRORED, not called, though the issue floats it: its state
  keys on a shepherd PR's fingerprint, `ralph.sh:1450` deletes
  `.ralph/logs/backoff.json` at startup, and reaching it would mean spawning
  the `bun` whose spawn just failed. Both review axes checked and accepted it.
- A retry does NOT `continue` the outer iteration loop — the first shape
  tried. The top of that loop re-runs `backoff.ts wait`, whose state survives
  an elapsed wait, so every gate retry would have spent backoff budget and
  could have escalated a loop to a human over a spawn race. Hence an inner
  `while :` loop, and the control-command wake becoming a `GATE_REGATE` flag.
- `${PIPESTATUS[0]}` instead of the pipeline's status: the one behaviour change
  beyond the retry is that an unwritable supervisor log is no longer fatal.
  Deliberate, commented, declared in the PR body, pinned by no test — there is
  no honest way to make just that timestamped file unwritable.
- The review's load-bearing find: the incident recorded itself as
  `unavailable`, "the harness is not installed", because nothing matched
  `ETXTBSY` and the gate's exit is 2. Hence the `spawn-failure` kind.
- Declined, with reasons in `.ralph/logs/phase-243-review.md`: a timeline row
  in `incidents/` (that file is the operator's own observed narrative), and
  moving the knob validation before `supervisor-start` (cosmetic, and
  `RALPH_LEASE_HEARTBEAT_SECONDS` has the same shape).
