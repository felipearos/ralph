### Why the groups came out 5 + 1

A mapper pass gave the files each swap touches. Select, Textarea/Checkbox,
ToggleGroup, Collapsible and Button each share a file with at least one other —
`tracker-connector.tsx`, `chat.tsx`, `backlog.tsx`, `app.tsx`, `lineup.tsx`,
`jav.tsx` — so they are one connected conflict component and share
`dashboard-controls`, which the frontier runs one at a time. Tabs touches only
`activity.tsx` and `add-project.tsx`, which nothing else touches, so it gets
`dashboard-tabs` and can run in parallel. **That parallelism is the reason the
Tabs child also takes the bare buttons in those same two files** — leaving them
to the Button child would have pulled Tabs into the big group and serialized all
six.

Two departures from the ticket's "one PR per component", both stated in the
triage comment: Textarea and Checkbox are one child (six controls over the same
three files; splitting them would hand two loops `setup.tsx` at once), and Tabs
carries those four bare buttons.

Two hand-built controls are outside the ticket's list of seven and are assigned
to no child, recorded in the comment: the clickable
`<li onClick aria-expanded>` at `activity.tsx:201-210`, and the `<datalist>`
options at `tracker-connector.tsx:217` and `lineup.tsx:740`. They want their own
ticket if they are wanted at all.

## The spec review earned its keep — two rounds

Worth reading before triaging anything in `dashboard/ui`: a shadcn swap looks
mechanical and is not. The reviewer found, and the children now carry criteria
for, every one of these:

- **A criterion that could never pass.** `rg -n "<textarea" dashboard/ui` would
  have matched the new `components/ui/textarea.tsx` the same ticket asks for.
- **`rg --glob '!components/ui/**'` excludes nothing** when run from the repo
  root — ripgrep matches `--glob` against the cwd, not the searched path.
  Verified here with ripgrep 14.1.1: it still reported
  `dashboard/ui/components/ui/sidebar.tsx`. `'!**/components/ui/**'` works. Round
  one wrote the broken form; round two caught it.
- **A false premise I had written in.** The Ask/Fix switch does not carry
  `data-chat="mode"`; that attribute is the transcript status line at
  `chat.tsx:282`. An AC saying "still carries" it would have put a misleading
  attribute on the new toggle group.
- **Three couplings outside the control being swapped.** `backlog.tsx:1010-1011`
  opens a fold through `element instanceof HTMLDetailsElement` and the count
  buttons at `:1069-1084` depend on it; `backlog.tsx:249-250` flips its label
  with Tailwind `group-open:`, which keys on `<details open>`;
  `lineup.tsx:655`'s `*:data-[slot=native-select-wrapper]:w-full` is the only
  thing making `:659`'s picker full width.
- **e2e selectors that a swap silently breaks.** `app.tsx:1829` is reached by
  `getByLabel("Where Pause and Stop apply")` (`remote-ui.e2e.test.ts:172`), so
  that `aria-label` must land on `SelectTrigger`, not the `Select` root;
  `chat-ui.e2e.test.ts` needs `role="radio"`, `aria-checked`, `isDisabled` and
  `[data-chat="seed"]` to survive.
- **Behaviour a drop-in loses.** Clicking Fix calls `setArming(true)`
  (`chat.tsx:326`) rather than `onMode`, and a Radix single ToggleGroup emits
  `""` when the selected item is clicked again — which is exactly the click
  `tracker-connector.tsx:117` uses to reset the draft to `EMPTY_TRACKER`.
- **No shadcn `Button` preset matches the bare buttons.** The base class is
  `uppercase tracking-widest font-semibold text-xs justify-center` and the
  smallest size is `icon-xs` (`size-7`); `jav.tsx:169` is a `size-3` icon in a
  `Badge`, and two others read as inline text. Both button children now say that
  `className` overrides are expected, and require the casing and alignment to be
  kept.
- **A path that does not exist.** Four children had cited
  `dashboard/ui/package.json`; `radix-ui@^1.6.7` is in the root `package.json`.

## For the next iteration

- **The parallelism is real but fragile.** #383 is the only child outside
  `dashboard-controls`. If a later ticket adds work in `activity.tsx` or
  `add-project.tsx` to one of the other five, the two groups collapse into one.
- **`dashboard/ui` has no component tests.** `vitest.config.ts` runs
  `environment: 'node'` over `**/*.test.ts` only, so nothing asserts on a `.tsx`
  except the two Playwright e2e files (`dashboard/chat-ui.e2e.test.ts`,
  `dashboard/remote/remote-ui.e2e.test.ts`). Every criterion in these six
  children that is not a grep is a behaviour a coder has to check by reading or
  by running those two e2e suites.
- **Don't cite `remote-ui.e2e.test.ts` as cover for the activity filter or the
  Add-project tab strip.** It never reaches them; it only checks that the Add
  project menu item is disabled (`:208-210`).
