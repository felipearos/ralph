# 2026-10-07 — #240 ci-doctor: a case the doctor rejects is re-offered every iteration

**Outcome: merged.** PR #242, squash-merged as `e02e590`, issue #240 auto-closed.

**What shipped.** A ci-doctor can reject a case in one command, as a store
transition rather than a sentence in a journal nothing reads:
`case-issue.ts reject '<key>' --reason '<why>'` writes `state: "retired"` plus
`Case.rejectedAt = { build, at, reason }`. `mergeCases` holds it there and
carries the boundary, `decide` does not offer it, and it returns only on
evidence from a build strictly newer than the boundary, with `rejectedAt`
cleared. The defect was `mergeCases`' ternary having no branch for a rejected
case, so it fell through to `proposed.state` — `confirmed` again, forever,
since a confirmed flake is sticky. That cost one loggd doctor ~450k tokens an
iteration, three iterations running.

**Key decisions.**

1. `retired` plus a new optional `Case.rejectedAt`, **not** a new `CaseState`.
   A new state breaks `dashboard/contracts.ts`, `contract-parity.test.ts`
   (twice), `known.ts`'s `never` switch, `ci-health.ts` and `revert.ts`, and
   buys nothing. But `retired` is also what `classify.ts` proposes for a stale
   candidate, so `rejectedAt` carries the distinction and a guard test fences
   the two meanings apart.
2. The reason lives in `rejectedAt.reason`, not `Case.rule` as the issue
   floated: the fold resolves `rule` as `proposed.rule ?? prev.rule`, so a
   scan clobbers it, and three call sites read `rule` as a test id.
3. `runReject` **and** `recordRejected` refuse `infra:check:` and `parked:`
   keys. This was the local review's load-bearing find and worse than the
   original bug: check-case evidence is written with `build: 0` and the scan
   never re-proposes those keys, so a rejection there was unliftable and the
   gate would report "CI is healthy" straight through a live outage.
4. A rejection names the parked tickets it leaves parked — reported, not
   refused.
5. The delete sweep keeps a rejected case of any kind; it is bounded by
   manual rejections, not by traffic.
6. Falsifiability verified by reverting each production change and re-running.

**Ruled out.** A new `CaseState` (decision 1). The reason in `Case.rule`
(decision 2). The issue's "worth considering" extension — the gate skipping a
flake whose file is absent from the base branch — is deliberately out of
scope; both review axes agreed, and it is follow-up ticket material.
